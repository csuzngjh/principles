PRI-892: fixed the silent no-op of `npx create-principles-disciple` on Windows. Node resolves the main module through symlinks/junctions while `process.argv[1]` keeps the unresolved link path handed over by npm/npx `.bin` shims, so the raw `pathToFileURL(argv[1]) === import.meta.url` entry guard never matched and the CLI exited 0 with zero output (install / repair-update-chain / uninstall all dead). The guard now compares the raw URL first (a plain direct invocation never depends on a filesystem lookup) and then canonicalizes argv[1] with `realpathSync` for the linked case, keeps the cli-7 import-safety semantics (importing the module still never parses argv), and adds an rc-9 observable fallback: when canonicalization cannot confirm the entry but argv[1] still unambiguously names this package's own entry file, the CLI warns on stderr and runs instead of saying nothing. The identical guard in the Codex `pd-hook` entry is fixed the same way (linked installs previously skipped `main()` silently); its fallback keeps the hook contract of exactly one JSON object on stdout. Regression tests spawn the built CLI and hook through a junction path, a direct real path, and an unresolvable entry path, and assert real output (red before the fix: empty stdout, exit 0).
