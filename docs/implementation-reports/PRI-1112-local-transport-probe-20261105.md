## 根因追查：首次失败几乎耗尽期限才发出请求

Owner 要求继续定位后，补查了保留原样的首次实验文件。probe.py 在写出 validation.stdout/stderr 后立即记录单调开始时间并启动宿主；端点收到完整正文后立即写 request-1.json。这允许从文件写入时间重建近似阶段，不能替代原始单调事件时间。

首次 run-lhftwjwv 的 validation.stdout 修改时间为本地 07:52:20.967，request-1.json 为 07:53:20.533，相差 **59.566 秒**；host.stdout/stderr 在终止后写于 07:53:21.287。也就是说，首次请求到达时外层 60 秒期限仅余约 **0.43 秒**。此前只有终止后的缓冲输出，缺少结果实际输出时间；据此描述成长期“输出后卡住”没有证据支持。首次仍为超时失败，不回写 PASS。

已定位的直接问题是：**全新隔离状态下的宿主启动和请求准备消耗了几乎全部外层预算；探针又没有阶段时间，导致将总期限耗尽误读为退出阶段故障。** 内层 --timeout 45 没有约束整个 CLI 从创建到退出：实际请求在启动近 60 秒后才到达。PD 插件在所有这些运行中禁用，因此当前慢点发生在 PD 原则接线之前。
