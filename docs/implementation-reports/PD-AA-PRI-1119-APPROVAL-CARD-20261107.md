## 0. 当前形势（供 Owner 决策的一句判断）

正常入口**已在生产真实运行**（8 天 238 个真实轮次均有注入事件），但**不能可靠地把指定的一条原则送达**（目标原则 97/238 = 40.8%，其余轮次被 `droppedActivationIds` 明确丢弃），且 **PD 拿不到宿主最终请求正文**（只返回片段，最终请求由宿主组装）。因此 SPEC G1 的“独立请求证据”在当前能力下**不可签收**。

→ 需要 Owner 批准的最小组合是：**单原则隔离工作区（解决送达确定性）+ 一处请求级只读观测（解决 G1 证据）**。两者都未在本轮执行。

## 1. 安全与隔离

| 项 | 要求 |
|---|---|
| 生产路径防护 | 专用工作区不得复用生产 `PD_WORKSPACE_DIR`；不得继承生产 `.pd`/`.state`；启动前用 `--workspace` 显式指定并记录绝对路径 |
| 安装目录防护 | 全程不手改安装目录；只通过官方安装器变更；安装前后校验版本 |
| 生产库防护 | 不写生产 `state.db`、不改生产 `approvals`/`activations`、不删污染记录、不改冻结证据 |
| 证据脱敏 | 采集只保留机会键、ID、时间、字符数、哈希；不保留完整 prompt 正文；不写入凭据 |
| 数据外发 | 0 外发；本地 provider 仅在本机回环；不得新增远端捕获服务 |
| 回退 | 任一层失败 → 停用专用工作区的 prompt 激活，回到 Native；不触碰 Runtime V2 治理状态 |

## 2. 硬预算 / 超时 / 停用 / 事故升级

| 机制 | 定义 |
|---|---|
| 硬预算 | 第 3 层的 token/金额/任务数上限；触达即停 |
| 超时 | 单任务与单次采集上限；超时记 `unknown`，不重试扩预算 |
| 停用 | SPEC §7 触发项（未授权原则、跨 session 污染、重复注入异常、确认误报、泄露、阻塞提交、重大行为损害）→ 立即停用映射并回 Native |
| 停用命令 | `pd runtime activation deactivate --workspace <专用工作区> --reason-code <code> --dry-run` 先验，再实际执行 |
| 事故升级 | 立即：①停用；②保存事实/范围/未知；③通知 Owner；④不改治理状态；⑤不清理事故记录 |
| 证据保留 | 保留窗口内事件日志、机会表、Examiner 复核记录；保留原始时间戳与批次 ID |
| 清理 | 窗口结束后按数据清理守则**保留**证据；仅清理 `.tmp` 中本轮可重建的中间脚本；不删事故记录、不删历史证据 |

## 4. 可接受的 unknown vs 阻断运行的未知

| 未知 | 分类 | 理由 |
|---|---|---|
| 无原生 `requestId` / `currentUserMessageId` | **可接受**（记 unknown，降级为 turn 级） | 身份到 runId 可用；不单独阻断 |
| `tool_calls.tool_use_id` 全空 | **可接受**（行动靠 name+params+ts） | 有替代关联方式，记录局限 |
| 最终请求正文不可得 | **阻断 G1** | SPEC C04 硬条件；必须由 D4/B1 解决或 Owner 明确接受“不签收 timely” |
| 目标原则在竞争预算下被丢弃 | **阻断“单目标”** | 40.8% 实证；必须由 D3 收敛工作区 |
| 专用工作区无法产出目标 revision | **阻断方案 A** | 若发生则回退到方案 B/生产，需重新批准 |
| 本地 provider 日志格式未知 | **可接受（暂缓）** | 先 V1 只读核实再决定 B1/B2 |
| 安装升级的 `--smart`/`--force` 语义 | **可接受（暂缓）** | 执行前只读核对 |
