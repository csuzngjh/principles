# 检查点 20261107T0018Z（trae）

## 缺陷与反例

- 复现：linkage 与 run-record 的 `hookInvocationId` 相同，但 `consumedBy.runId`、`consumedBy.sessionId` 均与 linkage 不同 → 旧实现返回 `matched_by_run` / `experimentLevelStrongLink=true`。
- 新增 2 个真实 CLI 回归测试，旧实现均失败：
  1. 同 hook、run 与 session 均不同 → `contradictory_identity`，strong=false。
  2. 同一条记录声明两个不同 run 值（其中一个恰好与 linkage 相同）→ `contradictory_identity`，不再因集合中存在匹配值而接受。

## 修复边界

- `hookInvocationId` 仍优先；命中后校验已声明的 run/session。
- 明确不同或一条记录内多个冲突声明 → `contradictory_identity`。
- 缺字段不等于冲突，保持 unknown；未新增字段。
- 弱候选（1105：22ms proximity）、`ambiguous` 多候选、`conflicting_linkage_invocations` / `conflicting_linkage_scopes` 与动态简报均保留；统计公式未改。
