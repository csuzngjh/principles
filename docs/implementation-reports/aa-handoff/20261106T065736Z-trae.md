## PRI-1118：三个缺口如何闭合

1. **本轮输入可信来源（§3.4）**
   - 冻结正文由实验 launcher 在宿主启动前写入 `<experimentRoot>/input.txt`，并计算原始字节 `inputSha256`；通过 `openclaw agent exec --message-file <abs path>` 等**按文件字节提交**的官方入口送入宿主，禁止 shell 拼接或历史拼接。
   - 插件侧双证明：`sha256(event.prompt) == inputSha256`（原始字节），且 `resolveCurrentUserMessage(...).message` 与冻结正文逐字节一致（解析一致性）。哈希不符直接拒绝，不做 trim/Unicode 归一化。
   - 端点侧独立证据：假 provider 记录 `endpointRequestId/bodySha256/userMessageSha256`；`userMessageSha256 == inputSha256` 仅作传输证据，不等于宿主 `requestId`。
   - 绑定：输入 ↔ 准入 ↔ 清单 ↔ workspace realpath ↔ 目标 Artifact/Activation ↔ `mappingSha256` ↔ 运行时配置快照。`sessionId/runId/hookInvocationId/hostVersion/pluginVersion` 均为**启动后**获得，在首个消费点校验并记录。
   - 三条身份线分别记录：operator admission / host identity / endpoint request identity，禁止互相冒充。
2. **一次性与重放边界（§3.5）**
   - 持久状态仅 `admission.json` 的 `consumedAt/consumedBy`；先写临时文件 + rename 原子消费，磁盘为最终事实；不建表、不新增长期状态或通用配置。
   - 最小进程内 claim 缓存：仅用于共享入口把消费结果交给同轮回调；key=`admissionId`，最多 2 条，TTL 60 秒，`finally`/journal close/进程退出清理。
   - 场景矩阵：首次合法消费；同回调重复、同输入新 run、跨 session、超时后再用、工具后第二次请求均拒绝并保持 Native；provider 消费后回调未发生 → 不重试，记 `consumed_without_injection`；中途失败/异常不自动重试。
   - 文件与上限：`input.txt` 16 KiB、`admission.json` 16 KiB、`manifest.json` 64 KiB；路径必须 realpath 在实验根内，拒绝 `..`/符号链接/junction/UNC；解析失败不“尽量解析”。
3. **默认共享入口接线（§3.6）**
