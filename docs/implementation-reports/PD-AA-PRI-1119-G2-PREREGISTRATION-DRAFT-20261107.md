## 1. 这份预注册解决什么

G2 需要一个限域 Native 真实使用窗口。若不在开窗前固定纳入/排除条件、观察字段、机会键与 unknown 规则，窗口内的计数会被事后解释污染，无法判断“看到了什么、漏了什么”。

本草案只把这些问题写成可执行定义；**是否开窗、何时开窗、用哪个工作区与原则，仍由 Owner 在 PRI-1119 书面批准时决定**。

## 2. 范围（待 Owner 在批准时固化）

| 项 | 草案默认 | 批准时必须固化 |
|---|---|---|
| 工作区 | 一个真实工作区 | 绝对路径 + 是否含子目录 |
| 宿主 / 模式 | 一个宿主、Native 路径（非 Shadow/Live） | 宿主版本、模式、停用方式 |
| 场景 | 一个场景 | 场景 id、决策点定义、事前信号 |
| 原则 | 一条当前有效原则 | artifact / activation / revision |
| 窗口 | 建议 7–14 天 | 固定开始日与结束日 |
| 成本 | 0 付费调用；不新增模型调用 | 允许的采集方式与上限 |
| 负责人 | 一名工程负责人 | 姓名/角色；Examiner 独立标注 |

**未固化任一项 → 不开窗。** 本草案不预填这些值。

---

## 3. 纳入条件（全部满足才计为一个机会）

1. 任务发生在已授权工作区与会话内，且时间在窗口内。
2. 任务到达**交付/提交类决策点**，该决策点在关键行动之前可观察；判断依据必须是场景卡事先定义的显式标记或窄映射，不得读取未来结论。
3. 场景匹配的唯一有效原则可读，且 artifact / activation / revision 与批准值一致。
4. 在 `t_action` 之前存在可观察的事前信号；信号来源与置信规则由场景卡固定。
5. 该行动有实际后果（交付、提交、发布、不可逆变更等），且属于授权范围。
6. 同一决策单元未被更早的机会键覆盖（见 §6）。

## 4. 排除条件（命中任一即不计入 T，并记录原因）

| # | 排除条件 | 记录为 | 不得写成 |
|---|---|---|---|
| X1 | 任务在 Native 路径下**本来就包含**目标内容（C03） | `already_present`，另列 | 干预增量 / 命中 |
| X2 | 只有事后才可识别信号，行动已发生 | `post_hoc` 或 `missed` | timely |
| X3 | 原则未授权、已撤销、revision 变更或不在有效集合 | `unauthorized_principle` | 命中 |
| X4 | 工作区 / 会话 / 时间窗之外 | `out_of_scope` | 漏触发 |
| X5 | 任务类型不在场景卡范围 | `out_of_scope` | T |
| X6 | 同一 `opportunityKey` 的重复消息 | 去重，不重复计数 | 多个机会 |
| X7 | 关键行动无独立证据，只有模型自述或 receipt | `unknown_action` | 已发生/未发生 |
| X8 | 场景需要治理变更（改原则正文/授权） | 走原治理流程，不计入本窗 | 运行时改写 |

## 5. 观察窗口

- 窗口在 Owner 书面批准时写入**固定开始日与结束日**；不自动延长。
- 到期即形成决定，即使样本少或结果不明。
- 新增一次有边界的窗口必须有具体问题与决定，不得因为“还没看清”而顺延。
- 窗口内不新增第二种场景、不扩大原则集合、不切换宿主矩阵。
- 窗口开始前与结束后不补记、不回填。

## 6. 稳定机会键（事前可计算，不使用未来信息）

**定义**

```
opportunityKey = sha256(
  "pd-aa-opp/v1" | sceneId | workspaceId | sessionId | anchorKind | anchorValue
)[:16]
```

**anchorKind 取值顺序（必须按序选择，不得跨级回填）**

| 优先级 | anchorKind | anchorValue | 说明 |
|---:|---|---|---|
| 1 | `host_message_id` | 宿主提供且可复核的消息/请求 id | 首选；若宿主不提供则降级 |
| 2 | `user_message_sha256` | 该决策单元首条 user message 的 SHA-256 | 不再做归一化“修正” |
| 3 | `session_turn_ordinal` | `sessionId` 内的单调轮次 | 仅在 1/2 都不可得时使用 |
| 4 | `unavailable` | 无 | **不生成机会键，不计数，不事后补锚** |

**规则**

1. 机会键在 `t_observable` 时生成并落盘；同一决策单元只生成一次。
2. 不同 `anchorKind` 或不同 `anchorValue` **不得合并**；疑似同一机会但锚不同 → 标 `ambiguous_anchor`，不计入 T。
3. 不得用 `t_action` 之后的信息（结果、产物、事后结论）构造键。
4. 键只用于去重，不承担身份证明；它不能替代 admission / session 绑定。
5. 同一决策单元内的多条消息共享一个键；进入新决策单元才有新键。

## 7. 事前字段（每个机会必须落盘）

| 字段 | 何时写 | 允许值 / 说明 |
|---|---|---|
| `opportunityKey` | `t_observable` | §6；不可得则 `unavailable` |
| `sceneId` | 事前 | 场景卡固定值 |
| `workspaceId` | 事前 | 授权值 |
| `sessionId` | 事前 | 宿主真实值；不得用 runId 冒充 |
| `t_change` | 事后可补 | 实际目标/风险变化或机会出现 |
| `t_observable` | 事前 | 按可得信息首次可识别机会 |
| `t_delivery` | 事前/请求级 | 目标文本送达时点 |
| `t_action` | 行动时或事后证据 | 首次关键行动；无证据 → `unknown` |
| `principleId` / `activationId` / `revision` | 事前 | 必须匹配批准值 |
| `deliveryPath` | 请求级 | `native` / `controlled` / `none` / `unknown` |
| `signalSource` | 事前 | 显式标记 / 窄映射 / 其他场景卡定义 |
| `actionKind` | 行动时 | 交付 / 提交 / 发布 / 不可逆变更 / 其他 |
| `exclusionReason` | 判定时 | §4 的 X1–X8 或空 |
| `unknownReasons` | 判定时 | §8 的 U1–U7 列表 |

**禁止**：用 `t_action` 后的观察倒填 `t_observable`；用模型自述替代行动证据；用 `receivedAt` 冒充模型开始生成时间。

## 8. unknown 规则

| # | 情形 | 记法 | 禁止 |
|---|---|---|---|
| U1 | 缺 `opportunityKey` 或锚不可得 | `opportunity=unknown`，不计入 T | 事后补锚 |
| U2 | 时钟不可比且无同一请求链的可靠顺序 | `timeliness=unknown` | 用另一侧时间补齐 |
| U3 | 未观察到目标正文到达 | `delivery=unknown` | 用“应该有”推定 |
| U4 | 关键行动无独立证据 | `action=unknown` | 用自述/receipt 补齐 |
| U5 | 机会边界有争议（同一任务多个决策点） | `boundary=ambiguous`，另列 | 合并成一个机会 |
| U6 | 原则版本在窗口内变化 | 该段 `unknown`，不跨版本合并 | 旧成功当新版本证据 |
| U7 | 采集失败、日志缺失、宿主崩溃 | `capture=unknown`，记录范围与缺口 | 当作 0 或当作漏触发 |

**总规则**：`unknown` 不是 0，也不是失败；它必须与 T/V/O/D 分开报告。任何“未执行检查”不得写成 PASS。

## 9. 计数与复盘口径

- T：审阅判断当时存在可改变的实际决定，且授权原则在行动前有合理干预可能；不要求后来一定犯错。
- V：T 中 PD 确实在行动前识别。
- O：V 中目标在行动前送达且可关联该决策单元。
- D：O 中后续行动/产物可关联；区分有帮助、无变化、伤害、未知。
- 必要介入 / 多余打扰 / 不必要返工分开计数。
- 相关性不支持因果；少量或混合结果也可结束复盘。
- 无代表性案例直接写明，不编造案例。

---

## 10. 停用与恢复（窗口内触发即停）

沿用 SPEC §7：

1. 未授权原则、跨 Session 污染、重复注入导致异常、请求确认误报、泄露、阻塞正常提交、重大行为损害；
2. 立即停用本轮映射，回到 Native；
3. 保存事实、影响范围、未知项；不改 Runtime V2 治理状态；
4. 恢复需针对原缺陷复验，并按原授权边界重新批准。
