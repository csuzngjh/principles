## 3. Console 操作路径（代码核实；本轮未启动 Console，界面未实点）

1. **定位**：Console「生效情况」页（`/activation`）→「已激活原则」，卡片标题就是 §1 表中的原则标题。也可以直接打开 `/activation?activationId=<URL 编码后的激活 ID>`，页面会滚动到该卡片并高亮。激活 ID 的形式是 `act_prompt_` 加原则标题。原则详情页按账本条目组织，而这四条的激活目标不在账本中，因此**不推荐**在原则详情页操作。
2. **停用**：卡片上的「停用」→ 确认。后端调用 `POST /api/activations/:id/disable`，要求 confirmed=true，并记录一条 `console_disable_confirmed` 治理决定。副本上用等价的 CLI 演练过，4 条全部成功。
3. **保留，并转为 Owner 批准**：卡片上的「修改为可注入版本」→ 输入新正文（必须与原文不同）→「创建待审批的新版本」→「前往治理焦点审批新版本」（`/focus`）→ 批准。批准后旧版本停用，新版本以 owner 授权生效，装配顺序移到末尾。L1、L3、L4 入队已演练；**L2 被拒绝**；批准这一步未在副本上执行。
4. **停用之后恢复**：L1、L3、L4 需要运维执行隐藏命令 `pd runtime activation dispatch -a <artifactId> -w <工作区> --confirm`，再到治理焦点批准；副本上已完整演练，结果是 owner 授权、激活 ID 重新生成、装配顺序移到末尾、每块短 8 字符。**L2 没有正式恢复途径。**「重新打开审批」（reopen）只适用于已有审批行的记录，对这四条都不适用。
