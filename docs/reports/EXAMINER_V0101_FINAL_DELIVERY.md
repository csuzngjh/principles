## 1. Examiner 现在能做什么？

Examiner 从"工程师用的离线研究面板"升级为**你能直接操作的原则评估产品**。你可以在 Console 里对任何一条 active 原则：

1. **看清它的真实生产状态**——运行时激活了几条、生产注入投影会不会带上它、实际预算来自哪里、回执与干预证据（投递/应用/行为/效果/结果）有多少，以及每一类数据的可信边界（哪些是投影、哪些只是"已提交"、哪些是 Agent 自述——绝不互相冒充）。
2. **配置一次受控 A/B 评估**——选挑战套件（默认 2 题或 6 题校准套件）、模式（默认完整库增量）、重复次数；页面直接告诉你 Gold 还没过独立人审（Gate 1）、真实宿主运行还差什么。
3. **执行并看到全部证据**——冻结的生产快照（A/B 起点与生产的每一处差异都有标记）、fail-closed 预检、离线执行、宿主演练（零模型调用的就绪检查清单）、F2 真实宿主请求（未授权会被明确拒绝并告诉你缺什么）。
4. **读懂报告并做决定**——ITT 效果、注入忠实度、重放校验、限制说明，外加同一条原则的**生产观察**（独立通道，不与实验数字合并），最后一键跳进既有的原则治理流程做保留/修订/撤销决定。Examiner 自己绝不改生命周期。

## 2. 与 v0.9 相比发生了什么变化？

| | v0.9 | v0.10.1 |
|---|---|---|
| 界面 | 单个技术面板 | 四页 Owner 旅程（评估→配置→执行→报告） |
| 生产证据 | 无 | 每条原则的完整生产证据聚合（激活/注入/回执/证据审计+覆盖度+降级原因） |
| Study 输入 | 固定 2 个演示题、固定预算 | 可选套件目录；冻结生产快照（预算/路由/差异标记）；真实 Pain 溯源进冻结映射 |
| RuleCode 事实 | 账本计数 | 运行时激活行为证据（按目标过滤；耦合即拒绝，不再误伤干净目标——本轮发现并修复的真实 bug） |
| 执行模型 | 仅同步离线 | 离线（同步，兼容）+ 宿主演练/F2（异步 202 契约：runId、单活、重启恢复、绝不自动重试未知结果） |
| F2 | 纯拒绝 | 就绪投影+授权门+受理+响亮不执行（零模型调用）；授权后路径就绪 |
| 决策闭环 | 无入口 | 报告页 → 既有治理工作流（零新决策系统） |

## 9. 是否修改生产数据？ — **零**。全部验收在临时工作区；v0.9 历史资产经树哈希证明未变；主检出未写文件。

## 10. 还有哪些真正影响使用的问题？

- Gold 独立人审（Gate 1）未做 → 正式效果结论保持阻塞（套件均 SYNTHETIC gold，报告如实标注）。
- 安装版（npx 安装的运行时）lab payload 不含 F2 transport 模块 → 安装版内真实 F2 执行需后续扩展 payload（已记录，不影响本轮一切功能）。
- 生产观察通道依赖各宿主证据记录器持续写入——工作区刚启用时各通道可能为 degraded（如实显示原因与 nextAction，不当成零事件）。

## 11. 如何启动和访问系统？

- 开发检出：`packages/pd-console` 起 dev server（或 `npm run test:e2e` 的 3101 实例）→ `/#/examiner`。
- 安装运行时：PD Companion 起 Console → 侧边栏 Examiner（研究引擎随 console payload 附带）。
