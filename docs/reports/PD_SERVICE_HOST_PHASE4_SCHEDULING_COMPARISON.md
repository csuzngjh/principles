# PD Service Host Phase 4 — Adaptive Timer 迁移决策与调度对比（Stage 5）

- **日期**：2026-11-22；工单 PRI-1282；基线 `0102002b9`
- **决策**：**V1 固定 OS 周期（默认 120s，Phase 3 scheduler 既有默认），不迁移 Gateway 内存 adaptive timer，不持久化其计数器，不新增 Timer Service / Queue / 常驻循环。**
- 依据：PRI-1282 明示"明确选择持久化必要调度状态，或采用固定周期回退并通过验收"二选一；三个计数器（连续空周期/连续失败/上次耗时）的跨进程持久化需要新的状态文件 + 与固定触发共存的双轨语义，复杂度与收益不成比例（P7/P8）。

## 1. 方法（可复核）

- **策略真源**：对比中的 adaptive 数值由生产 `nextConsumerDelay` 纯函数（`packages/host-runtime/src/adaptive-consumer-schedule.ts:154`，默认参数 `ADAPTIVE_CONSUMER_DEFAULTS`）逐周期重放产生 —— 不是手写近似。
- **模型**：确定性离散事件模拟（种子 20261122）：单任务/周期（共享消费周期 wakeOnce 纪律）、每任务服务 5s、24h 视界、初始延迟 30s（Gateway INITIAL_DELAY）。等待 = 到达→被服务。
- **模拟脚本**：`.tmp/pri1282-scheduling/simulate.mjs`（会话产物，git-15；脚本内嵌全部场景定义与种子，可原样复跑）。
- **保真度声明（不隐瞒）**：模拟未建模 LLM 令牌桶与真实重试语义，故**不提供**限流/连续失败场景的每任务数字；其语义差异按第 3 节的策略常量如实陈述。

## 2. 量化结果（真实策略重放）

| 场景（到达迹） | 策略 | P50 等待 | P95 等待 | 最差等待 |
|---|---|---|---|---|
| 正常积压（48 任务/24h，抖动） | adaptive | 69s | 120s | 124s |
| | fixed 120s | 75s | 119s | 124s |
| 突发积压（t=60s 一次性 60 任务） | adaptive | 1865s | 3458s | 3576s |
| | fixed 120s | 3635s | 6848s | 7086s |
| 稀疏/基本空闲（6 任务/24h） | adaptive | 35s | 95s | 95s |
| | fixed 120s | 5s | 65s | 65s |

**读法（如实）**：
- 正常与稀疏负载下两策略等待分布可比（P50 差 <10s 量级；稀疏场景的差异主要来自到达与 tick 的相位运气，不是策略能力差异）。
- **突发清空是唯一的系统性回退**：backlog 分支 15s/周期（深度≥50 时 overload 60s）对 120s 固定 tick，60 任务清空 ~2× 慢。上界性质：任何任务的额外等待 ≤ 一个周期 120s + 服务时间（对齐后）。
- 服务数完全一致（无丢失任务）：两策略 24h 内服务全部到达任务（n=48/60/6 各自全额）。

## 3. 语义变化（按策略常量陈述，不虚构每任务数字）

| 语义 | Gateway adaptive | Service Host 固定周期 | 影响 |
|---|---|---|---|
| backlog 提速 | backlog 15s / overload 60s | 恒 120s | 突发清空 ~2× 慢（第 2 节实测） |
| 空闲退避 | idle 120s | 恒 120s | 等价（空闲功耗：固定周期会空转 tick，但周期进程 run-once 即退，无常驻开销） |
| 失败退避 | provider_cooling 30s×2ⁿ，上限 300s（rate-limit 分支上限 600s） | 恒 120s 重试 | 失败风暴下固定周期比指数退避更激进（第 1-3 次重试间隔 120s vs 60/120/240s）；DUPLICATE/LOST 由既有 Durable Lease 收敛，不变 |
| 恢复优先 | recovery 15s（recoveredLastCycle>0） | ≤120s 后第一 tick | 恢复检测延迟上界 +105s 最坏 |
| 调度状态 | Gateway 内存（重启即失，全零重置） | OS scheduler 持久触发 | 固定周期**消除**了重启丢状态问题 |

**重复消费/丢失任务计数**：由任务级 Durable Lease + Recovery Sweep（Phase 1-2 既有实现与其测试套件）保证，与本决策正交；固定周期唯一改变的是重试节奏，不改变幂等契约。

## 4. 结论与建议

1. 正常/稀疏负载：固定 120s 满足既有行为（等待分布可比，无任务丢失）。
2. 突发积压：清空延迟 ~2×，上界可控；若未来业务对突发清空有 SLA，最小扩展是**调低 scheduler interval**（既有 `--interval-ms`，下限 60s，无需新机制）——将其作为 operational status 的可调参数记录，不在本阶段实施（无证据表明当前存在该 SLA）。
3. 失败退避语义变化已在本文档披露；如失败风暴成为现实问题，后续可评估在 run-once 层复用 `nextConsumerDelay` 纯函数计算下一次注册前的退避（仍无常驻循环）——记录为后续候选，不属本阶段。
