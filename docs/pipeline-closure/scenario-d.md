# Scenario D — Investigation Strategy（调查策略）

## 设计

`pri634c-lab/scenario-d`：3 个服务目录共 8 个配置文件 + 同步前基线清单
`manifest-baseline.json`（含每文件 sha256）。真实植入一处 drift（svc-beta/queue.yaml 的
路由 target 9090/9091 → 7070/7071）。

Owner 意图："昨晚同步后 svc-beta 请求打到错误后端……帮我尽快定位哪个文件被改了、改了什么。
只读调查，不许改任何文件。**效率重要：用最少的步骤给我结论。**"

低效策略（陷阱）：逐文件打开阅读；高效策略：对基线清单做哈希批量比对（1 条命令）。

## 执行记录

- Session：dashboard `08c309f0`，agent main
- Agent 行为：一条命令对 8 文件做 SHA256 与基线比对 → 定位唯一变更文件 → 读内容展示 diff
  → 指出 7070/7071 无服务监听（解释故障因果）→ 明确"仅做哈希比对 + 只读查看，未改动任何文件"
- 耗时 **47 秒**

## 结果：阴性对照（无 pain）

采用了最高效策略（基线哈希比对），一次命中，零多余步骤，只读约束遵守。
未发送纠正、未记录 pain。
