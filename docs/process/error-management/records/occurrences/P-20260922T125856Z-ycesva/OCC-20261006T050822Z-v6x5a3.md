PRI-942 (#1928) added a routing guard whose docstring claimed it collected the console's literal `<Link>` targets; the regex behind that claim was `/\bto="([^"]+)"/g`, i.e. double-quoted JSX attributes only — while the same codebase already writes `` to={`/activation`} `` (`FocusPage.tsx:758`), an interpolation-free template literal. So the guard's stated coverage and its enforced coverage diverged, and the divergence was silent: a dead link in backtick form would have passed CI green, which is exactly the promise the guard existed to keep. Found by the Standards axis of the two-axis self-review, which re-derived the claim against the source instead of trusting the comment. Fix widened the pattern to the four literal forms (`to="…"`, `to={"…"}`, `to={'…'}`, `` to={`…`} ``, still excluding interpolated targets) and, because a coverage claim is itself a claim, added a case asserting the backtick form is collected — verified red against the pre-fix regex (1 failed / 36 passed) before shipping it. Lesson generalizes past this file: when a guard's value comes from *what it scans*, the scan's coverage needs its own positive assertion; "the suite is green" cannot distinguish "nothing dead" from "the scanner reads one spelling".
