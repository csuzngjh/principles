**What happened**: B-1 诊断中的拟议配对守卫，把本应产生的五条模板缺失表示为普通空数组。alias 或 LLM 用例非空时，剩余集合仍能重放通过，形成“其他检查通过”替代“必需检查已执行”的错误成功判据。该方案在评审和生产 sandbox 离线前后对照中被拦下，未上线。

**Why it's wrong**: 缺少必需证据与正常不适用是不同事实。将两者都表示为空集合，会让下游非空集合检查和成功重放把派生缺口隐藏起来；遥测不能恢复已经被取消的检查。

**Correct approach**: 私有派生结果显式区分失败，唯一消费者在 alias/LLM 合并与 gate 调用前立即返回失败。approved 路径复用既有 PRI-634 R3 永久失败通道；needs_revision 保持评价完成语义，但不得伪造 replay 证据或组装规则。工具与路径来自同一个完整合格样本。

**How to prevent**: 通过 runner.run、真实 SQLite 和生产 factory 测试必需模板缺失时 alias 非空、LLM 非空及 needs_revision 分支。必须同时断言终态、gate 未调用、无 replay provenance；并验证正确配对后原有真实模板失败仍保留。
