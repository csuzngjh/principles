## Observation (PRI-935, 2026-09-28)

**Where**: `packages/host-runtime/src/prompt-injection-projection.ts` — the
console's prompt-injection budget forecast consumed by
`pd-console/src/server/models/ApprovalsConsoleModel.ts`.

**What happened**: the projection called
`trimToBudget(principles, 2000, escapeXml)` while the production plugin
route (`openclaw-plugin/src/hooks/prompt.ts`) calls
`trimToBudget(dedupedV2, 2000, escapeXml, nextSessionTurnOrdinal(...))`.
Omitting the 4th argument did not make the forecast "conservative" — it
selected a *different policy* (`legacy_fifo_prefix_v1`), which structurally
excludes the newest activation from every truncated selection.

**How it was observed**: the console therefore emitted
`injection_budget_excluded: ... will NOT enter agent behavior until older
ones are deactivated` for a principle that production injects within N user
turns under fair rotation. Reproduced read-only against the real workspace
`state.db` (19 eligible prompt activations, budget 2000): the console forecast
selected 9/1893 chars with the newest absent, while `fair_rotation_v1` injects
it at `roundKey=10` (also 13, 14, 15, 17, 18). The Owner was being told to
deactivate healthy principles.

**Aggravating factor**: `50ed22ec` (PRI-904) added fair rotation and touched
`openclaw-plugin` + `principles-core`, but not `pd-console` nor the
projection, and the projection's doc comment asserted "identical input ×
ordering × trim logic as openclaw-plugin" — a self-certifying comment that
nobody differential-tested. The existing test
(`prompt-injection-projection.test.ts` "Case 2") actively pinned the FIFO
prefix as expected behavior, so the divergence was locked in by tests.

**Second-order instance found during the fix**: the first implementation
passed `roundKey` through but computed reachability only when the *forecast*
had a round key. The console never has one, so the reachable set was always
empty and the starvation claim would have persisted — the fix looked correct
while reproducing the original defect. The corrected design computes
reachability under the **production** policy and reports `productionRotates`
separately from the forecast's own `selectionPolicy`.

## How to prevent

- When mirroring a production selector, enumerate **all** its policy
  parameters; each one the mirror lacks is an independent divergence channel.
- Make the policy the replica actually ran a **returned value**, not
  something each consumer hardcodes in prose.
- Prefer "no round key ⇒ reachable set empty" to be an explicit, tested
  degradation rather than an emergent property of an `if`.
- Treat "this is conservative" as a claim requiring evidence: in this case
  the default branch was the *only* branch that could starve the newest item.

## Regression guard

`packages/host-runtime/tests/prompt-injection-projection.test.ts`:
4 PRI-935 cases pin policy reporting, rotation reachability of the newest
activation, true starvation (oversized), and the non-rotating shared route.
`packages/pd-console/tests/integration/governance-approve-activation.test.ts`
asserts the approve path emits `injection_budget_queued` over real HTTP.
Verified by negative control: reverting only the two production source files
makes 5 of these tests fail.
