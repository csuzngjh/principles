- **What happened**: PR #1635 handed the long-lived Console Bearer token to the renderer over IPC, guarded by "plain-http loopback URL" — hostname checked, PORT not. Any other loopback service's page keeps the bridge and would receive the credential; the destructive clear endpoint had only a sender-id check.
- **Why it's wrong**: On loopback, hostname is not an identity — every local service shares 127.0.0.1. A class-level check does not select the intended peer; it authorizes a whole class of unrelated origins to pull or erase a long-lived credential.
- **Generalized failure mode**: When guarding a credential by peer origin, compare the sender against the ACTIVE server's FULL origin (protocol+hostname+port) from the owning authority (supervisor state), failing closed when the authority has no active peer.
- **How to prevent**: For any origin guard ask "what ELSE satisfies this predicate?" (other ports, sibling paths). Compare exact origins against the runtime's own server URL, never class predicates; unit-test the different-port rejection.
- **Regression guard**: pd-companion `tests/lib/console-origin.test.ts` + `tests/main/coexistence.test.ts`.
