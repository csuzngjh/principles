PRI-927 第一版把 https-only 策略做成跨模块共享谓词（`release-metadata.ts` 导出、`apply-payload.ts` 调用），运行时完全有效，但 CodeQL `js/insecure-download` 的 sanitizer 判定是作用域局部的：跨调用的类型细化不被追踪，high 依然报在 `fetch` 调用点上（head `ea871b63` = "2 new alerts including 1 high"），而本地 `npm run verify:merge` 全绿没能发现这一点。修复形状：在真正打开承载方的那一层自己 `new URL()` 解析、测解析后的 `protocol`，并把归一化后的 `href` 交给 transport（head `38fb8545` 该 high 消失，降为 1 条 medium）。这是 ERR-080"控制作用在错误的层/形式上"的一个新变体：形式对了（解析后的 URL），但**位置**离开 sink 一个模块，对静态证明而言等于没有控制；安全边界判定必须与它所保护的副作用处在同一可证明作用域。

- **How to prevent**: 任何把协议/路径/包含性判定重构进"共享谓词/共享 helper"的 PR，先问一句——这条判定保护的效果发生在哪个作用域？如果那个作用域会被静态扫描（CodeQL / 数据流规则）检查，判定就必须在**该作用域内可见**，helper 只能做辅助而非代替本地判定。
- **Regression guard**: `packages/create-principles-disciple/tests/apply-payload-url.test.ts` 的"注入可用 transport 仍拒 `http://`，且断言 transport 调用次数为 0"（拒绝先于任何出网），以及 sink 作用域内的 `assetUrl.protocol !== 'https:'` 判定本身。
- **Residual**: 同族的 `js/http-to-file-access`（网络字节→写盘）无法用位置修复消除，属 Owner 裁决项，见 PR #1876 Follow-ups 2。
