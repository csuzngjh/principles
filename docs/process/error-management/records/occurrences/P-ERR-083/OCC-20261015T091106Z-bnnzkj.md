PRI-986 把 npm 对账 cron 从每周五 04:00 UTC 改为每日 04:00 UTC，只改了权威（workflow YAML）与本包测试守卫，漏了 `packages/create-principles-disciple/tests/release-target-matrix.test.ts:201` 里第二处手抄字面量 `cron: '0 4 \* \* 5'`。改 cron 后 `npm run verify:merge` 在该包测试处跑红才暴露。

同一根因在两周内出现两次：PRI-979 seam 6 是 smoke 测试里手抄的 install-layout 版本号，本次是手抄的 cron。二者都是"发布/配置常量被抄进守卫"，抄写点分散在不同包的测试里，改权威值时不会自动传播。

处置：两处守卫都改为从工件派生——本包测试断言 cron 的 day-of-week 字段为 `*`（不再钉时钟字面量），`scripts/__tests__/release-workflows.test.ts` 从解析后的 YAML 取 schedule 条目并用 `isDailyCron` 判定。负控成立：旧值 `'0 4 * * 5'` 会让两个守卫都失败。

后续（未在本 PR 做）：需要一条机械化守卫，扫描"测试里出现的 cron / 版本字面量与 workflow 或 manifest 权威值不一致"，否则第三处抄写点仍只能靠 CI 跑红发现。
