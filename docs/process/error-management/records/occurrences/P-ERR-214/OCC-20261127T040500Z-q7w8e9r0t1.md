PRI-1299 PR #2805 follow-up review found two shapes of the same lifecycle-evidence error. First, an Evaluator first created after an upstream Artificer revision already evaluated the current artifact, but the revisionCount/cascade-cause heuristic still reopened it on rerun, producing duplicate evaluation and downstream approval evidence for the same input. Second, internally consistent run/artifact output could be stale together: terminal recovery did not prove that the output evaluated the dependency artifact that fresh execution would read, and a nonterminal completion intent captured before an upstream revision could still be finalized after that revision.

Fixed by resolving the current dependency artifact through the same selectTaskRevisionArtifact authority as fresh execution, passing that input identity into Artificer/Evaluator recovery validation, refusing repair-round recovery without convergence evidence, probing input-current recovery before deciding whether a formal cascade is needed, and refusing to resume or finalize completion intents whose durable output names a different input artifact. Regression coverage includes first-evaluation-after-revision rerun without another model call or cascade, stale completion-intent re-evaluation against the revised artifact, and the pre-existing stale-terminal cascade path.
