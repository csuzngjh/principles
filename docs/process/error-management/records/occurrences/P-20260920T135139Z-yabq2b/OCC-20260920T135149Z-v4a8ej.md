- **What happened**: This record is the originating occurrence. PR #1781 added `Verify the packed installer tarball carries the product identity` to `publish-npm.yml`, consuming `npm pack --json` output with `JSON.parse(...)`. `bundle-plugin.mjs` (run by the package's `prepack` hook) wrote its progress banner with `console.log`, npm spliced it into the same stdout stream, and `Publish create-principles-disciple` died with `SyntaxError: Unexpected token '�', "📦 Bundlin"... is not valid JSON` on run 35509453375 (head 8821d1b5). Reproduced and fixed the same session: a throwaway package with a `prepack` hook that logs to stdout fails the identical parse (`first bytes of stdout: "📦 Bundling plugin + pd-cli for npm publish...\n  Copying plu"`), and the same package logging to stderr yields `PARSE OK -> filename=pd-pack-probe-1.0.0.tgz`.
- **Why it's wrong**: The step had zero execution evidence before it mattered — the release gate upstream had been red on main since 09-19, so the publish job never reached it. Green CI on the PR therefore said nothing about this line, and its first real run broke the whole publish train at a step whose failure message described an emoji rather than its cause.
- **Correct approach**: `bundle-plugin.mjs` routes all progress through a `log()` helper writing to `console.error`; stdout is empty and reserved for data.
- **How to prevent**: For a `--json` consumer step, run the exact `JSON.parse(stdout)` locally against a package that actually has a `prepack` hook, and treat any CI step that has never executed (upstream red) as unverified code rather than covered code.
- **Regression guard**: verified producer contract — `node scripts/bundle-plugin.mjs --output-root <temp>` emits 0 bytes on stdout, 4585 bytes on stderr; no mechanized gate.
