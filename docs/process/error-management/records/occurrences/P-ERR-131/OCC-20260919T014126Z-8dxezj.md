What happened: the first full-product release train since 2026-09-14 died at publish 4/7 (codex-adapter tsc: 7x TS2305/TS2353, host-runtime has no exported member). Root cause (clean-worktree repro, Windows reproducing Linux CI): train step 3/7 runs npm version 0.7.5 --no-git-tag-version inside packages/host-runtime; npm version re-runs workspace resolution, codex-adapter's declared ^0.1.0 is no longer satisfied by the workspace version, so npm installs a REGISTRY copy (host-runtime@0.1.1) nested in packages/codex-adapter/node_modules; step 4/7's tsc (moduleResolution: bundler, nearest-first) reads the nested 0.1.1 types instead of the freshly built workspace dist. Why it looked impossible: the missing symbols exist in HEAD source, local builds pass, per-PR CI passes (no mid-run bump in those trees), and the 0.7.5 tarball packed one minute earlier from the same runner dist is complete. Correct approach: version bumps inside a shared multi-package CI tree must be plain file edits; npm version implies an install-graph operation, not a metadata edit. Verified: npm run --workspace does NOT reify an out-of-range tree, only npm version does. Related: ERR-131 family, ERR-068 (lockfile drift), PRI-690 (train build-order defect, prior class). Fix: .github/actions/publish-npm-package/action.yml bump step now uses direct package.json edits; inline push-path publish job left as-is (matrix entries run on separate runners, no shared tree).
