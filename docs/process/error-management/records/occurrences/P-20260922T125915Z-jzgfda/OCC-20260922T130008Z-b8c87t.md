listSessions() cloned the newly added injectedActivationIds while injectedPrincipleIds stayed aliased to live session state through the object spread. Because PRI-899 resolves a reported principle to its activation by injectedIds.indexOf(principleId), a consumer reordering the principle array it was handed would make the next self-report read the parallel activation array at the wrong index and persist a receipt against a DIFFERENT activation. Measured: with the clone removed the pairing test failed with expected [ 'principle-b', 'principle-a' ] to deeply equal [ 'principle-a', 'principle-b' ]. Fixed by cloning both arrays together, and the test now mutates both as handed out and asserts the persisted row.
