- **What happened**: PRI-917 landed two by-design ledger behaviors — (1) a reuse decision resolves a consumed candidate into an EXISTING principle via `Principle.reuseEvidence[]` (zero ledger growth), and (2) the Phase 1/PR1 kind gate refuses non-`principle` kinds from ever writing the ledger — but the two read/audit surfaces were never updated to recognize them. `PainChainReadModel` built its candidate→principle linkage ONLY from `derivedFromPainIds` and hardcoded "ledger zero-growth" as `degraded/ledger_write_failed`, so every successful reuse chain was reported as a failure by `pd trace` (R7: OC-02 + CX-02 reproduced 4x). `auditCandidateLedgerConsistency` (and the drifted inline copy in `pd candidate audit`) flagged every reuse- or kind-resolved consumed candidate as missing: `pd health` showed missing=61 where only 5-8 were true drift, masking real drift under 52+ false positives and pinning health degraded/exit 1 long-term.
- **Why it's wrong**: A write-side change does not propagate itself. When a durable write path gains a new by-design expression (or by-design non-write), every read/display/audit surface that judges the persisted state must be enumerated and taught the new vocabulary, or the observability layer inverts: success paths alarm, and the noise floor hides the true drift the audit exists to surface.
- **Correct approach**: The audit judgment was centralized in core (`auditCandidateLedgerConsistency`, reuse-aware + kind-aware via `isPrincipleLedgerEligibleKind`) and the CLI `pd candidate audit` rewired to consume it (one judgment truth, no inline drift); `PainChainReadModel` merges `reuseEvidence.candidateId → target principle` into the linkage map so reuse chains trace as successes with the reuse target in `ledgerEntryIds`. New additive result fields (`reusedResolvedCount`, `nonLedgerKindCount`, `missingLedgerEntryIds`) make the exclusions observable instead of silent.
- **How to prevent**: When adding or changing a ledger write path (new field, new refusal disposition, new resolution expression), grep ALL read models / audits / CLI judgment surfaces over that store (`rg "loadLedger|derivedFromPainIds|principle_candidates"`), and update each in the same change. An audit that cannot distinguish "by design absent" from "drift" is not an audit.
- **Regression guard**: vitest regression suites — `pain-chain-read-model.test.ts` (reuse chain → succeeded, not ledger_write_failed; malformed evidence not trusted) and `candidate-audit.test.ts` (reuse-resolved not missing; non-principle kinds counted not flagged; true drift still reported). No static/architecture guard.
- **Related ERRs**: EP-02 (write-side change must enumerate read sites), ERR-089-family sibling-branch rule (both audit surfaces fixed together).
