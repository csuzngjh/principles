Codex 插件 `pd-setup` 用 `npm install --prefer-offline` 安装 pin 住的运行时后，只凭 npm 退出码 + 入口文件存在就写 `.pd-runtime.json` 标记并宣告 `runtime_installed`。npm 11 在「stale packument + 已有 tree」下会 `placeDep REPLACE` 后把 `@principles/core` 整棵 `REMOVE`，退出码仍为 0，于是标记把一次空装永久固化：后续每次 setup 都走 `already-present` 短路，pin  silently 降级到旧字节。

判据错误点同 ERR-150：退出码证明的维度是"命令跑完了"，不是"pin 声明的字节在盘上"。修复把证明改成内容判定——`verifyInstalledRuntime()` 逐包读已安装的 `package.json` 版本与 pin 比对，标记只在该断言成立后才写；断言失败即 `runtime_pin_mismatch` 大声失败并给出"删除插件 data 运行时目录后重跑 setup"的 nextAction；顺带去掉了 `--prefer-offline`（与 sync-plugin.mjs 先例一致），并让"标记与字节不一致"强制重装而不是信任标记。

负控：移除标记门后同一夹具断到的是 `runtime_install_failed`（重装被真正触发），证明该门是可观察的分支而非死代码；首装端到端测试额外断言 `readInstalledRuntimeVersions()` 等于 pin。
