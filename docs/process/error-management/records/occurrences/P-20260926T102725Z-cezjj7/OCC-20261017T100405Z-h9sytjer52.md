PR #2067 评审轮发现 P1：watchInstalledVersion() 的版本变更路径只调用了 supervisor.onServerExit(null)——它只把状态机翻到 restarting，从不停止旧 Console 进程；随后 scheduleRestartRetry 定时 spawn 的 pd console open 探测到旧进程仍健康占着端口而返回 reused，handleLaunchResult('reused') 又把磁盘新版本号写成 serverStartedVersion 并切到 attached，于是旧服务被标记为'升级完成'，之后的版本检测永远不再触发。修复把 kill/确认/裁决提取到 lib/version-handover.ts：ownedManagedHandle 在状态仍为 running 时快照所有权证据（onServerExit 之后快照会得到 undefined，kill 静默跳过——这正是缺陷形状），killManagedServerAndWait 真正 kill 并轮询确认 server+CLI 两个 PID 退出，judgeVersionChangeLaunch 作为唯一裁决权威：handover 期间 reused 只能 keep-waiting 永远不能完成切换，started 必须版本一致才接受，其余终态失败。守卫：接线测试钉住快照先于状态转移的顺序（红灯验证过：把快照移到 onServerExit 之后测试即失败）；真实子进程测试覆盖旧进程健在占端口→kill 确认→端口释放→新 PID 进程接管，attached 外部实例绝不产 killable handle，kill 被拒/进程顽固存活如实返回 unconfirmed。
