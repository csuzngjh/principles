2026-11-06 disk-cleanup session (escaped, real damage outside the repository). `npm run dev:worktree:cleanup -- <path> --delete-branch` drives `git worktree remove --force` (Git for Windows 2.40.0.windows.1, `core.longpaths` unset). On two MERGED worktrees — `PRI-1112-aa-delivery-verifier` (09:23) and `PRI-1129-p0-openclaw-launcher` (09:25) — the `.tmp/` test fixtures held junctions pointing OUT of the worktree into the real global install `%APPDATA%\npm\node_modules\openclaw` (OpenClaw plugin-captures `node_modules/openclaw`, fake-home skill dirs linked to `dist/extensions/*/skills/*`). git recursed through the junctions and deleted real files: the first three root entries in NTFS order (`.openclaw-lifecycle-pending`, `CHANGELOG.md`, `cli-root-options.mjs`) plus two `SKILL.md`. It stopped only because the junction-composed path exceeded MAX_PATH at the fourth entry. `cli-root-options.mjs` is statically imported by `openclaw.mjs` (via `gateway-run-argv.mjs`), so every new `openclaw` launch failed with ERR_MODULE_NOT_FOUND for about an hour. In the same batch, four large worktrees (90k–540k files) failed mid-removal and became `NO_GIT_MARKER` residue shells: git deleted part of the tree, then the admin dir, and the tool only reported `is not a working tree`.

Detection: before deleting the residues, the dry-run of `dev:workspace:cleanup --residue` listed reparse points whose targets were outside the root; diffing the installed package against `npm pack openclaw@<ver> --dry-run --json` located the 5 missing files.

Repair: the 4 files were restored from the registry tarball (sha512 identical across local hash, `npm pack`, and registry `dist.integrity`) with `cp -n`, then the full manifest was re-checked (only the self-consumed lifecycle marker was intentionally left absent). The residues were removed with the reparse-safe `dev:workspace:cleanup --residue ... --ack-unknown --apply`, after first unlinking each external junction individually with a full manifest re-check after every unlink. No other location changed in the cleanup window.

**Correction to this pattern's prevention rule: `git worktree remove` is NOT junction-safe on Windows.** Before deleting any worktree, enumerate reparse points (`scanReparsePoints` in `scripts/dev/lib/residue-delete.mjs`) and unlink every link whose target lies outside the root, or delete the tree via `removeResidueTree`. Verify the external targets afterwards. The tool fix, the Must-check correction, and the Enforcement Decision are tracked in PRI-1143.
