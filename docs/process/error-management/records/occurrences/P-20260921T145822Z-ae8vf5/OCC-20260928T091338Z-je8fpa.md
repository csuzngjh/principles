- **Occurrence**: PD console `/api/update/check` runs a full online TUF metadata refresh (several sequential requests to the metadata host) under the server's generic 10s request budget. On a CN network a single slow DNS/TLS leg pushed one measured run to 12.52s; the 504 `Request timeout` was rendered as "无法加载更新数据" — a data-load failure — so the Owner reasonably concluded the update subsystem itself was broken, while `manager.check` was healthy and 2.2.0 was already current.
- **Impact**: Owner-visible red state on every install with a slow metadata round trip (~1 run in 5 on the affected machine); diagnosis pointed at release metadata/identity instead of the wait budget.
- **Fix**: adhoc-20260928-update-check-timeout — `PD_UPDATE_CHECK_TIMEOUT_MS` (default 30s) gives the check its own budget; an unusable value falls back to the default with a loud startup line. The budget is chosen in `src/server/index.ts`, whose request handler is not exported and whose module runs `main()` on import (index.ts:354, :706), so no committed guard pins that wiring for either knob — tracked as a testability seam in PRI-925.
