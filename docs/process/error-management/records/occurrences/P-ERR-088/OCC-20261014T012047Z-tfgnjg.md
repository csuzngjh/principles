- **What happened**: In PRI-957 / PR #2017 the write-side regression test `pain-record-cwd-workspace.test.ts` was supposed to prove cli-5 ("a failed parse performs no state write"). It fed the resolver a `null` workspace-discovery result, while the code path that was actually broken returns the new discriminated state `kind: 'unparseable'` together with the directory the operator is standing in. The test therefore asserted a refusal that the production path could never reach, went green, and the real P1 safety gap — a write targeting a workspace whose declaration is UNKNOWN — escaped to the reviewed head. The same commit's PR body asserted "解析失败在任何写入之前抛出" without evidence: `pain-record.ts` only warns when `loadPdConfig` fails and continues with defaults, so the claim was false as written and the parse layer was the only gate that could have stopped the write.
- **Why it's wrong**: Both are self-authored verification that never executes the failure path it claims to cover. A negative assertion fed with a state the production code cannot produce is vacuously true, and it is worse than no test because it manufactures merge evidence. Stating the guard as prose in the PR body turned an unverified claim into an apparent fact for the reviewer.
- **Correct approach**: Make the missing state unrepresentable at the type level (`WorkspaceDiscoveryResult` as a `resolved` / `unparseable` union with no workspace path on the failure arm), then drive the regression test with exactly that variant and assert that no service is constructed; for the real machine, prove the refusal by showing no `state.db` appears under the rejected workspace. Every failure-path test must name the state the production branch actually emits, not a nearby nullish value.
- **How to prevent**: For each failure branch the author adds, run a positive control that executes it and asserts a signal unique to that branch, plus a negative control that must fail when the branch is not reached; before writing "X throws before any write" into a PR body, quote the command that observed it.
