- **What happened**: `candidate-audit.test.ts`'s "returns error when DB throws" test asserted only `status === 'error'` — a non-unique signal produced by BOTH the missing-db early return and the DB-throw path. Two mock-isolation defects silently rerouted it: (1) `vi.spyOn(fs, 'existsSync').mockReturnValue(false)` from the earlier missing-db test leaked (restoreAllMocks does not undo spies on module-mock exports); (2) `clearAllMocks` does not reset mock implementations, and an arrow-function `mockImplementation` cannot be constructed with `new` (vitest then throws the arrow function itself, not the intended Error). Net effect: the file exercised the missing-db path twice while claiming to cover the DB-throw path — its assertions passed vacuously.
- **Why it's wrong**: A test that passes on an unintended path proves nothing about the claimed path; the F1 reason-swallowing defect coexisted with this vacuous test, which is exactly why the test suite never caught it.
- **Correct approach**: New reason assertions (`expect(result.reason).toBe('Cannot open database')`) make the intended path uniquely identifiable; each error-path test now re-establishes its own Database constructor mock with a regular function, and `beforeEach` re-pins the mocked `existsSync` default to kill the leak.
- **How to prevent**: When asserting an indirect signal (status/exit code), enumerate every path that produces it and add an assertion unique to the intended one; never rely on mock state (spy return values, implementations) surviving from a previous test.
