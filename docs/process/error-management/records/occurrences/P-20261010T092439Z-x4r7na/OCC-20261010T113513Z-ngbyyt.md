- **What happened**: r3 re-review found this pattern's own r2 fix over-declaring the gate — the same defect
  shape as the original bug, mirrored. Two prose claims about validation had been written from the
  validator's list of message strings and from a directly-called low-level template, not from the production
  call chain:
  (1) `validateV2OutputContract` can emit `Owner-labelled example <id> was rewritten`, but the restoration
  step in `ArtificerRunner.fetchAndParseOutput` rebuilds every entry whose `caseId` matches a pack case from
  the authoritative `BehaviorExamplePack` BEFORE validation runs. A model that keeps a pack caseId and edits
  its protected fields is silently reverted and passes; the rewritten message is unreachable for pack
  caseIds in production. The v9 prompt told the model the opposite, and this record's "missing or reworded"
  wording repeated it.
  (2) The acceptance report claimed the `v2-path-boundary` rejection had been reproduced "through the
  production entry point" by calling the case generator with an `ls`-derived tool list. That call bypassed
  `EvaluatorRunner.generateV2CasesFromArtificer`'s kind gate, so it demonstrated a branch production never
  takes. Re-running the real sequence (`parseArtificerArtifact` → `extractPositiveCases` →
  `generateV2CasesFromArtificer`) on the actual run artifacts showed the write branch producing the same
  rejection and the `ls` artifact skipping the whole template batch — and that the template's write target
  is copied from the Owner-labelled positive evidence, which in this pack is an `ls` observation.
- **Why it's wrong**: Each sentence asserts an authority it does not have. Over-declaring a gate makes
  compliance a guess in the other direction — the v9 obligation can be neither satisfied nor violated, so it
  is noise in the prompt; and a "reproduction" that executes a different code path than the pipeline is
  evidence for nothing, while it reads to the Owner as production proof.
- **Correct approach**: Describe a gate by its reachable outcomes, traced from the production entry point
  through every pre-validation normalisation step. Where a normalisation layer restores a field, state that
  the field is restored — not that editing it is rejected. Reproduce a gate claim by calling the same
  function the pipeline calls, with the persisted inputs of a real run.
- **How to prevent**: For every "the gate rejects X" or "reproduced through production" sentence, name the
  production call chain that reaches it and check that nothing upstream overwrites the input first and that
  the call is the pipeline's own entry point. Prompt obligation text stays pinned by the existing
  prompt-text assertion; the report's reproduction section now carries the actual call sequence.
- **Regression guard**: prompt-text assertions in
  `packages/principles-core/src/runtime-v2/internalization/__tests__/artificer-prompt-builder.test.ts`
  (v10 asserts the restoration sentence and asserts `was rewritten` is absent from the prompt). No mechanised
  guard over report prose.
