The same declaration-versus-fact disagreement, on the other compatibility knob. `release-metadata.yml`'s required dispatch input `data_schema_forward_readable_from` — the value the installed release-manager enforces at `packages/create-principles-disciple/src/update/release-manager.ts:440-447` (the decision itself is made in `packages/create-principles-disciple/src/update/data-compatibility.ts:41-64`) to refuse updates with `kind: 'no_update'` / reason `destructive_migration_requires_maintenance` — had been carried forward verbatim for **31 consecutive publications** (`2.1.0` since seq 7 / 2026-09-23), established by rebuilding the publication ledger from the 37 `targets/releases/*/metadata.json` objects on `origin/gh-pages`. Meanwhile the first destructive on-disk migration (`packages/principles-core/src/runtime/trajectory-schema.ts:156` `ALTER TABLE tool_calls DROP COLUMN gfi_before/gfi_after` plus `:164-166` forcing pending empathy rows to `abandoned/gfi_removal`, `TRAJECTORY_SCHEMA_VERSION` 1 -> 2) first shipped in product version **2.8.1**. So the published floor and the actual schema history were two declarations of one fact that disagreed, and no gate compares them: the value is free text on a `workflow_dispatch` input, the schedule event silently re-derives it from the previous channel pointer, and the only way to discover the divergence is to reconstruct the release ledger by hand — which is what had to happen for the 2.8.4 publication, where the floor was corrected to 2.8.1. Consequence of getting it wrong is user-facing and asymmetric: too low and old builds silently degrade against a migrated `state.db` instead of being held back; too high and current users are locked out of updates with a refusal that has no `nextAction` and whose Console copy points at a maintenance flow the repository does not have. As in ERR-139, the oldest declared value is the least exercised and therefore the one that silently rots, and as in ERR-139 the fix class is the same: a gate that reads BOTH the declaration and the produced fact (the migration marker's source commit, mapped to the first published product version that carried it) and refuses a dispatch whose value disagrees with the reconstructed fact, instead of trusting an inherited string.
