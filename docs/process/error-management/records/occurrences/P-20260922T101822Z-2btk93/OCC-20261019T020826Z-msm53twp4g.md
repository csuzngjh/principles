Release-watch authority axis. The Companion version watch decided whether to hand a running Console over to the installed release by comparing the installed plugin's `package.json` version — a component axis with no causal link to "which release is installed here". Field evidence from this machine: channel seq 15->16->17 all carried plugin 2.1.0, and seq 22->23 (product 2.3.7->2.3.8, new console/core code) all carried plugin 2.1.8, so for those releases the predicate could never become true; the marker also flips before the transaction journal reaches `staged` (the window PRI-1012 had to absorb with a bounded entry wait), and a failed transaction restores the old extension tree from backup (`installer.ts restoreBackup` -> journal `rolled_back`), so the same marker walks back too — its movement tracks deployment mechanics, never which release is installed. Consequence in production: after every such update the old process kept serving the old build until the Owner restarted it by hand, and `/api/health` reported a hybrid reading (disk = new productVersion, memory = old code). Escaped because the component axis is what the surrounding docs and the ticket wording called "the installed version", and no test asserted causality between that field and a release change; caught when the Owner reported the recurrence ("每次都出现很烦人") after two consecutive releases behaved this way. Same root shape as ERR-148: a predicate governing a capability was keyed on an orthogonal axis, and fixing the symptom (the PRI-1012 restart race) left the wrong axis in place. Guard shipped here: `src/lib/release-watch.ts` makes the decision on `~/.pd/active.json` release identity (releaseId + generation) and fails closed with a distinct reason per authority-failure class instead of falling back to the component marker; `tests/main/release-watch-wiring.test.ts` asserts the watch body never calls `readInstalledVersion` and was proven red against `origin/main`'s main.ts (negative control, ERR-148 rule 4); `tests/lib/release-watch.test.ts` pins the ERR-148 differential (retired predicate returns "no change" for the seq 22->23 pair, new judgement returns restart); `docs/specs/features/companion/release-watch.feature` makes the contract Owner-readable (10 scenarios). Residual gap for the mechanized side: nothing yet checks, repo-wide, that a restart/hand-over predicate is keyed on the release authority — left as the semantic verification obligation per ERR-148's enforcement note.
