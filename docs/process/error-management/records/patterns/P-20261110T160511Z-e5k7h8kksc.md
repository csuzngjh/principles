- **What happened**: In the PRI-1170 adaptive selection protocol (`packages/host-runtime/src/adaptive-selection.ts`), each outbound candidate carries a locally precomputed `digest` so the model can copy it verbatim instead of hashing. The candidate body is bounded to 600 characters before sending, but `digest` was computed as `sha256(principle.text)` — the **unbounded source** — while `text` on the wire was the truncated body. For any candidate longer than the bound, `digest !== sha256(sent text)`. The freeze-table comparison (`selection.digest !== entry.digest`) still passed, so the defect was invisible to the happy path; it surfaced only when a test recomputed the hash from the body found in the **actual request**: `outbound candidate c2 must carry a locally precomputed digest: expected 'dfc71736…' to be '97fca70e…'`.

- **Why it's wrong**: A digest that travels with a body is a claim about *that body*. Once any transform (truncation, whitespace collapse, redaction) sits between the hashed value and the transmitted value, every independent verifier — a test reading the request, a proxy, a reviewer, a future consumer — recomputes a different hash and must conclude the payload is corrupt. Comparing the reply only against the frozen table hides this because both sides are wrong in the same way.

- **Generalized failure mode**: Whenever a value is described as "the digest of the candidate/artifact/payload", the hash input silently becomes the pre-transform source while the transport carries the post-transform projection. The pair stays internally consistent (frozen value vs copied value), so tests that never recompute from the wire stay green, and only an external recomputation exposes it.

- **Correct approach**: Compute the digest from the exact bytes that are sent, after every bound/transform has been applied — bind it once (`const candidateText = boundText(...)`; `digest: hash(candidateText)`) and let both the payload and the verification read that same value. Verification should keep two independent computations (the frozen table value and a fresh hash of the frozen body) so a future change to either side fails loudly.

- **How to prevent**: For every "X + digest of X" payload, add the assertion *from the request/wire*, not from the source object: parse the emitted payload, then assert `digest === sha256(emitted body)` for **every** element, including ones long enough to be truncated. If the fixture's bodies all fit under the bound, the assertion is vacuous — include at least one element that is actually truncated.
