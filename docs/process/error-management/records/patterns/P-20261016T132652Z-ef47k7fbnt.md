- **What happened**: `npm run verify:merge 2>&1 | tail -30; echo "VERIFY_EXIT=$?"` reports the exit code of `tail`, not of the gate. A failing gate (lint errors) was read as passed because the pipeline's last command succeeded. This is the third+ occurrence of the same class in this agent's history on this repo (previously swallowed vitest/verify exit codes in PRI-917 and pd-prompt-capability sessions), each time producing a false "gate green" conclusion.
- **Reproduction**: PRI-995 session (2026-10-16): verify:merge runs 1–2 both FAILED on core lint, but the `$?` read after `| tail` printed 0 for run 1; the failure was only surfaced when the output was redirected to a log file with the exit code appended inside the same shell invocation.
- **Invariant**: The success signal of a pipeline is the exit status of the LAST command — never read `$?` after a pipe when the gate is not the last stage; capture `cmd > log 2>&1; echo EXIT=$?` with no pipe, or use `set -o pipefail`.
- **Fix/correctness**: All subsequent gate invocations in the session redirected to a log file and appended the exit code without a pipe; the true failures were then fixed (lint + changeset commit).
- **Guard**: Manual discipline; consider a shell profile alias/wrapper for gate commands that forces pipefail (no mechanized repo guard yet).
