**[ERR-141]** | URL 参数拼接 querySelector 属性选择器未转义，且把 `CSS.escape` 放进引号内的"修复"本身语义错误

- **What happened**: 深链实现把 URL 查询参数（`?activationId=` / `?taskId=`）未经转义地内插进 `document.querySelector('[data-testid="prefix-<param>"]')` 的属性选择器。参数含 `"` 等字符时 `querySelector` 抛 `SyntaxError`（未捕获，落在 useEffect 内可打断页面渲染）。评审建议的字面修复 `CSS.escape(<v>)` 放进**带引号**属性值里，同样是错的：`CSS.escape` 产出的是标识符转义（如 `\31 `），放进引号字符串会被 CSS 字符串转义规则二次解释（`\31` 是十六进制转义），广义上不再匹配原值。
- **Why it's wrong**: URL 参数是不可信输入（rc-1）；选择器是解释器上下文，内插 = 注入面（轻则 SyntaxError 崩溃，重则选择器语义被构造）。引号内/外的 CSS 转义规则不同，工具函数必须用在它设计的语法位置。
- **Correct approach**: 无引号属性选择器 + 对**完整组合值**做 `CSS.escape`：`` document.querySelector(`[data-testid=${CSS.escape(`prefix-${param}`)}]`) ``——`CSS.escape` 保证输出是语法合法的标识符，等值匹配由选择器属性比较完成。或遍历 `querySelectorAll` 后用 `getAttribute` 精确比较。
- **How to prevent**: 凡把外部输入拼进任何解释器上下文（CSS 选择器、正则、SQL、shell、XPath），先问"这个转义函数是为哪个语法位置设计的"；PR 自评审清单加一条：`querySelector(` 模板串里出现 `${` 即报警。
