**[ERR-142]** | 从既有机制抽取共享代码时静默丢弃其校验步骤，还用测试把弱化契约钉死

- **What happened**: 把 ApprovalsGroupedConsoleModel 的 artifactId→principleId 解析装配抽成共享 resolver 时，忠实保留了"直接命中 `sourcePrincipleId` 不经 ledger 校验就透传"的旧内联行为，却没意识到这与被复用的纯解析器（`resolveLedgerPrincipleId`：直接命中必须过 `hasPrinciple`）的文档化契约相矛盾；随后写了"列上有 id ⇒ 条目带 principleId"的测试，把弱化契约钉成了断言。CodeRabbit 评审以 Major 抓出：陈旧列值会作为合法深链目标输出，落地即 404 死链。
- **Why it's wrong**: "行为等价"被当成了最高目标，但被等价的参照物（grouped 内联代码）本身携带一个未声明的校验缺口；抽取动作把缺口放大成了跨消费者的共享契约。测试随后固化了错误状态——测试 Reality Gap（EP-09）与信任边界（EP-01）叠加。
- **Correct approach**: 抽取/移植机制时把**被抽取者的全部契约（含校验步骤与其文档哲学）**列成清单逐条对照；凡发现参照物自身可疑，先验证参照物的原始意图（本例：解析器模块头注释明确写着"never returns an unvalidated string"），拿不准的在 PR 里显式提出契约决策而不是默认沿袭。fixture 要让"可解析"用例走真实存在性（注册真实 ledger 条目），并为收紧后的契约写 pre-fix 必失败的负向对照。
- **How to prevent**: 抽取式重构的自评审问题固定为一条："新接口的契约是否严格强于（或等于）被抽取者的每一个调用点？列出每个调用点行为差异。"允许收紧，但收紧必须有波及清单（本例：cr8、governance-approve-activation、e2e 三处 fixture 同步补注册）。
