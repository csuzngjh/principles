Fixture seeders that reconstruct an installed node_modules layout by walking package.json dependencies with an ancestor walk must check the ROOT node_modules package slot (rootNm/<dep>) explicitly. The walk pattern 'candidate = dir/node_modules/dep; if (dir === rootNm) return null' terminates at rootNm without ever testing rootNm/<dep> — root-HOISTED deps (flat-installed by npm at node_modules/<dep>) are structurally unfindable, while NESTED ones (node_modules/pkg/node_modules/dep) resolve fine. The blind spot stays invisible while the tested import graph only pulls nested deps lazily; an upstream dependency upgrade that turns a root-hoisted dep into an EAGER import on the tested path (here: Pi 1.2 json-parse -> partial-json on the UserPromptSubmit injection path) crashes the spawned child with ERR_MODULE_NOT_FOUND and looks like a product regression. Fix: after the ancestor walk, test rootNm/<dep> directly; keep the walk for nested/workspace-junction resolution (realpath first). Real installs are unaffected — only the seeded layout diverges from what npm produces.
