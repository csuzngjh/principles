The v4.1.2 release finalize step called `clawhub package publish packages/openclaw-plugin`. That source directory's `dist/` is gitignored, so the uploaded file set could not satisfy the package's own manifest (`openclaw.extensions`/`openclaw.setupEntry` point at `./dist/bundle.js`). ClawHub rejected both attempts with "declares openclaw.extensions entry ./dist/bundle.js, but that file is missing from the package". Because the step is intentionally non-blocking (`continue-on-error: true`), the finalize job still reported success, and the step summary's manual fallback (`clawhub package publish .`) reproduced the same invalid input — a recovery instruction that could never work. The same command was also missing `--source-repo`/`--source-commit`, which the ClawHub CLI requires for `--family code-plugin`, so it would have failed again even after fixing the file set.

The npm tarball for the same version does contain `package/dist/bundle.js`; the marketplace artifact is required to be byte-identical to the npm publication (RELEASE_PROCESS "Marketplace artifact provenance"), never a working-tree rebuild. The upload input must therefore be fetched with `npm pack <name>@<version>`, its declared runtime entries asserted before the network round-trip, and a degraded run must state which channels updated and which did not while offering a recovery command against that same artifact.

Must check:
- A marketplace/secondary-channel publish consumes the immutable artifact the canonical channel published (`npm pack <name>@<version>`), never a source directory whose build output is gitignored or regenerated locally.
- Before upload, assert the artifact actually contains every runtime entry the package manifest declares.
- A non-blocking failure names the channels that DID succeed and the one that did not; it never reports a bare success.
- Its manual recovery command is executable against the same artifact and includes the flags that channel's CLI requires (ClawHub code plugins require `--family code-plugin --source-repo --source-commit`).
