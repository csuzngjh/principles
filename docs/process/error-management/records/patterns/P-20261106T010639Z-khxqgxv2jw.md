PRI-1110 (PR #2370) added `packages/openclaw-plugin/src/core/adaptive-config-identity.ts` — a plugin I/O adapter that reads the executing plugin manifest from disk — without classifying it in the PRI-212 anti-growth baseline (`KNOWN_PLUGIN_CORE_FILES`, which lives in `packages/principles-core/src/runtime-v2/__tests__/architecture-regression.test.ts`). The guard worked exactly as designed and failed — but on the immediately following Version Packages PR #2372, after the unclassified file had already landed on main with green CI.

The escape is structural: the guard lives in principles-core but scans `packages/openclaw-plugin/src/core/`. The CI Impact Gate resolver (`scripts/ci/impact.mjs` `SCOPE_BY_DIR`) maps changed-file directories to semantic scopes, and `Test principles-core` runs only when the `core` scope is affected — so a diff touching only openclaw-plugin (+ docs) skips the core suite. On PR #2370 the job was `skipping`; on the resulting main push it was skipped again. Main's green was honest for every job that ran — the guard simply never executed. It first ran when the changesets version bump touched every `package.json`, which pulled the CI Impact Gate into the core suite, and the guard flagged the file it should have flagged one PR earlier.

This is a sibling of ERR-131 (path-filtered CI skips blast-radius jobs on dependency bumps) but a distinct class: no bump happened, and ERR-131 diligence cannot help — a plugin-core diff carries no signal that a foreign package's guard constrains the directory. The blind spot is in the guard's own wiring: its CI trigger set covers the package it LIVES in, not the directory it GUARDS. Green CI precisely on the diff class the guard exists to police makes the guard's coverage illusory until an unrelated trigger rescues it.

Must check:

- When adding, removing, or renaming any file under a directory that another package's guard/test scans (today: `packages/openclaw-plugin/src/core/` is scanned by principles-core's architecture-regression PRI-212 guard), run the owning guard suite in the same PR (`npx vitest run src/runtime-v2/__tests__/architecture-regression.test.ts` under `packages/principles-core`). A path-skipped CI job is not green evidence for a guard that lives outside your diff's packages.
- When creating or moving such a guard, its CI trigger set must include the guarded directory (or the guarded package's own suite must exercise it): trigger scope must be symmetric with scan scope.
- Clear this failure class only through the guard's own rubric — classify the file (pure logic → principles-core; plugin I/O adapter → baseline entry with classification comment) and update the self-consistency count in the same change. Never widen the baseline or weaken the assertion to obtain green.

Fix for this occurrence: classify `adaptive-config-identity.ts` as a plugin I/O adapter (OpenClaw-only manifest read, PRI-1110) with baseline size 93 → 94, plus this record.
