**What happened**: `resolveWindow` derived candidate journal files from the UTC day keys intersecting `[start,end]`, and `selectDateFiles` matched exact filename dates. `EventLog.ensureEventsFile()` names each file after the date at FLUSH time, while each record's `ts`/`date` is fixed at creation; a record created at `2026-11-04T23:59:40Z` is therefore appended to `events_2026-11-05.jsonl` when the buffer (30 s / 20 records) flushes after midnight. A window ending `2026-11-04T23:59:59.999Z` read only the 11-04 file, found the open record without its terminal, and reported `open_only` with `coverage.status=complete` and `countsAreLowerBounds=false` even though the paired closed record existed in the next-day file.

**Why it's wrong**: The coverage contract claims completeness over a window, but the candidate set was derived from an assumption the producer does not satisfy across a midnight flush (`file date == record date`). Reading one of the two files that can carry a window record and then asserting `complete` converts an unread file into a definite false negative — the answer states "no terminal exists" when one does. The same assumption also makes `filesRead`/`filesOmitted` budgets under-count the real candidate set.

**Correct approach**: Treat the UTC day AFTER the window end as one bounded extra candidate file — the window's day keys are contiguous, so only the endpoint's next day falls outside the derived set. Include it in the file-count and byte budgets, and keep record inclusion decided by the envelope `ts`, never by the filename. When the file cap or byte budget omits a candidate, report `partial` with the omitted file, `countBasis=lower_bound` and a `limitCode`; never `complete`.

**Must check**: Before bounding a date-partitioned log by filename date, read the producer's naming/flush behavior and prove the partition invariant holds under buffering and midnight rollover. Every additional candidate file must count against the same caps as the primary ones, and semantic inclusion must stay on the record's own timestamp so spillover candidates cannot admit out-of-window events.

**Regression guard**: `packages/host-runtime/tests/adaptive-journal-reconciliation.test.ts` — cross-midnight describe: open on 11-04 plus terminal in the 11-05 file pair into `paired_open_and_terminal` with `complete` and `lowerBounds=false`; an out-of-window `ts` inside the next-day file stays excluded; `maxDateFilesPerDir:1` yields `partial`, one `filesOmitted`, a `coverage_file_limit_reached` limit code and lower-bound counts; the default 7-day window reads all 9 candidate files.
