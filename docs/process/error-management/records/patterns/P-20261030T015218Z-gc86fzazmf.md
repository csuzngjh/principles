- **What happened**: `dedupeProductizationCandidates` published `skeletonDuplicatePairs: structural.filter(([a, b]) => !exactKeys.has(...))` — literally the same expression as `structuralDuplicatePairs` — so the productization path advertised a third dedupe tier it never computed. No test asserted the field's value, and the function's only caller is a test, so the copy passed review until the dedupe contract was read line by line.
- **Why it's wrong**: An advertised output dimension is a capability claim. Reporting three tiers when the third is a copy of the second tells every consumer — and any future frozen report derived from this projection — that a distinct skeleton comparison ran. Here v2 candidates vary only in expression against a fixed decision body, so the decision projection already is the skeleton and the third tier could never differ.
- **Generalized failure mode**: A new output field/tier is filled with a copy of a sibling so the contract's shape looks complete, advertising a capability that is never computed and that no assertion distinguishes.
- **Correct approach**: Advertise only dimensions derived from distinct criteria. When the domain has no additional axis, remove the field and state why in the contract docstring instead of filling it with a copy.
- **How to prevent**: For every new output field, add an assertion a sibling cannot satisfy (a differ-from-sibling case, or explicit absence), and ask "what criterion separates this tier from the previous one?" before publishing it.
- **Regression guard**: `scripts/__tests__/principle-learning-lab-examiner-productization-entry.test.ts` (`expect(result).not.toHaveProperty('skeletonDuplicatePairs')`).
