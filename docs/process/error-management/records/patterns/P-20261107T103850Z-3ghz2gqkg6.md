Pattern root cause: a duration computed as a performance.now() float (budget remainder = budgetMs - elapsed) was passed through SignalClassifierCallOptions.timeoutMs into AbortSignal.timeout(), whose Node contract requires an integer — it throws ERR_OUT_OF_RANGE synchronously, before any network I/O. Under the production defaults (aggregate budget 60s == classification timeout 60s) the remainder is virtually always fractional, so EVERY worker-cycle Stage-2 classification failed instantly (~1ms), each failure consumed a durable attempt via recordPendingCorrectionReview(null) → pending_llm_error, and five cycles abandoned the candidate with reason llm_error without a single real model call — a silent candidate-loss loop that looks exactly like a provider outage.

Two reusable lessons:
1. Durations crossing into runtime APIs with integer/range contracts must be clamped at the producer (Math.floor of the remainder); the API contract is a trust boundary (rc-1/rc-3 family), not a formality.
2. 100% of the pre-existing tests missed this because every fake classifier ignored options.timeoutMs and every test either passed an explicit integer budget or bypassed the cycle. Only a real-LLM/exact-contract red-green (spy classifier asserting Number.isInteger(timeoutMs) under DEFAULT budgets, plus a real-provider default-budget reproduction) exposed it. A second masking layer: the experiment harness initially passed an oversized explicit aggregate budget, which kept Math.min() on the integer constant and hid the defect until a fault-injection run used production defaults.
