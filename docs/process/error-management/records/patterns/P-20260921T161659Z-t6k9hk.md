**[ERR-145]** | AI agent session fabricated an inline Git commit identity (`git -c user.email=pd@users.noreply.github.com`), silently overriding the correct configured identity

- **What happened**: On 2026-09-21 an agent CLI session (Qoder, working `d--Code-principles`) ran four commits shaped like `git -c user.name="PD" -c user.email="pd@users.noreply.github.com" commit ...` while reconciling dependabot PRs (#1806, #1810) and release-lock fixes (PR #1807). The global `~/.gitconfig` had the correct identity (`PD <csuzngjh@hotmail.com>`); the agent bypassed it with a per-invocation `-c` override of a fabricated email that reverse-engineers the display name. GitHub attributed all four commits to github.com/pd (a stranger's account) instead of the repository owner csuzngjh; three of them are permanently on `main`.
- **Why it's wrong**: Commit identity is a governance fact (attribution, audit trail, contributor history). The email `pd@users.noreply.github.com` is a plausible-looking but unverified guess — GitHub's noreply addresses are `<id>+<login>@users.noreply.github.com`, and `pd` maps to a foreign account. An agent must never invent identity data; when it wants a noreply-style email it must use the owner's verified one, which the effective config already provides. The failure was silent: every existing gate (pre-commit worktree-guard, repo-hygiene, verify:merge, gitleaks, CI, review) is identity-blind, so fabricated attribution sailed into `main`.
- **Correct approach**: Use the effective configured identity verbatim (`git var GIT_AUTHOR_IDENT` shows what a commit will be attributed to). If a different identity is genuinely required, it must come from the Owner's instruction, never inferred from a display name.
- **How to prevent**: Validate the identity the commit will actually carry, not the one stored in config — a pre-commit guard reading `git var GIT_AUTHOR_IDENT` / `GIT_COMMITTER_IDENT` (which reflect `-c` and env overrides) and failing closed on known-foreign emails (implemented as `scripts/dev/check-commit-identity.mjs` wired into lefthook `pre-commit: commit-identity` in this PR). Config repair alone cannot prevent recurrence because the wrong email was never persisted anywhere.
