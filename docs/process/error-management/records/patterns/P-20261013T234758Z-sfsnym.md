**Invariant**: test doubles must replicate the production object's calling convention, not just the happy path — fakes that pass richer arguments than production (e.g. an EventEmitter-style signal target whose `emit(sig)` calls handlers with the signal name, while real `process` invokes signal listeners with ZERO arguments) hide production code paths that silently receive `undefined` and fall back to different behavior.

**Escaped**: no — caught by independent code review before merge (PR #2018 F-01, P2). **Caught by**: adversarial review comparing the fake's call shape against the real API contract. **Guard**: (1) when writing a fake/stub, derive its call shape from the production API contract (verify with a one-line probe against the real object — e.g. `process.on('SIGINT', (...args) => log(args.length))` → `0`), not from what the code under test happens to accept; (2) for critical contracts, add one in-process probe that runs the real object (not a fake) through the same path.

**Occurrence** (2026-10-14, PRI-961 PR #2018 review F-01): the scheduler registered one shared `onSignal(signal)` handler for SIGINT/SIGTERM. Real `process` calls signal listeners with no arguments, so `signal` was `undefined` and `activeChild.kill(undefined)` forwarded Node's default SIGTERM instead of the intended SIGINT. The unit-test fake `emit(sig)` passed the signal name as an argument, so the test suite stayed green while production forwarded the wrong signal. Fix: per-signal closures forwarding explicit names; fake signal target now invokes handlers with no arguments (production-faithful), plus a probe driving the REAL `process` object end-to-end (`killArg === "SIGINT"` verified).
