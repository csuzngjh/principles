- **What happened**: PR #1781 (merged 2026-09-20) added a `Verify the packed installer tarball carries the product identity` step to `publish-npm.yml` that consumes the pack report with `JSON.parse(execFileSync('npm', ['pack', '--json'], { cwd }).stdout)`. `npm pack` runs the package lifecycle (`prepack` → `npm run build && npm run bundle`), and npm splices a lifecycle script's stdout into its own stdout — so `bundle-plugin.mjs`'s progress banner (`console.log('📦 Bundling plugin + pd-cli for npm publish...')`) landed in front of the pack report. The next `Publish to npm` run on main failed at exactly that step with `SyntaxError: Unexpected token '�', "📦 Bundlin"... is not valid JSON` (run 35509453375, head 8821d1b5, job `Publish create-principles-disciple`), and every step after it — the channel guard, `npm publish`, tag, GitHub Release — was skipped. The step had never executed before, because the release gate upstream of it had been red on main since 09-19; fixing the gate revealed this second, different blocker, which read as "the train is still broken" rather than "a different step is broken".
- **Why it's wrong**: `--json` is a machine contract over stdout, and the consumer's only option is to parse the entire stream. A producer that is not party to that contract — a build script's progress logging — silently invalidated it, and the failure surfaced as a JSON syntax error whose most prominent token was an emoji: the least useful possible description of the real cause. The blast radius is the whole publish train: the root cause was one line of cosmetic logging.
- **Correct approach**: Progress and diagnostic output belong on stderr; stdout stays reserved for data. `bundle-plugin.mjs` now routes every progress line through a `log()` helper that writes to `console.error` (its warnings already did), and documents the contract at the definition site so the next edit does not put a `console.log` back.
- **How to prevent**: Before writing a CI step that consumes a tool's `--json` output, enumerate the whole producer chain and check each link: does the tool run a lifecycle script whose output is spliced into the same stream, and does every script in that chain keep stdout free of human output? Verify by running the exact consumption locally (`JSON.parse(stdout)`) against a package that has a `prepack` hook, not against a stripped-down one. And treat a step that has never executed in CI — because an upstream gate was red — as unverified code: its author has no evidence, however green the PR looked.
- **Regression guard**: none mechanized (the workflow step is itself the consumer); the verified producer contract is `node scripts/bundle-plugin.mjs --output-root <temp>` emitting 0 bytes on stdout while its progress goes to stderr.
