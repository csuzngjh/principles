# Forecast/Replica Diverges From Production Policy And Is Presented As Fact

## Invariant

任何**预测 / 预报 / 预演**路径（forecast、projection、preview、dry-run、
simulation、what-if）必须复用**生产实际执行的那条策略/代码路径**。
当生产策略依赖某个仅在运行时才有的输入（session turn ordinal、随机种子、
游标、当前时间、host 身份）而预测方拿不到时：

- **不得**用「缺省值」静默降级为另一条策略，再把结果当作生产事实呈现；
- 必须显式区分三态：**完全一致** / **降级且已知偏差** / **无法判定**；
- 任何"保守"偏差（例如始终选更悲观的结果）**不是**安全默认——它是系统性
  偏置，会以事实口吻被下游（尤其是 Owner 面向文案）放大成错误行动指引。

## Symptom

预测结果"看起来合理"、测试全绿、文档自洽，但与生产行为相反。
典型表现：预测说某对象"不可达 / 永不生效"，生产实际在第 N 轮就可达。

## Root cause class

复制了生产的**输入**却漏掉了生产的**策略参数**，而二者的差别只在
参数缺省时才显现；缺省分支恰好是结构上最悲观的那一条。

## How to prevent

1. 定位生产选择器时，列出它的**全部**策略参数，逐一确认预测方是否持有；
   缺一个就是一条独立的偏差通道。
2. 让预测结果**显式携带它实际跑的那条策略标识**，而不是让每个消费方
   各自假设（"按 FIFO" 这类硬编码文案是偏差的传播载体）。
3. 当判定依赖"生产是否轮转/是否降级"这类**策略属性**而非某一轮的具体
   取值时，在预测层按**生产策略**计算，而不是按自己手里的那个缺省轮次——
   否则预测方越"诚实"地降级，越会得出错误结论。
4. 复制粘贴生产代码时，把"这里与生产一致"的注释当作**待证明的断言**，
   用差分测试证明，不接受注释自证。

## Regression guard

- 差分测试：对同一 fixture 分别跑生产路径与预测路径，断言策略标识一致。
- **负向对照**：把生产侧改动回退，断言新测试确实失败（见 EP-09）。
- 预测方在拿不到生产参数时，必须有测试断言其**显式降级标识**，
  而不是默默按缺省策略出结果。

## Second-order: a fix can reproduce the defect it was meant to remove

The first implementation of this fix returned `selectionPolicy` and branched
on it. That was still wrong: the console holds no session round key, so
`selectionPolicy` is `legacy_fifo_prefix_v1` **even on a route where
production rotates**. Rendering that value next to the words "the current
production selection policy" reintroduced the original falsehood in a new
sentence.

Generalized:

- A fix that adds a "which policy am I?" field is not automatically a fix.
  Ask **whose** policy the field describes. "The replica's own policy" and
  "the production policy" are different facts, and the caller usually needs
  the second one.
- When a replica cannot obtain the production input, deriving the production
  attribute from the replica's degraded state silently propagates the
  degradation. Report the production property directly
  (`productionRotates`) rather than inferring it.
- Audit the *sibling* branches too. The same string template rendered
  `fair_rotation_v1` hardcoded two lines above the buggy one — the
  inconsistency was visible inside a single function.

## Third-order: a promise must be conditioned on the subject, not the mechanism

The pre-approval badge promised "it will come around on later turns" purely
because the route rotates. But an entry whose own serialized content exceeds
the budget is skipped in **every** round: rotation is a position mechanism and
cannot fix a size problem. The claim was false for oversized candidates.

- Before promising that mechanism M will deliver subject S, verify M
  operates on the property of S that M actually controls. Here M (rotation)
  controls *order*, not *size*.
- The knowledge needed to check the promise (the serialized, escaped size)
  often lives only on the server. If the UI cannot compute the condition, the
  condition must be computed server-side and shipped — a UI-only "fix" would
  have been a guess.
- An unknown must never resolve to a promise. Absent size data degrades to
  "do not promise", not to the optimistic branch.
