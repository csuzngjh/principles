**[ERR-149]** | 生产构建把测试代码编译进发布产物，且没有任何闸门校验产物内容

- **What happened**: 三个包（principles-core、pd-cli、pd-console）的 tsconfig 以 `include: ["src/**/*"]` 编译，测试文件与源码同放 `src/`（core 384 个 `*.test.ts`）被全部编译进 dist；构建从不 clean，还积累了源码已删除的 stale 孤儿树。测试产物经 `files:["dist"]` 进入 npm 包（core tarball 57.1% 字节是测试），再经安装器整目录复制进入用户机器（live ~/.pd/runtime 实测 1576 个测试文件）。该状态存活数月，直到一次人工发布卫生审计才被发现。
- **Why it's wrong**: 违反"发布产物只含生产内容"的边界。根因不是知识缺失，而是**产物内容从未被任何机器闸门断言**——发现完全依赖偶发人工审计；dist 是生成物，其正确性被默认信任而从未被验证。
- **Generalized failure mode**: When 构建系统的输入范围（tsconfig include、打包 glob、安装器复制清单）按目录而非按"生产语义"划定，且发布链路没有任何产物内容断言时，助手必须假定非生产内容（测试、fixture、快照、stale 输出）会混入发布物并在构建/打包边界加 fail-loud 断言，否则污染会静默流向 npm 与用户机器，且随每次发布持续放大。
- **Correct approach**: 生产构建用显式过滤配置（tsconfig.build.json 排除 `*.test.*`/`__tests__`/`__fixtures__`/`*.spec.*`），构建前 clean（产物成为 src 的纯函数），构建后内容断言（check-dist-hygiene：命中测试产物即列出清单并退出非零）；测试类型检查改由显式 `typecheck`（tsc --noEmit）承载并接入合并门，门强度不降。
- **How to prevent**: 触碰构建脚本、打包清单、tsconfig 或安装器 bundle 逻辑的 PR，30 秒检查：产物里是否会有非生产文件？构建后有没有跑内容断言？（error:context 路由本卡即提示。）
- **Regression guard**: `scripts/build/check-dist-hygiene.mjs`（每次生产构建内联断言，PR #1841 起）；RAH-3 将补安装器 payload 零测试断言 + verify:merge 全仓 dist/payload 扫描作为第二道闸。生产夹具模块（如 golden-dogfood-fixtures.ts、split-pipeline-fixtures.ts，被生产 barrel import）不在断言模式内，勿误伤。
- **Related ERRs**: None（EP-06 管的是"改生成物要改源头"，本卡管"产物内容边界从未被断言"，互补不重叠）
