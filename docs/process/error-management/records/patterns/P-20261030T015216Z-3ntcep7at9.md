- **What happened**: CEB-001 cycle-2 `probe-authorization.json` recorded `issuedAt: 2026-10-30T03:25:00Z` — the +08:00 local wall-clock reading relabeled with `Z` — which lands after the record's own `validUntil`, so the authorization read as issued in the future. The same record's blockage text advertised a `03:30Z-09:30Z` window that does not overlap the enforced `19:30Z-01:30Z` (local 03:30-09:30) window.
- **Why it's wrong**: The `Z` suffix is a claim about the instant, not a formatting choice. A record whose stated issuance postdates its own expiry contradicts the authority it documents, and an advertised window that misses the enforced one makes the authorization unverifiable from its own text — exactly the provenance the record exists to carry.
- **Generalized failure mode**: An evidence record's UTC timestamp is written from the local wall clock and merely labeled `Z`, so the recorded instant is offset by the zone and can contradict the record's own validity window.
- **Correct approach**: Derive UTC fields from the actual UTC instant (local time minus the offset) and quote enforced windows in the basis the gate enforces, naming the local equivalent separately.
- **How to prevent**: When writing any evidence timestamp, compute the UTC instant instead of relabeling the wall clock; assert `issuedAt < validFrom < validUntil` and that the advertised window overlaps the enforced one in the test that pins the record.
- **Regression guard**: `scripts/__tests__/principle-learning-lab-probe-authorization.test.ts` (pins `issuedAt < validFrom`).
