**Failure mode**：安装器把"能力是否执行"的 gate 键在**另一个正交关注点的模式轴**上，且没有独立证据要求两者相关。PRI-898 实例：`installGlobalPdShim()`（向 PATH 托管的 npm global bin 写 `pd` 转发垫片）被 `isNpmDependencyResolutionEnabled()`（= 组件依赖如何解析：npm-distributed vs self-contained）gate 住。依赖解析模式与"往哪个目录写转发脚本"毫无因果耦合，但 gate 让**推荐渠道（self-contained 发布资产）的每一次安装都静默失去全局 `pd` 命令**——宿主智能体报 command-not-found，仅剩 verifyPdCliShim 事后一条 `verified_local_only` stderr 警告。测试套件（payload-form-gate）还把这一错配**钉成了期望行为**（断言 self-contained 模式必须跳过 shim），使 gate 漂移在 PRI-697 修"消息/模式错配"时就已埋下：同一函数先后两次把错误的条件轴当判据（先 legacy env、后 payload mode），消息与 skip 各修各的，轴本身没人质疑。

**Prevention**：
1. 添加/审查任何条件 gate 时，先问：被 gate 的能力**实际依赖**哪个事实？判据必须与该事实有因果证据（读该 gate 谓词的定义，不许凭名字）；"这个函数和历史代码放在一起/共享过 env" 不是证据。
2. 修 gate 相关 Bug（消息错、skip 错）时，必须同时重新论证**判据轴本身**是否选对，不得只换消息或换键名。
3. 渠道矩阵外化：任何"推荐渠道 vs 其他渠道"行为差异要么有文档化不变量（如 PATH 契约文档明言安装器唯一拥有全局 shim），要么有测试说明为何允许差异；gate 使行为偏离既有契约文档即为 bug 信号。
4. 回归测试须含**反向对照**：在修复前代码上跑新断言必须红（PRI-898 已按此执行：回退 installer.ts 恰好 2 个新用例红）。

**Enforcement**：语义验证义务（reviewer 对 gate 判据轴逐条质询）；`tests/payload-form-gate.test.ts` + `tests/global-shim-lifecycle.test.ts` 的 gate 矩阵用例把"shim 写入不再键于 payload mode、依赖解析仍键于 mode"钉成双向契约。
