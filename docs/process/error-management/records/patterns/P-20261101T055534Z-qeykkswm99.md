**What happened**: `lefthook`'s npm dependency `postinstall` runs `lefthook install -f` in whichever worktree is installing dependencies. Lefthook writes that command into `core.hooksPath`, which resolves to the PRIMARY checkout's `.git/hooks` — a directory shared by every worktree of the repository. The generated `pre-commit` / `pre-push` therefore embedded the installing worktree's absolute executable path (`D:/Code/_worktrees/principles/<task>/node_modules/lefthook-windows-x64/bin/lefthook.exe`, twice per file). Every worktree's commits and pushes executed the last installer's binary; deleting that worktree would break hooks everywhere.

**Why it's wrong**: The hooks entry is shared, durable state, but its content was derived from one checkout's filesystem layout. Whichever worktree installed last silently became the authority for all of them — several write pipelines unaware of each other, with no gate noticing a foreign absolute path inside a file that defines everyone's commit behaviour. The generated hook also fell back to PATH / go / bundle / yarn / pnpm and, finding nothing, printed "Can't find lefthook in PATH" and exited 0 — a silent skip of every hook rather than an error.

**Correct approach**: Keep `core.hooksPath` pointing at the shared directory (git-lfs owns `post-checkout` / `post-commit` / `post-merge` there), but install a deterministic, path-independent dispatcher from a tracked template (`scripts/dev/git-hooks/{pre-commit,pre-push}`). The dispatcher resolves the current worktree (`git rev-parse --show-toplevel`), then runs that worktree's own lefthook binary and `lefthook.yml` through `scripts/dev/run-lefthook-hook.mjs`. The root `postinstall` and the worktree bootstrap re-establish the dispatcher after every install, because the dependency postinstall still rewrites the shared entry. A worktree lacking local tooling fails loud with the installation command; it never borrows another worktree's binary.

**Must check**: Before letting any install/upgrade step write to a location shared by multiple checkouts (git common dir, `core.hooksPath`, global config), verify the artifact's content is environment-independent — no absolute paths, no per-checkout names — and re-establish it after the third-party step. A runtime entry point shared by several environments must resolve its dependencies from the CALLING environment and fail loudly when they are missing; a fallback that prints a message and exits 0 is a silent skip, not a degradation.

**Regression guard**: `scripts/__tests__/git-hooks-dispatcher.test.ts` — installed bytes contain no `_worktrees` / `node_modules` path; a second worktree's install leaves the shared entry byte-identical; each worktree runs its own binary and config; missing local deps fail with the bootstrap command; `LEFTHOOK_BIN` takes precedence; `LEFTHOOK=0` is an intentional skip. `scripts/setup-worktree.mjs` Step 4b also reinstalls in `--strict` mode.
