**What happened**: Exact-duplicate identity was certified by less than the whole record, in two ways. (1) It was computed from the display projection (`projectionKey` over `buildProjection`), which collapses evidence to the boolean `evidenceReferencePresent` and omits `targetBodySha256`: two legitimate closed records for the same invocation, same receipt state and target, but `evidence.reference` `capture-A` vs `capture-B`, produced one key and were reported as `terminal_only` with `duplicatesExact=1`. (2) After the projection fix, the canonical data text was compared, but once `canonicalStringify` reported `truncated` the key became `${ts}|${prefix}`. A truncated prefix cannot certify equality: two records with the same `ts` and the same first 262 144 canonical characters but different later `evidence.reference` values were again merged into `terminal_only` with `duplicatesExact=1`; conversely, genuinely identical oversized data with different envelope `ts` values were split into a `conflicted` pair.

**Why it's wrong**: Duplicate identity is an equality assertion, and it was being made over data that is deliberately lossy (the display projection) or deliberately incomplete (the marked prefix). In both cases different observations were merged, the conflict signal disappeared, and `duplicatesExact` over-reported. When the same defect is patched by folding envelope `ts` into a truncated key, the opposite error appears: identical data reported as conflicting because the envelope differs. The report then states a single terminal state — or a conflict — that the records do not support.

**Correct approach**: Certify exact duplication only on the normalized FULL record `data`, using the existing `canonicalStringify` for the common case and a full (never truncated) canonicalization for data beyond its prefix limit; object-key order differences stay equal, array order and every field value (evidence reference, target digest, admission identity) participate. If the full canonicalization exceeds the comparison budget, never assert equality: treat the record as distinct and report `coverage.identityComparisonLimited=true` plus a `q5` note. Keep the display whitelist untouched — only comparison uses the canonical text; reports still expose the projection. Different identities keep both variants, classify `conflicted` under the existing variant cap and omission counts, and no "favourable" variant is chosen as the winner.

**Must check**: An identity predicate must be defined over the complete canonical source data, not a presentation projection and not a truncated prefix. Prove every field a projection drops is irrelevant to identity, or include it. Never add envelope fields (e.g. `ts`) to repair a comparison that is missing content. Test both directions: equal view with different data must not dedupe (including beyond the serializer's prefix limit), and equal data with different key order or envelope must dedupe.

**Regression guard**: `packages/host-runtime/tests/adaptive-journal-reconciliation.test.ts` — duplicate identity describe: different `evidence.reference` → `conflicted`; difference only beyond 262 144 canonical characters → `conflicted` with `duplicates.terminal=0`; identical oversized data → `terminal_only` with `duplicates.terminal=1`; key-order-only difference → duplicate; content beyond the identity comparison budget → `conflicted` with `coverage.identityComparisonLimited=true`.
