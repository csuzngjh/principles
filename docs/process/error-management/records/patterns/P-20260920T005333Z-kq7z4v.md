**Failure mode**：开发便利工具链把开发构建/旧捆绑包写进正式安装面。三个已实证机制（2026-09-20 只读复核 + 本机事务日志）：

1. `scripts/install.mjs` 与 `sync-plugin.mjs` 的清理步骤在 EPERM（文件被运行中进程持锁）后"回退原位覆盖"——不删除直接 `cpSync` 叠加，留下半新半旧混合树；
2. `sync-plugin.mjs` 的 `injectLocalWorkspacePackages` 用 `realpathSync` 解析插件内 junction（本机实测 3 个：`core`、`node_modules/@principles/core`、`node_modules/@principles/host-runtime`，全部指向 `~/.pd/runtime/{core,host-runtime}`）后 `rmSync`+`copyDir`——**写穿链接、改写真实目标**；
3. npm 安装器是重装语义：每次运行都以捆绑清单的 productVersion 盖写 `active.json`（本机 2.1.0 于 2026-09-19/20 被三连盖回 1.74.1，gen21/22/23），与签名更新链互不感知。

**Root cause class**：写边界没有被强制——"写到哪个目录"由路径拼接决定而非强制边界；降级路径（EPERM 兜底）比正常路径更宽松；同一文件树存在两条互不感知的写入管线（npm 安装器 vs 签名更新链）。

**Prevention rule**：

1. 只有官方安装器（`npx create-principles-disciple`）与签名更新链可写 `~/.pd` / `~/.openclaw` 正式安装面；开发验证一律 worktree 源码运行，绝不安装进真实 home。
2. 安装/替换管线清理失败（EPERM）必须中止——禁止"原位覆盖"兜底；涉及 junction 的操作先判定真实目标归属，跨边界写穿禁止。
3. 写边界守卫必须位于第一个副作用之前，且无参数可绕过（PRI-868 弃用守卫为本模式首个机械化守卫，负向测试=临时 HOME 哨兵零写入 + 全参数组合拒绝）。
4. 刷新环境前先核验 `active.json` / 签名频道版本真值；不得以 npm latest 作为"最新版本"依据（跨编号体系）。
