A PR that changes any file under `plugins/principles-disciple/` must also strictly increment `.codex-plugin/plugin.json`'s `version`. Codex caches plugin payloads by that version, so shipping a changed `SKILL.md` / script without a bump makes the update undiscoverable for already-installed hosts. `scripts/release/sync-codex-runtime-pins.mjs --check-base` enforces this: it diffs `<PR base>` against the checked-out tree restricted to the plugin directory, then `checkMetadata(before.version, after.version, true)` requires a strict increase. PR #2640 changed four plugin files (`skills/pd-pain-signal/SKILL.md`, `scripts/pd-review.cjs`, `pd-setup.cjs`, `pd-status.cjs`) but left version at `0.3.35`, so the `Codex plugin delivery contract` job failed with "Codex plugin payload changed without increasing plugin.json version". npm publication alone is not plugin delivery: the runtime pin is materialized inside the Version Packages PR and verified against the registry after the train.

Must check:
- Any diff under `plugins/principles-disciple/` (including skill docs and `.cjs` helper scripts, not only `src/`) is accompanied by a strict increase of `.codex-plugin/plugin.json` `version`.
- Run `node scripts/release/sync-codex-runtime-pins.mjs --check-base <base-sha>` locally before pushing; success prints `{"ok":true,"payloadChanged":true}`.
- A normal PR must not hand-edit `runtime-version.json` (the pin); the Version Packages PR owns it.
- When a Version Packages PR is open it also bumps `plugin.json`; keep that PR open until last, otherwise every later changeset spawns another release PR.
