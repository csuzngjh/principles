`scripts/check-repo-hygiene.js` decided workspace cleanliness from `git ls-files`
(mode `all`) and `git diff --cached` (mode `staged`). Both enumerate tracked /
index paths only, so anything `.gitignore` covers is structurally invisible to
the gate — and to `git status`.

Observed: four PRI-923 publish run logs (8 MB) plus a retired-trainer state dump
accumulated at the repository root over 40 days and passed every merge gate.
The same blind spot already caused the incident recorded in `.gitignore`
(2026-09-04): `git stash -u` swept ignored root scratch into `refs/stash`, and
the pre-push gitleaks scan, which walks `git log --all`, failed on the secrets
inside it — blocking every push in the repository.

**Must check**: when a guard's job is *workspace state*, its enumeration source
must be the working tree (`readdirSync` + tracked-set difference), not git's
index. "Ignored by git" means "will not be committed", never "is not present".

**Recurrence**: None (first recording)
