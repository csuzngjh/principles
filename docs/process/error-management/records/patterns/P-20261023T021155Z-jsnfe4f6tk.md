**[ERR-166]** | A repo-workspace build artifact (dist/) was executed as if current — a stale pre-fix console dist served broken output to the Owner

- **What happened**: An agent session launched the console from a repo checkout (`cd packages/pd-console && node dist/server.js`) following a pilot runbook and trusted the `dist/` already on disk. That dist was a pre-fix build that had been copied into the primary checkout on 2026-10-16 while local `main` was two days behind `origin/main` (the READABILITY-002 separator fix landed 2026-10-15). It survived 7 days untouched — `dist/` is gitignored so git never invalidates it, the root `build` chain excluded pd-console (only `verify:merge` built it, in clean CI envs), and the install/update chain never writes to repo workspaces. The Owner then saw the fixed bug "reappear" live at 127.0.0.1:3111.
- **Why it's wrong**: "File exists" was treated as "artifact is current". P1 (Evidence Over Assumption) was applied to source code but not to build artifacts. This is the mirror image of the 2026-09-03 incident (AGENTS.md §1.1: installed `~/.pd/runtime/console/dist/server.js` overwritten out-of-band) — same identical-path-confusion class, two same-named entry points (`dist/server.js` in the installed runtime vs the repo checkout) with no freshness signal to tell them apart. Second incident of the family within ~90 days.
- **Correct approach**: Any serve/execute from a repo build artifact must prove freshness — rebuild immediately before launch, or use the canonical installed runtime path. The same-day contrast is the proof: a sibling session served an isolated UI the same morning from a worktree whose dist had just been rebuilt (clean), while the failing session reused a 7-day-old primary-checkout dist (garbled). Artifacts of servable packages must also sit INSIDE the repo's build authority so repo-wide builds refresh them instead of leaving orphaned copies behind.
- **How to prevent**: (1) pd-console joined the root `build` chain — every repo-wide build and every worktree bootstrap (git-13) now refreshes its dist, and the build-stamp freshness check treats root build-authority edits as stale-triggering; measured cost ~4s per root build (14s total). (2) Pilot/E2E runbooks must pin console launches to the installed-runtime absolute path or rebuild-before-serve. (3) Stale, unserviced dists in the primary checkout are deleted on sight (openclaw-plugin 2026-08-28 and pd-companion 2026-08-28 copies found and removed 2026-10-23).
