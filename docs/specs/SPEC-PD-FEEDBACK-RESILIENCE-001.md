## 1. 目标与首版范围

用户在对话里说「记一下刚才漏验收的问题」。PD 给出真实保存回执。即使目标轮正文尚未采到，反馈的身份和可用线索也留在原任务。正文入库后，PD 在后台补回并正常诊断，用户无需找 ID、重复贴原话或点重试。没有足够证据时，在原反馈上说明原因。其他反馈仍能正常处理。

**首版先交 Codex 已有明确目标、正文晚到这一条。** 它使用已有工作区绑定、采集和补采、诊断任务、`evidence`、候选准入及 worker。Windows 独立唤醒、全缺身份回填、历史批量重开及其他宿主的等价身份接线分别有交付条件，不压住这条主路径。

## 2. 三项产品保证

### G1 能保存就真实登记

- 由 #2699 的工作区绑定决定写入对象。错绑、无写权限等真正的保存问题返回失败或待确认。禁止写入其他宿主目录。现有反馈锚点、表单权限、`painId` 与读回语义继续适用。
- 缺会话、轮次、正文，或诊断暂不可用，均不作为合法反馈登记失败的理由。先保存原反馈和程序确实拿到的宿主线索。相同反馈身份重试走既有读回与去重。响应丢失但无法确认是否同一次调用时，保留未知，禁止用相似文本冒充幂等键。
- 提交路径保持有界。只做本地入库和至多一次精确查询。采集扫描、模型请求与 worker 健康是独立步骤。

### G2 自动补证，失败不堵队列

- 第 12 轮登记第 10 轮的问题。明确知道目标时保存提交与目标的分别引用；目标正文晚到时，Codex worker 在已有补采后自动按原工作区、原会话、目标轮次补录，不新建反馈。不能用提交轮或最近消息替代未确定的早前目标。
- 复用 #2701 的精确取证和既有输入证据。诊断和候选准入须通过真实读回消费同一份材料。授予采集权限不自动等于允许保留一份新副本，正文读取、持久短摘录和重用按现有政策校验。缺授权、来源过期或不可信时给出具体处置。
- 待补证项在诊断候选查询的数量上限之前排除，其余任务继续。首版按现有 worker 节奏有界重查，到上限就显示「证据不足」。具体次数与每批数量作为实现默认值，不冻结产品时钟。能确定目标源后来进展时，可按证据证明重新安排一次；没有观测点则首版不订阅新事件。
- 沿用既有宿主采集与检查点补采。合并验收单条确定完整的坏记录、未结束尾部和重启。合法后续记录须可采，未完成尾部可等写全，重复重放不得增写。

### G3 后台可解释，独立运行有单独门槛

- 首版使用现有 CLI worker 和 OpenClaw 现有宿主调度。Companion 可以启动独立 worker；诊断代理位于 PD Core。注册成功和实际有处理者是不同事实。只有近期执行证据才展示「正在处理」，否则显示「已保存，后台暂不可用」；已有诊断结果的账本问题走原后处理。
- 关掉 Companion 后用户仍不应被迫手动处理。正式承诺之前，一次正式安装对照确认现有受支持的后台启动方式是否覆盖无界面场景。如果确有缺口，再复用 `worker --once` 接入安装器托管的用户级触发，独立验证是否需要典型 Windows 任务计划。需证明正式安装、升级、停用和卸载、一宿主出错不拖另一宿主、无重复领取，以及实际凭据可读。该门槛不阻塞 G1/G2 的首版交付。

## 3. 最小开发与验收

| 验收 | 通过条件 |
| --- | --- |
| A1 正常入口登记 | 缺身份或诊断不可用可保存；写入失败、写回执丢失和真实已保存分别有明确结果。同一已知身份读回不生成第二条。 |
| A2 Codex 正式入口先提交、后采集 | 同一原反馈无需用户动作。持久化任务经实际读回、诊断装配、候选准入可见同一目标证据，且 `evidenceClass` 与输入证据计数一致。使用隔离安装包、历史宿主夹具及本地假诊断模型。 |
| A3 隔离与正常任务推进 | 错会话、异宿主同 ID、授权撤回、源过期不误绑。构造多于领取上限的旧待补证任务，后面的正常任务仍能被领取。 |
| A4 补采和重复恢复 | 超长完整行/未完成尾部不阻断合法后续记录；重复补采、两个并发执行者、崩溃后重跑不会重复补证或诊断。只有成功装配及准入的例子算闭环。 |
| 独立交付条件 B1 | 缺全部身份的回填先实证同一工具调用与成功回执的关联，再支持解码；旧反馈再诊断按原任务逐个恢复并先证明原子重开。无可验证来源仍记录证据不足。 |
| 独立交付条件 B2 | WorkBuddy / OpenClaw 各自证明正常入口提供同义目标，再扩展自动关联。系统始终按 #2699 的工作区路径权威。 |
| 独立交付条件 B3 | 正式环境中证明无界面仍处理或补上备用触发；不通过则明确报告后台可用性问题。 |

## 4. 自查结果与复杂度

v0.1 把 Windows 定时器、所有宿主的精确恢复和历史重开都拉进首版，并为恢复另设证据表示。v0.2 的首版只解决已知目标晚到。新增持久内容限于原任务上的可选补证进度和身份线索；证据使用现有字段。保持现有数据库、治理审批、路径解析与调度。仅在实现证明现有任务查询无法满足时考虑索引。回退时保留原反馈及历史，已部署诊断不得读取到未验证证据。

首版结束条件是 A1–A4 在同一安装候选通过。工程验证使用真实提交、采集、诊断装配与准入；模型质量无需新增实验。B1–B3 是剩余能力与明确门槛，不被写成已交付。
