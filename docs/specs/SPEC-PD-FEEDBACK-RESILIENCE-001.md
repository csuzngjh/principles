## 1. 什么值得 PD 记下

痛苦信号记录**一次真实行为相对于明确要求的具体、显著偏差**。一份有锚点的反馈能回答三个问题：当时依据什么要求，助手实际做了什么或漏做了什么，两者差在哪里。要求可以来自 Owner 表达过的期望、当时适用的已有原则，或生效的 Agent Instruction / Skill。一次就可以记录；重复、损失和情绪强度影响优先级。原始信号表达值得调查的偏差；其根因、是否值得形成原则、该原则能否生效，分别由后续诊断和治理决定。[正式 Skill](../../packages/pd-skills/skills/pd-pain-signal/zh.md) · [架构中的 Pain Evidence](../architecture/PD_Owner_Reader_Companion.md)

例如，Owner 已要求「验证通过才能交付」，助手却在未运行测试时宣称完成。这里的信号是错误的交付声明；测试失败本身或一句「我不满意」均不足以独立证明这个偏差。Owner 只说「刚才漏了验收」时，PD 仍可按原入口保存其原话，标为未经独立核验的陈述；有授权证据时再还原事情经过。

## 2. 用户在宿主里应得到什么

用户在对话里说「记一下刚才漏验收的问题」。PD 给出真实保存回执。即使目标轮正文尚未采到，反馈的身份和可用线索也留在原任务。正文入库后，PD 在后台补回并正常诊断，用户无需找 ID、重复贴原话或点重试。没有足够证据时，在原反馈上说明原因。其他反馈仍能正常处理。

第一条工程切片选 Codex 已知目标、正文晚到。与它并行推进统一登记和后台独立运行。整项产品交付须证明：用户或已获对应权限的宿主代理均能创建；同一偏差从不同受支持入口进入后，诊断能理解同一组事实；Web 和 Companion 始终关闭，原反馈仍能走到应有的治理结果。

### 谁发起，如何统一

| 情形 | 用户可依赖的行为 |
| --- | --- |
| 用户手工或委托助手提交（含 Skill、CLI、MCP） | 原话或明确授权代报的内容只保存一次。能提供的锚点、行为、偏差及来源一起传递；现有简短原话入口仍可用。CLI 的显式会话模式继续约束其可信会话；不具备身份时使用合法无绑定入口，不伪装已绑定。 |
| 宿主代理自己发现偏差 | 在该工作区已允许自动上报、具有可信事件及具体偏差依据时，可以不逐条请用户签字。保留代理或自动观察来源。普通 Owner 代报工具的调用权限不能充作自动上报权限。可恢复的线索不足时保留观察，条件具备再按原观察身份推进。 |
| 程序补证、重启恢复或重试 | 沿原记录补足事实，不新报一个相同偏差。对获取不到的内容记录原因；后续各层可分辨 Owner 原话、代理陈述、宿主直接观测以及诊断推断。 |

## 3. 三项产品保证

### G1 能保存就真实登记

- 由 #2699 的工作区绑定决定写入对象。错绑、无写权限等真正的保存问题返回失败或待确认。禁止写入其他宿主目录。现有反馈锚点、表单权限、`painId` 与读回语义继续适用。
- 会话、轮次、原始正文和诊断模型可用性属于关联或执行条件。合法的手工反馈在这些条件缺失时仍可登记；对缺依据的自动事件，应回报真实的观察状态。先保存原反馈和程序确实拿到的宿主线索。相同反馈身份重试走既有读回与去重。响应丢失但无法确认是否同一次调用时，保留未知，禁止用相似文本冒充幂等键。
- 提交路径保持有界。只做本地入库和至多一次精确查询。采集扫描、模型请求与 worker 健康是独立步骤。

### G2 自动补证，失败不堵队列

- 第 12 轮登记第 10 轮的问题。明确知道目标时保存提交与目标的分别引用；目标正文晚到时，Codex worker 在已有补采后自动按原工作区、原会话、目标轮次补录，不新建反馈。不能用提交轮或最近消息替代未确定的早前目标。
- 复用 #2701 的精确取证和既有输入证据。诊断和候选准入须通过真实读回消费同一份材料。授予采集权限不自动等于允许保留一份新副本，正文读取、持久短摘录和重用按现有政策校验。缺授权、来源过期或不可信时给出具体处置。
- 待补证项在诊断候选查询的数量上限之前排除，其余任务继续。首版按现有 worker 节奏有界重查，到上限就显示「证据不足」。具体次数与每批数量作为实现默认值，不冻结产品时钟。能确定目标源后来进展时，可按证据证明重新安排一次；没有观测点则首版不订阅新事件。
- 沿用既有宿主采集与检查点补采。合并验收单条确定完整的坏记录、未结束尾部和重启。合法后续记录须可采，未完成尾部可等写全，重复重放不得增写。

### G3 控制台和 Companion 全程关闭，PD 后端仍能工作

- 当前 CLI worker 能执行周期，OpenClaw 插件能向宿主注册服务；Codex/WorkBuddy 的 Companion 启动并监督子进程，退出会停止这些子进程。诊断代理位于 PD Core。注册成功和实际有处理者是不同事实。只有近期执行证据才展示「正在处理」，否则显示「已保存，后台暂不可用」；已有诊断结果的账本问题走原后处理。
- **无界面运行是整项发布的必要条件。** 支持的安装方式应随启用配置好 PD 后端的启动、故障恢复与更新。在典型 Windows 用户环境中，用户登录后只使用宿主，安装的后台执行者须自己消费任务；浏览器、桌面控制台、开发终端、人工运行命令均无需在场。沿用 OpenClaw 已注册的宿主服务和已有工作区 worker，按宿主核验谁拥有其生命周期。
- 一条反馈可终止在按规则拒绝、证据已耗尽或已有 Owner 治理节点；系统须展示原因及可恢复条件。临时缺证、服务暂不可达、worker 崩溃要自动恢复。原有工作区停用、授权撤回、重复候选审查以及需要 Owner 决定的治理节点继续有效。Owner 通过后后台接着跑，拒绝后停止对应分支。

## 4. 工程切片与产品验收

| 验收 | 通过条件 |
| --- | --- |
| A1 正常入口登记 | 缺身份或诊断不可用可保存；写入失败、写回执丢失和真实已保存分别有明确结果。同一已知身份读回不生成第二条。 |
| A2 Codex 正式入口先提交、后采集 | 同一原反馈无需用户动作。持久化任务经实际读回、诊断装配、候选准入可见同一目标证据，且 `evidenceClass` 与输入证据计数一致。使用隔离安装包、历史宿主夹具及本地假诊断模型。 |
| A3 隔离与正常任务推进 | 错会话、异宿主同 ID、授权撤回、源过期不误绑。构造多于领取上限的旧待补证任务，后面的正常任务仍能被领取。 |
| A4 补采和重复恢复 | 超长完整行/未完成尾部不阻断合法后续记录；重复补采、两个并发执行者、崩溃后重跑不会重复补证或诊断。只有成功装配及准入的例子算闭环。 |
| 独立交付条件 B1 | 缺全部身份的回填先实证同一工具调用与成功回执的关联，再支持解码；旧反馈再诊断按原任务逐个恢复并先证明原子重开。无可验证来源仍记录证据不足。 |
| 独立交付条件 B2 | WorkBuddy / OpenClaw 各自证明正常入口提供同义目标，再扩展自动关联。系统始终按 #2699 的工作区路径权威。 |
| B3 无界面运行（发布必过） | 从正式安装、登录后两个界面均未启动开始，在真实宿主入口提交。观察原任务完成诊断、准入并推进到适用的后续状态；终止一次后台进程，系统自行恢复，另一工作区继续，原任务无重复副作用。再验打开/关闭 Companion 不抢占或终止独立执行者。 |
| B4 输入等价与自主创建（发布必过） | 同一具体偏差分别从手工 CLI、Skill 引导入口、MCP 和可信自动来源提交到隔离工作区。比较原任务读回与诊断实收输入；相同事实、不同来源如实保留。另验代理无授权、自动事件缺证后晚到、旧版原话及重复投递。 |
| B5 治理闭环（发布必过） | 在两界面均关闭时走完一条合法正例至既有 Owner 节点；用受支持的治理入口分别批准/拒绝独立样本，读回后续结果。另验合法无候选、策略停用、暂时故障自动恢复，均有可区分的结果。 |

## 5. 范围、复杂度与完成条件

v0.1 把 Windows 定时器、所有宿主的精确恢复和历史重开都拉进首版，并为恢复另设证据表示。v0.2 的首版只解决已知目标晚到。该切片的新增持久内容限于原任务上的可选补证进度和身份线索；证据使用现有字段。v0.3 保留现有数据库、治理审批和路径解析；后台启动责任见 G3。仅在实现证明现有任务查询无法满足时考虑索引。回退时保留原反馈及历史，已部署诊断不得读取到未验证证据。

A1–A4 只关闭「Codex 目标正文晚到」切片。总单 PRI-1272 的产品验收还包括 B3–B5、各声明支持的宿主及入口矩阵；B1/B2 只为有可核验来源的场景承诺精确补录。任一宿主未具备能力，须在交付记录单列。正式安装验证允许隔离模型返回确定性结果，须真实经过正常入口、后端进程、状态库和治理链。验收衡量数据能否流转，模型是否产出高价值原则另评。

复杂度预算：优先复用既有 ingress、状态库、任务租约、轨迹授权和 CLI worker。若标准安装缺少无界面驱动，新增的是安装器管理的一项用户级启动责任；若代理只有 Owner 代报通道，新增的是可鉴别的自主来源及对应准入。两者均须在实现评审列出真实增量；无需新建一套代理、队列或数据库。
