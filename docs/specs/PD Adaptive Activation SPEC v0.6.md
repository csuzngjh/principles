## 1. 产品目标与成功标准

**短期目标是 Decision Intervention。** 在一个仍可改变的决定前，把一条已授权原则送入将作出决定的模型请求。观察 Agent 随后做了什么、用户得到什么，以及额外提示付出了多少代价。例如，交付结论前主动核实一项关键证据，同时避免为已验证事项重复检查。

**长期目标是 Behavioral Evolution。** 在持续开启 PD 的不同任务、Session 和时间窗口中，Agent 能更稳定地作出合适决定。范围包括识别真实意图、自主推进、发现目标偏离、自我纠偏和完成高质量交付，也包括适当的风险提醒。持续干预下的长期可靠性与撤掉提示后仍保留的行为内化是两个独立命题。后者需要说明变化的可能载体，隔离历史上下文、工作产物、持久记忆及 Owner 工作习惯的影响；可在未来与 Adaptive Cognitive Memory、行为反馈和持续学习结合研究。

| 设计原则 | 对第一阶段的约束 | 如何判读 |
|---|---|---|
| Intervention over Relevance | 先写明具体决定、候选行动和希望避免的后果，再映射原则。 | 记录相对现行策略可能增加的收益；按 §6 估计 Marginal Intervention Value。语义相关度仅作诊断。 |
| Root Cause before Activation | 选场景时先核对原则是否有可能改变错误。遇到新案例可标未知，不在同步路径增加分类器。 | 按 §3 区分提醒可以处理、只能间接帮助和需要其他补救的问题。 |
| Timeliness over Frequency | 先定位可观测信号与关键行动的先后关系，再选宿主入口。 | 用真实决策机会计算 Timely Intervention Coverage；每百次回调的成本单独报告。 |
| Net Benefit over Compliance | 同时留存目标动作、任务结果和对正常工作的干扰。 | 自主纠偏、减少返工与不必要确认、任务阻塞等分别列示。严重伤害不能被平均收益抵销。 |
| Evidence over Self-Assessment | 复用 Receipt、Evidence 和 Examiner；允许“未知”。 | 工程运行、真实使用观察、可归因的对照结果按 L1/L2/L3 分开报告。 |
| Incremental Value over Architectural Complexity | 先接通一条 Native 链路。新增模型、状态或配置必须对应已观察的缺口。 | 与更简单方案比较收益、额外延迟、费用和维护成本。没有增量证据时维持简单路径。 |

**成功口径分三次决定。** 工程验收要求能复现事前送达，并能关联后续行为。真实使用复盘要求能说明何时有帮助、何时造成干扰、哪些机会没看到；仅有少量或混合结果也能完成复盘。要声称“PD 导致改善”或“改善能长期持续”，还须取得与主张相称的对照或纵向证据。工程验收和结束观察窗口均不自动产生后两项结论。

**第一阶段结论边界。** 第一阶段成功只表示 Principle Intervention Loop 在指定场景下达到相应工程或行为证据要求；不能外推为通用 Adaptive Activation、跨任务自主识别原则需求、自动更换原则、多原则动态组合或通用 Adaptive Selector 已获验证。后续自动化按真实使用发现的明确缺口逐项建设，并独立验收。

## 2. 第一期工程范围与场景契约

首期复用现有 Native 激活阅读、容量预算、装配和渲染路径。一次映射只指定一条干预目标；已有 Native 内容、不可省略的治理或宿主约束继续由原路径处理。额外选择、重复注入或为容纳试点而挤掉必需内容均不允许。目标原本已在本次 Native 最终文本中时，复用该份内容，记录“两种策略的实际内容相同”；即使及时送达，也不能据此主张增量内容效果。

**建议首选的试点**是 OpenClaw embedded 中的“交付验证结论”。例如，在明确进入验收的真实工作中，Agent 即将对一项工作给出完成判断；适用原则要求根据已有验证证据作出结论，缺少证据则如实指出。关键行动是首次对外给出该项完成结论。可观察结果包括核实了已有产物、正确指出尚未验证、发现不符后自行更正；干扰包括重复昂贵检查、索要无关确认或拖延已经充分验证的交付。以上是可替换的实施建议，不代表现有原则库里已有对应 Artifact，也不代表当前宿主链路已验证。

每轮开始只冻结一张**场景卡**，放入已有工程或评估记录。最少填清：

1. 宿主、版本、运行模式、隔离工作区和使用边界；记录正常工作里已有的决策点，以及什么情形应保持普通 Native 行为。
2. 可在行动前识别的信号、当前请求与关键行动的关系、可接受的结果和禁止的副作用。例如用团队原有验收步骤的显式标记，或本轮事先配置的窄映射。不得读取未来结论作为触发条件。
3. Runtime V2 当前有效的原则、Artifact/Activation 标识和修订；确定优先方向不能创建授权。若无匹配原则，缩小或更换场景；需治理变更时走原有流程。
4. 独立确认本次请求收到目标文本的方法、任务产物或行动证据来源、机会去重规则、观察窗口与可接受成本。要能发现至少一部分漏触发机会，例如在已有交付清单中抽查全部验收交付，而非只查干预日志。
5. 本轮负责人、结束日、停用方式及 Owner 需要决定的一件事。标记应尽可能复用已有工作步骤，不要求 Owner 每轮对话打标。

可以人工确定一次映射，或使用窄配置/确定性规则。宿主回调只陈述事实；“发生回调”本身不能证明用户切换任务、存在干预价值或已经到达指定决策点。匹配不到事前信号就走 Native。首期不推断长期隐含意图，不在每条消息上调用模型，不要求构建数据集。一个场景和一条原则是本期范围，长期支持多原则与复杂任务的方向保留。

## 3. 错误成因与可干预性

下表用于选场景、复盘误判和归类遗漏。依据可见事实，在现有案例记录中填一个主要标签，必要时补次要标签、证据引用及“推测/已核实”。多个成因可并存；证据不足写“未知”。不对每次操作做强制诊断，不增加服务、模型调用或治理状态。

| 成因 | 何时值得试用原则 | 何时应改走其他路径 |
|---|---|---|
| 忘记已知约束 | 约束早已明确，Agent 有能力在提醒后调整下一步 | 约束从未提供，先修复事实或约束的可见性 |
| 目标或意图理解错误 | 提醒核对已表达的目标、识别矛盾或做必要澄清 | 两种目标都符合现有证据且后果不同，由执行 Agent 向 Owner 求证 |
| 风险识别不足 | 风险征兆在行动前已出现，可触发恰当核验 | 风险只能在事后识别，记录可观测性缺口 |
| 缺少必要事实 | 提醒查证可取得的事实或缩小结论 | 提示不能补出缺失事实；记录信息缺口 |
| 工具或执行能力不足 | 提醒承认限制或采用已获准的替代路径 | 根因是工具或访问能力时，转交原责任方 |
| 授权不明确 | 提醒核实范围或暂停受限动作 | Runtime V2 管原则资格；真实操作权限仍由原权威裁定 |
| 错过干预时机 | 有更早且可靠的信号，可调整本场景时点 | 行动已发生则计入遗漏，事后纠正另记 |
| 原则本身不清晰 | 可通过真实案例揭示歧义或冲突 | 将证据交 Owner 治理；运行时不得改写 Artifact |

## 4. 共享核心、宿主入口与调用链

```text
已核实的行动前入口 → Adapter 绑定宿主、工作区、Session、请求和事前信号
  → 共享核心核对本轮场景映射 → Runtime V2 Reader 返回当前有效候选
  → 验证目标 ID、Artifact、授权与范围 → Native Budget / Packer / Renderer
  → 同一 Adapter 按该模式编码和返回 → 独立请求证据确认送达及时点
  → 既有 Evidence 关联后续动作、产物及任务结果 → Examiner 独立评价

无匹配、失效、超时、超预算或不可安全交付 → 原 Native / 宿主安全降级
各段实际观测 → 原有 Receipt / Evidence；证据缺失处保留 unknown
```

| 责任方 | 输入与输出契约 | 实施边界 |
|---|---|---|
| Runtime V2 | 从经批准的 Activation 与已验证 Artifact 读出当前有效候选和身份 | 唯一治理授权权威。共享核心、映射、宿主、Examiner 均无权授予、修改、撤销或激活草案。使用前发现撤销或版本变更必须重新验证。 |
| Host Adapter | 校验精确 profile、真实事件、运行模式与可用身份，向共享核心提供事实；将验证后的文本送回正确请求 | 不拥有原则决策。宿主任务事件或内部 todo 不代表 Owner 目标。身份不可靠时不合并事件或跨 Session 复用；未知 profile 退回已验证 Native。 |
| 共享核心与 Native | 有界事前信号、场景映射和有效候选 → 一条验证后的引用或空结果 → 现有预算、装配与渲染 | 不改原则正文；检查重复、现有约束优先级、最终装配内容及容量。仅对目标产生的增量负责。首期无需持久 Working Set、语义路由器、外部推理或新存储。 |
| Receipt / Evidence | 关联选择、最终渲染、适配器返回、独立请求证据、动作与结果引用 | 记录事实及其来源；不能给自身打行为效果分。强关联需要可验证的相同请求或受限因果顺序；仅凭墙钟相近不能拼接。 |
| Examiner | 读取授权范围内的证据、冻结的场景判据与产物，分别评价遵循、结果、代价与结论边界 | 复用既有隔离、配对、负迁移和报告。首期允许“未观察到”“改善未知”；不为本项目另建实验平台。 |

工程落点可从现有的 `packages/principles-core/src/runtime-v2/activation/prompt-activation-reader-contract.ts`、`prompt-budget-policy.ts`（同目录）、`packages/host-runtime/src/active-principle-prompt.ts`、`packages/openclaw-plugin/src/core/runtime-v2-prompt-activation-reader.ts` 与 `packages/openclaw-plugin/src/hooks/prompt.ts` 核对。这些是代码定位线索；实施时应在选定版本沿正常入口核实实际生产者、消费者及重复装配风险。不得假定各宿主走相同调用栈。

**时延与失败。** 首期不增加外部模型调用。沿用现有同步耗时和提示容量两个独立预算，按所选 profile 的实际超时留出安全余量；证据收集不能在提示路径同步等待后续行动、网络评分或新增数据库事务。到达软截止即放弃本轮增量，记录降级。已匹配但正文装不下、只送达部分目标文本、请求换代、结果过期都不能算成功。重试和重复回调按同一真实决策机会去重；无法建立可靠身份，保留独立未关联记录，不能重复注入或将其计为多次成功。

**隐私。** 默认记录版本、最小关联标识、摘要指纹、事件时间和可控访问的证据引用。避免默认保存原始会话、密钥、绝对路径、完整模型请求及推理过程。独立确认可由受控观察者在请求边界比对目标正文、请求身份和修订后仅留下引用。导出样本、调用外部模型或扩展观察范围须遵循现有数据权限；收集不到就标未知。

## 5. 交付、行为与证据语义

| 事实层 | 可接受的证据 | 允许作出的结论 |
|---|---|---|
| Governance Authorization | Runtime V2 当前有效 Activation 和 Artifact | 允许参与本次选择 |
| Principle Selection | 映射命中且通过资格、范围、版本验证的目标 ID | 核心选择了它；装配结果仍待验证 |
| Prompt Delivery | 区分 rendered、returned、confirmed。confirmed 需要独立证据证明目标正文位于本次实际模型请求 | 仅当请求与关键动作的先后也可证，才能判定及时送达 |
| Behavioral Compliance | 工具动作、工作产物或对外决定可独立核实，与事前行动判据相符 | 可观察到遵循；引用原则、自称遵循或输出理由均不足 |
| Behavioral Improvement | Examiner 依据独立结果、代价、比较条件及观察时长出具判断 | 明确是实际观察、可归因的增量效果，还是跨时间的可靠性；遵循本身不保证获益 |

沿用 v0.5 的四维交付事实：hook 执行结果、payload 状态、选择状态、宿主提交结果；独立保存 journal 的 open/closed/reconciled 状态和证据等级。同一调用用同一 `hookInvocationId`，跨调用的同一机会另行去重。未决 open 不计成功；缺少起始记录不证明宿主 kill。降级/失败不证明提交被阻塞，超时归因和提交结果需独立宿主证据。returned 不等于 confirmed；事后对账可以保留 unknown。目标未匹配可记录完成评估后的 `none_applicable`，策略未运行用 `skipped`，无法完成选择用 `unavailable`；不得用合法空集掩盖故障。普通 Native 另有内容时，分开标明试点目标结果与整体 payload，不能把其他原则的送达归给试点。

**分级按所要证明的主张，不按日志数量，也不替代宿主的事实来源等级。**

- **L1 工程证据**：功能经过哪一层、失败在哪里、目标是否在行动前进入请求。fixture、mock、独立宿主请求分别标来源。mock 只能证明契约。
- **L2 真实使用证据**：在实际任务中，以动作、产物或必要的简短反馈观察到的改变、无变化、伤害或未知。保留未干预与原本做对的机会。相关性不支持因果结论。
- **L3 对照研究证据**：比较条件、分配、基线、隔离、盲评或客观终点及不确定性足以支撑特定归因。只知分组时最多报告策略分配效果；声称内容效果还需送达证据和排除其他干预差异。一次 L3 对照也不能自动证明长期内化。

### 5.1 最小数据契约与状态转换

每份 Receipt 必须分别保存以下字段，不允许合并成一个 Injection Status。界面或旧接口若显示 returned、confirmed、skipped、timeout、failed、unknown，须保留来源维度；skipped 来自 selection，timeout/failed 来自 execution，returned/confirmed 来自 payload，unknown 须注明未知维度。组合结果不能掩盖其他维度。

| 字段 | 枚举与精确定义 |
|---|---|
| execution | completed 正常结束；degraded 因自设截止、依赖或资源限制中性降级；timeout 有独立宿主 kill 证据；failed 执行或编码错误；unknown 无法确定结束原因。自设截止只能记 degraded。 |
| payload | none 已知未产生目标载荷；prepared 正文已渲染尚未返回；returned 已返回 callback，尚未证明进入请求；confirmed 独立证据确认完整正文进入对应实际请求；unknown 无法确定。 |
| selection | selected 有效目标已选中；none_applicable 已完成评估且无适用目标；skipped 策略未运行；unavailable 依赖失败导致无法完成选择。 |
| submission（HostSubmissionOutcome） | proceeded 宿主提交继续；blocked 宿主拒绝提交；unknown 默认值。前两者必须有独立宿主证据，不能由执行或载荷状态推断。 |
| receiptState | open 已写启动记录，尚无终态；closed 已产生终态，允许失败、降级和空结果；reconciled 后台对账完成，允许仍未知。三者均不代表送达成功。 |

启动时保存 open、execution=unknown、payload=unknown、submission=unknown；selection 尚未判定时用 unavailable 并注明初始化未决，不计依赖失败。每次调用在最早可记录入口生成唯一 hookInvocationId，并贯穿启动、终态、对账及证据引用。该 ID 标识调用，不代替机会去重身份；缺失 ID 的记录不得自动拼接或计为成功。

正常路径为 open → closed；对账可将 open 或 closed 更新为 reconciled，保留原记录和对账依据。payload 的正常观测为 prepared → returned → confirmed；只有独立请求证据才能升级 confirmed。对账可直接补充确认事实，但必须保留原未知状态、证据来源和时间；缺证继续 unknown，不能按“未报错”升级。每次升级须绑定相同调用、请求、正文及配置身份。证据相矛盾时标待核实，不覆盖原事实。

confirmed 必须同时具备 execution=completed、独立验证标记及证据引用。execution 为 degraded/timeout/failed/unknown 时，不能把本次目标 payload 标成 returned/confirmed；若部分阶段观察冲突，保留阶段证据并交对账，不能拼成成功。none_applicable 表示成功完成空选择；其目标 payload=none、execution=completed，不计故障。skipped 与 unavailable 分别报告。reconciled、closed、proceeded、returned 均不能代替 confirmed；confirmed 仍需行动先后证据才能计及时送达，也不能证明理解、遵循或改善。

### 5.2 运行配置身份

每份运行证据必须带有或引用不可变的配置身份快照，最少包括 host、hostVersion、runtimeMode、pluginVersion、effectiveHookSetFingerprint 与 evidenceCoverage。evidenceCoverage 为 complete、partial 或 unknown，并说明已覆盖的配置来源及缺失项。各字段取不到写 unknown，不能以安装目录或预期配置冒充真实生效配置。

effectiveHookSetFingerprint 对当时实际可观测的生效 Hook 集合及来源作确定性规范化后取摘要；无法覆盖全部来源时使用 partial，完全不能核实则为 unknown。partial 指纹只识别已知部分，不能宣称完整配置身份。沿用现有 profile 与证据记录归属，无需另建配置管理系统。

版本、模式、插件或指纹变化后，新请求必须绑定新快照；无法取得新指纹时记录缺失。旧证据保留原身份，只能支持原范围，不能自动证明新配置有效。实际链路变化或配置无法匹配时重新核验所选入口与交付，恢复前遵守 §7 的安全降级；不触发其他宿主全面审计。

## 6. 评价定义与日常采集

### 6.1 及时干预覆盖率（Timely Intervention Coverage）

每个案例区分三个时点：实际目标/风险变化或决策机会出现的 `t_change`、按该模式可得信息能够首次识别机会的 `t_observable`、Agent 首次采取事先定义的关键行动的 `t_action`。另记实际发现时点与目标请求的送达时点 `t_delivery`；观察者事后发现的时间不能充当事前可见时间。时钟不可比时可用同一请求及其后续动作的可靠顺序；没有可证顺序则及时性未知。

以场景卡规定的**决策机会**为单位，在固定窗口内去重，依据独立任务/产物样本复核：

| 集合 | 定义 |
|---|---|
| T 理论机会 | 审阅判断当时存在可改变的实际决定，且已授权原则在行动前有合理干预可能。依据场景及前置事实认定，不要求后来一定犯错。不可干预和范围外另列。 |
| V 事前可见 | T 中在选定 profile 上有可取得且早于行动的合格信号。 |
| O 实际识别 | V 中 PD 确实在行动前识别的机会。误触发与只在事后识别的事件另列。 |
| D 及时送达 | O 中独立确认目标文本位于同一决策的实际模型请求，且送达先于关键行动。仅 returned、延迟送达、未知分别列示。 |

**主指标为 D/T**。同时给出 V/T（可见性）、O/V（识别能力）、D/O（交付能力）及各自计数。按抽样审阅得到的 T 只报告该样本的覆盖率，说明抽样与漏检限制；无法估计 T 就报告未知，不能把 D/O 改名为总体覆盖率。分母为零写“不适用”，不同分母的未知数分别报告。及时送达下界使用已确认数，未知不算失败也不算成功。错过行动、失败回退、重复和错误匹配必须可见；全量 hook 数只用于运行负载。对原本就已送达相同文本的情形，分别报告覆盖和真正新增及时提示的次数。

### 6.2 边际干预价值（Marginal Intervention Value）

比较同一适用人群/任务条件下，**在现行 Native 策略之上纳入目标原则**与**维持原策略**时的结果差异。治理资格和不可省略约束保持一致。记录实际呈现差异；若加入目标挤掉其他可选内容，比较所得是整套装配策略的增量，不能单独归给该原则。给定一条真实轨迹无法直接观察其反事实；第一阶段不建立价值预测器，不给每条原则虚构分值。

首期逐案保留目标决定、下一步实际动作、最终结果、原本相同提示、潜在成因和代价。L2 可以写“在提示后发现了遗漏并更正；归因未知”。当有适当对照，再报告差值、样本与不确定性。采用结果向量，逐项说明收益或损害，不设未经 Owner 裁定的综合权重。

| 收益 | 同时检查的负面结果 |
|---|---|
| 决策正确、减少有后果的违反、任务完成质量 | 过度谨慎、上下文干扰、只复述规范而任务未完成 |
| Agent 在 Owner 纠正前发现偏差并实际修正 | 无效检查、重复劳动、额外延迟或任务阻塞 |
| 减少因错误/遗漏导致的 Owner 纠正与返工 | 对已授权事项重复确认；遗漏本应向 Owner 请求的澄清或审批 |

区分**必要介入**（目标冲突、权限不清等必须由 Owner 决定）、**不必要返工**（修正本可避免的错误）、**多余打扰**（本可安全自主推进）。记录类别、理由及已知成本；无法判断标未知。Owner 介入次数下降同时伴随应有审批遗漏时，不能解读为改善。

### 6.3 自动采集与反馈

按已有证据链自动关联去标识的机会、请求、有效原则版本、最终提示差异、动作/产物引用、时点、结果及回退原因；采不到的维度允许缺失。请求和机会是一对多时，只将行动前与该机会相关的请求用于判断。重复行为或后续自行纠正不覆盖首次行动。弱关联单列待核实。Examiner 读取受限引用和抽样的正常案例，不把模型自述作为判分依据。只在重要误判、实质性收益/损害或下一轮取舍需要时向 Owner 请求一次简短反馈。仅记录失败事故会高估收益，仅记录已送达样本会高估覆盖。Owner Review 必须写明本轮仅支持指定场景的闭环结论，自动语义选择与多原则组合的验证状态另列。

## 7. 宿主边界、启用与停用

**选择宿主的条件**是 Owner 确实在该模式工作、存在真实的行动前窗口、能安全回到普通 Native，并能独立确认目标请求。优先核对 OpenClaw embedded 的既有 prompt-build 入口和 Examiner 的 OpenClaw 受控评估路径。两者的历史证据不能相互代替。当前版本、运行方式和可用请求观测须重新核对。若只能取得 callback return，可继续局部开发和 L1 故障定位；在独立确认前不能验收“及时送达”或将该路径作为已闭环试点。

| 宿主范围 | v0.5 留存的历史事实；本版不升级证据 | 对 v0.6 的约束 |
|---|---|---|
| OpenClaw embedded | 历史 probe 的 embedded prompt 路径与 Gateway reset、普通 Gateway 对话属于不同范围。原则正文与短指令使用各自通道。 | 首选核对 embedded 正文通道。普通 Gateway、reply reset 及其他配置不能借用该证据。 |
| Codex headless CLI | 历史 headless 模式观察到用户提示事件；交互式 TUI 证据未建立。 | 若替换首选，仍只选一种已核实模式；按其 additionalContext 契约独立验证。 |
| WorkBuddy Desktop 5.9.2 / CLI engine 2.165.0 / PD 0.2.2 | v0.5 报告过自降级后零原则贡献、配置来源覆盖不完整。源代码识别的 user-role hook 提醒不等于当次请求已确认。自设截止预算不能定位耗时阶段。 | 单列宿主可靠性事项。仅当选它且直接阻断当前链路时，定位必要耗时段、验证中性降级、journal 和请求证据；不以此启动全量宿主审计。已有阻断继续约束该路径。 |

默认保持原 Native。未来的**限域 Native 试用**会改变真实提示，必须经 Owner 对指定宿主、工作区、场景、原则、期限及停用方式的明确授权；不能借“Native”名称绕过生产控制。已有开关及授权边界优先复用，不要求新建开关平台。模型辅助 Shadow 与模型辅助 Live 分别需要相应 Owner 授权、外发许可及该模式自身的安全和证据门槛；Shadow 不改变真实提示，两者均不得自动升级。Native 试用许可不包含任何模型辅助权限。

**停用与恢复。** 出现未授权原则、跨 Session 污染、重复注入导致操作异常、请求确认误报、泄露、阻塞正常提交或重大行为损害时，立即停用本轮映射，回到原 Native；原链路自身也不安全时按宿主既有安全策略中性返回。保存事实、影响范围及未知项，不改 Runtime V2 治理状态。持续多余确认、延迟超出约定预算或长期无法关联结果，应暂停扩大，缩小场景或结束本轮。恢复需要针对原缺陷复验，涉及重新启用时依原授权边界办理。解除一处宿主阻塞不授权其他模式。

## 8. 交付节奏、测试与验收

每轮在开始时记录实际截止日，窗口届满即形成决定。下列时间盒是推进边界，不是工程工期估算。可以在开发期间用小量既有案例调通；完整离线研究、统计显著性、人工事前对照和大样本均不阻塞核心开发。

| 阶段及时间盒 | 可使用的交付与验收 Gate | 到期或受阻怎样处理 |
|---|---|---|
| G0 核心设计收敛：一个短设计周期 | 一张场景卡；一条有效原则与读入口；选定模式的行动前信号、确认方法、成本边界、退路及最小测试。Owner 确认工程范围后可进入组件开发。 | 优先收窄任务或选择已有可信入口；若没有可靠映射或证据窗口，明确具体阻塞。 |
| G1 核心组件：一个短开发迭代 | 经另行授权开发后，走真实适配器的正常入口，在隔离范围用独立请求证据复现一次及时送达及后续动作关联。完成下列适用测试并演练停用。mock 通过只支持组件级结论。 | 未能确认交付则保留“仅 returned”等真实状态；缩小或更换唯一场景/宿主，重新核对 G0，不扩大模型或宿主矩阵。 |
| G2 真实使用：建议初始 1～2 周 | G1 达成并取得限域试用授权后，在一个真实工作区使用，自动采集命中、遗漏、无变化、伤害与未知。记录范围、暴露次数、采样方式和实际截止日。 | 样本少或结果不明也按时结束观察并复盘。新增一次有边界的观察窗口须有具体问题及决定；不自动延长。 |
| G3 复盘：一次集中分析 | Examiner 分列 L1/L2、收益/干扰、分母/未知和典型案例；Owner 在保留、修订、缩小、停用或申请下一轮之间作一次选择。 | 若可见收益只来自少数例外，限定结论；若需声称因果或扩大高成本架构，转 §9 明确比较条件。 |

### 8.1 第一期最小验收测试

以下是**待执行的规范测试**。每项在实施记录中填写证据来源、profile 与结果；未运行、失败、不适用及原因必须分开。G0 不要求预先取得 G1 的运行结果。

| ID | 场景 | 必须观察到的结果 |
|---|---|---|
| C01 | 同场景、同权限，匹配与不匹配两个输入 | 匹配时只选择配置的有效目标；正常任务按原 Native 路径处理，不凭一般关键词或回调推定风险。 |
| C02 | 目标未授权、Artifact 变更/撤销、临交付前失效 | 不把旧正文带入目标请求，不修改任何治理记录；可追溯拒绝或回退原因。 |
| C03 | 目标已在 Native、预算不足、原约束不可省略 | 已有内容只出现一次；不可安全装配时无本轮增量。记录最终文本差异及未送达，不挤掉必需约束。 |
| C04 | 正常宿主入口与真实请求、只有返回的对照情形 | 独立比对同一请求正文、配置身份和行动顺序；前者可取 confirmed/timely，后者只取 returned，缺证保留未知。 |
| C05 | 动作已经发生、没有信号或未被捕获 | 不补记为及时；能通过任务产物抽查漏触发机会。未能建立完整 T 时只报可观测部分。 |
| C06 | 重放、并发 Session、profile/配置或请求身份变化 | 无跨界、无重复投递或虚构合并；不同请求不能借用旧确认。指纹不可得记录 partial/unknown，配置变化后旧成功不能充当新配置证据。 |
| C07 | 依赖失败、软截止、证据缺失和恢复 | 增量失败不阻塞正常任务；没有返回、提交或 kill 的独立证据不能伪造成功或阻塞。撤掉映射后原 Native 仍可工作。 |
| C08 | 一次符合原则的行为、一次无效/有害遵循 | Examiner 能区分行动、最终结果和不必要代价。行为独立证据缺失时不以自述或 receipt 补齐。 |
| C09 | 限域授权、到期、未经授权的外发或模式切换 | 仅在批准的使用范围和期限运行；不自动开启 Shadow/Live，不向未授权目的地发送上下文。 |

**工程可用**要求 C01–C09 各自的边界有证据，C04 正例与 G1 必须使用选定运行模式；C08 可先用已知例验证评分区分能力。**真实使用有价值**由 G2/G3 的工作证据判断，必须同时查看负效应、必要介入和未确认部分；缺乏依据时结论为“尚不确定”。**广泛推广/效果归因**另须匹配主张的证据，不能由测试清单通过代替。

### 8.2 一页 Owner Review

每轮结束由工程负责人汇总，Examiner 独立标注证据边界。只交付六项：本轮用在哪个决定；完成/未完成；机会、及时送达与未知的计数；一个有帮助或无帮助的案例和最重要的负面信号；当前最大风险及其证据等级；下一步、预期代价和需要 Owner 作的一个决定。必要介入、多余打扰、不必要返工分开。没有代表性案例就直接写明。Owner 无需手工补记每次行为。

## 9. Deferred 能力与研究路线

下列能力均为 **Deferred**。首期接口无需为它们预建空服务、状态机、表或开关。每轮从 G3 证据选择一个瓶颈，写清简单对照、预计新增成本、失败/回退和撤销条件，再按原权限提议。若 Native 足以带来实际收益，优先继续用 Native。

| 候选能力 | 何时值得重新研究 | 重启时保留的边界 |
|---|---|---|
| Decision Model、General Reasoning Selector | 窄映射系统性漏掉可预见且有价值的机会，或选错原则；有简单基线可比较 | 分别比较单次选择、两阶段判断和复用既有映射。不把任务标签当作原则价值。模型输出只能引用当前有效候选，验证身份、修订、允许列表和容量。 |
| 多标签动态选择 | 行为证据表明一条原则不足，存在互补或冲突且对结果有后果 | 复用 Packer，检查最终组合和挤出效应；允许合法空集。旧候选数/置信度阈值只是研究参数。 |
| 复杂 Working Set、三层上下文维护 | 跨轮连续性影响已出现，且仅靠已有上下文无法解决 | INTENT 归 Owner，Workspace Focus 有边界，Working Set 为 Session 缓存；只读无副作用。先定存储归属、过期和并发隔离，不恢复旧提案为授权。 |
| Deferred Refresh | 有足够多可在后续轮次获益的决策窗口，值得承担异步成本 | 不阻塞同步路径；仅应用于后续可验证请求，要求 lease、版本围栏、幂等、失效丢弃及隔离。它不能挽回已经发生的行动。 |
| Model-assisted Shadow / Live | 试用材料足以说明增加推理可能带来净价值，并有比较和停用办法 | 外发授权、独立预算和精确 profile 必须就绪。Shadow 验证选择和成本；行为效果依真实干预验证。先 Shadow 后 Live，各自授权。 |
| 多宿主全面适配，跨模型、跨宿主的全面实验 | 首宿主出现可复用的价值，或环境变化使结论边界成为实际决策障碍 | 每个版本与模式单独验证通道、时限、失败语义和证据。升级模型后核验负迁移。缺乏验证保持关闭。 |

**可选研究对照。** 人工事前选取可估计情境判断潜力；固定精简集检验简单策略；中性提醒对照区分原则内容与一般注意效应。获得足够可重复决策点后，可微随机比较提醒时机；冻结策略后，在新任务、新 Session、不同时间和模型上验证稳定性。撤除干预后的保持实验用于研究内化。这六类研究均由具体问题触发。

优先复用 [Examiner v0.10.1](SPEC-PD-EXAMINER-001-v0.10.1.md) 的隔离、基线、配对和评价能力。其既有“单条原则启用与否”对照不能直接证明动态策略有效；比较选择策略时固定授权集合、RuleCode、模型与任务条件，明确改变了什么。按任务族和时间留出案例，避免同一事故改写同时用于调优和验证；观察者尽可能看不到策略身份。对照主分析保留被分配后的回退、未送达、无响应与未知；对内容效果单独限定证据。预先约定值得部署的收益和不可接受的损害。仅在作统计推广主张时才需要相应样本量、不确定性和重复测量处理。

本表处理旧版所有 ADR。编号仅用于溯源；本期工程接受条件以 §8 为准。旧版安全不变量继续在对应能力的范围内生效，历史阈值和探针结论不自动成为当前生产证据。

| ADR-006、007、014 | **保留归属，暂缓建设** | 不新增上下文权威、不覆盖 Owner 内容；复杂 Focus 维护与 Working Set 方案继续受原 Hold 和存储门槛约束。 |
| ADR-009、016 | **保留，按范围应用** | 精确宿主证据、安全预算和状态纪律约束所选路径；不要求先通过所有宿主的统计发布门槛。旧版已阻断的特定生产路径仍需修复与复验。 |
| ADR-010、012 | **暂缓执行，保留保护条件** | 模型 Shadow、Live 及异步刷新只在各自重新立项后适用。 |
| ADR-013、017、018 | **保留并扩展评价** | 四维交付、合法空集和独立确认仍有效；新增机会分母、行为干扰和 L1/L2/L3 结论边界。 |
| ADR-015 | **修改** | host 事件继续不具备用户意图的语义权威。首期允许共享核心使用冻结的有界事前映射；旧版“必须经过 Decision Model”只属于被暂缓的两阶段候选。 |

**章节和 Gate 迁移。** 旧版 §0–4 的目标、角色和三层上下文由本版 §1–4、§9 重新定界；旧 §5–11 的模型输入、周期复评、选择上限、持久化和开关不进入首期；旧 §12–17 的宿主事实、回执、安全、隔离和预算由 §4–§7 在所选路径执行。旧 §18–22 的数据集、T 系列和 Gate 0–5 不再作为统一开工清单：治理、交付、失败负例映射为 C01–C09，模型、worker、生命周期与跨宿主发布测试随对应能力暂缓；旧 Phase 6 的行为问题提前进入场景卡与每轮复盘。旧 §23–25 的 ADR、状态、自查由本表及 §11 接替。详细历史事实见 [v0.5 原件](PD%20Adaptive%20Activation%20SPEC%20v0.5.md)。

## 11. 当前状态、开放问题与自洽性

**本次完成的是规范。** G0 的实际场景卡与工程批准、G1 的实现与运行证明、G2 的授权试用和 G3 的 Owner 复盘均待后续工作。当前没有 v0.6 L1 宿主验收、L2 行为样本或 L3 因果结论。历史代码与探针仅在原范围内作为定位线索。

| 待决问题 | 影响哪一步 | 最小解决动作 |
|---|---|---|
| Owner 的实际工作是否经过建议的 embedded 路径，哪条有效原则与交付决策对应？ | G0 范围冻结 | 只读核对一个 profile、一份 Artifact 与一个已有工作步骤，不能核对则换窄场景。 |

| 自洽性检查 | 本版落点与结论 |
