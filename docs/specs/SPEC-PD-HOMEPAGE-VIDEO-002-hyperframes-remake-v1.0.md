## 1. 问题、受众和成功定义

首次访问官网、已经使用 AI Agent 的用户，应快速理解：PD 帮自己把反复纠正整理为可审查的行为原则；是否采用由自己决定；原则用于指导后续相似任务；后续表现需要观察，原则可撤回。

现有 36 秒动画用抽象文字卡片解释机制，约 24 秒才进入后续行为；首屏约 450px 宽的播放器使卡片说明过小；审批选项与后续行为之间缺少可见的批准/应用过程。当前线上观看、截图及仓库工程核查支持这些发现，但没有访客测试证明它们对转化率的影响。

本次目标：前 5 秒看到熟悉的具体困扰与期望变化；看完能复述「PD 做什么、我做什么、下次如何使用、如何撤回」。不承诺 Agent 永不再犯，不将示意演出当成实际改善证据。

若跳过：官网继续要求用户从术语和流程自行推导价值。可观察结果：新分镜、可播放双语视频、网站实际尺寸可读性记录和理解测试结果。情绪价值：减少重复教育的疲惫，建立纠正能沉淀、决定权仍在自己手里的感受。

## 4. 固定故事与分镜

贯穿案例：用户只要求修一个按钮，Agent 却扩大到整页重构。纠正沉淀为「超出原任务范围前，先说明影响并确认」。下一次面对相似扩展，Agent 说明额外修改并等待决定。确认只用于超出约定范围的动作，不能暗示所有普通操作都需要批准。

画面持续保留可读的「机制示意 / Illustrative example」，它是说明来源的标识，不是实际产品界面。

| 段 | 时间 | 画面与动作 | 主文案（中文 / English） | 旁白（中文 / English） |
|---|---|---|---|---|
| S1 | 0–4s | 同一任务的以前/后来依次出现；扩大修改用暖色提醒，先说明影响用蓝色强调；不用缩小双栏承载长文 | 只修按钮，却改了整页？ / A button fix became a page rewrite? | 只让它修按钮，却又改了整页。 / You asked for a button fix. It rewrote the page. |
| S2 | 4–8s | 用户纠正气泡→相关纠正聚合；不用固定 3× 阈值；突出原话 | “超出范围，先问我。” / “Ask before expanding scope.” | 你反复提醒：超出范围，先问我。 / You keep saying: ask before expanding scope. |
| S3 | 8–13s | 相同气泡整理为一张原则建议；保留来源线索，突出 PD 在做的事 | PD 整理为原则建议 / PD drafts a principle | PD 将相关纠正整理成原则建议。 / PD turns related corrections into a proposed principle. |
| S4 | 13–17s | 用户审阅一条短原则→明确点击批准→出现经你批准状态；可以修改/暂存作为次要信息 | 你审查，你决定 / You review. You decide. | 你审查、修改，再决定是否采用。 / You review, edit, and decide whether to adopt it. |
| S5 | 17–25s | 明确的下一次相似任务；经批准原则被应用的连接→Agent 发出具体回应；保留任务上下文，不以勾选清单代替行为 | 下一次，先说明再行动 / Next time: explain before acting | 下一次遇到类似情况，原则用于指导行为；是否改善，仍看实际表现。 / In a similar task, the principle guides behavior. Check what actually changes. |
| S6 | 25–30s | 持续可读的收尾卡；产品名、价值、可撤回、网站下一步提示；保持到最后一帧 | 少一点重复纠正。决定权仍在你。 / Fewer repeated corrections. You stay in control. | 少一点重复纠正，决定权仍在你。原则随时可撤回。 / Fewer repeated corrections. You stay in control, and can withdraw the principle. |

S3/S4 短原则：`扩大修改范围前，说明影响并确认。` / `Explain the impact and ask before expanding scope.`

S5 Agent 示例：`还涉及另外两个模块。我先说明影响，等你确认后再扩大修改。` / `This also affects two other modules. I’ll explain the impact and wait before expanding the change.` 可分两次气泡显示。不要额外同时显示整段旁白。

S6 固定产品名：Principles Disciple；类别以 `docs/product/PRODUCT_IDENTITY.md` 和 `docs/concepts/pd-canonical-definition.md` 为准，可在邻近网页文字承载，避免片内堆术语。提示：`在本页选择「开始使用」` / `Choose “Get started” on this page`。视频内提示不是可点击按钮，真正入口沿用首页安装链接。封面可用 `30 秒，看一次纠正如何用于下一次任务` / `30 seconds: from correction to the next task`，语义以最终可读布局为准。

上述为可执行文案基线。为自然口语、TTS 时长或换行可作等义缩写，并在验收记录列出差异；改变故事、产品承诺、审批边界或超出 30 秒目标需先报告并取得确认。不得用加速旁白解决过密脚本。

## 5. 画面、动作、音频标准

### 5.1 以网页播放尺寸设计

- 主交付 1920×1080、30fps。先按 450px 和 350px 宽检查可读性，再决定大画布布局。
- 每个镜头只有一个主要阅读焦点；关键文字建议不小于画布 88px（约等于 350px 播放时 16px），主标题约 104px 起。实际可读性优先于数字合格。
- 解释所必需的信息不能放在微小标签里。长原则分两行；Agent 对话分两次显示。画布四周约 5% 安全边距，底部约 18% 留给原生字幕/播放器；在实际浏览器复核。
- 依次对比优先于双栏长文本。保持现有深墨色、冷蓝强调、暖白文字和本地字体；色彩不能是区分前后的唯一线索。
- 用户气泡、原则卡、批准状态之间有连续的对象关系。动作用于解释整理、批准和后续应用，减少仅装饰性的同心圆和大面积空置。
- 使用真实仓库品牌素材；概念交互明确标为示意，不伪装成现有 Console。不要为了美观虚构功能、接口或真实效果数字。
- 开场第一帧即有有效信息；结束卡至少完整保持最后 3 秒，片尾不淡出为空白。

### 5.2 HyperFrames 制作约束

- 先读项目 `AGENTS.md`、HyperFrames 入口、core、animation/keyframes、creative、CLI 及需要的 media 技能。旧模板与现版本冲突时按实测 CLI 兼容性处理，并记录选择。
- 保留可拖动、可确定性 seek 的时间线。不要以 setTimeout、随机数、实时网络结果或自动播放时钟驱动剧情。
- 在既有项目内工作；避免引入新框架或独立视频服务。先查现有组件/registry 可否覆盖所需动作，再决定小范围自制。
- 用实际安装版本的 help/docs 确认变量和输出参数；为 zh/en 给出两条真实可运行的渲染命令，输出脚本所需的两份母版。
- 当前脚本使用 0.7.24。先执行只读升级检查（若该能力可用），兼容升级后必须验证；升级失败恢复本次版本修改、保留旧 pin 并报告。不要把最新版技能的语法直接套给旧版本。
- 新版以 `check` 为主验证；已有 lint/validate/inspect 包装需根据实际 CLI 一并整理。不能将零检查样本、超时或失效的预览当成通过。
- 旁白独立制作后由现有 FFmpeg 脚本混入成片，是可继续复用的离线制作链路；网页播放时不调用 TTS。

### 5.3 音频和双语

- 延用现有 Edge TTS 作为默认候选；必须实际听完整中英文成片后决定是否适用，不能只凭文件存在判定声音合格。
- 每段旁白需在场景结束前留约 0.3 秒余量；超时先缩短文案。双语允许不同换行和轻微停顿，但共用本规格场景时间。
- 字幕与实际旁白逐字对应，按自然短句切 cue，最多两行；不要把长场景全文塞进单行。现有脚本按场景生成单 cue，需要时在既有清单内扩展 cue 或采用确定性切分，保持字幕时间单一来源。
- 允许保持现有旁白 loudness 目标（脚本为 -18 LUFS、true peak -2 dBTP）；最终用检测和实际听感确认无削波、无抢话、无截断。背景音乐不是必需，不为凑氛围增加采购或外部生成。
- 配音服务不可用时报告明确原因，先保留可用视觉预览。不得复用旧台词充当新配音或标记完成。

## 6. 输出、接入和成本

交付物：更新后的现有工程；新增或更新 `BRIEF.md`、`STORYBOARD.md`、README（记录预览/检查/双语渲染/配音/合成/封面命令）；双语最终 MP4、VTT、WebP；验收报告 `docs/implementation-reports/SPEC-PD-HOMEPAGE-VIDEO-002-acceptance.md`。

沿用 MP4/VTT/海报现有路径。视频 H.264 + AAC、yuv420p、faststart，1920×1080/30fps，总长 30 秒（容器误差 ≤0.1 秒）；每份 MP4 ≤4MiB；海报 960×540 WebP、≤100KiB。保持用户启动、controls、playsinline、preload=metadata、语言正确的默认字幕和可访问名称。两语言全部通过才更新接入产物；临时文件不能作为最终交付。

离线制作输入输出：规格/文案/本地素材 → HyperFrames 双语母版与封面 → TTS 分段音频和 VTT → FFmpeg 双语最终成片 → public → VitePress 首页。时间/字幕沿用现有 manifest 的所有权；画面时间允许必要重叠转场，但必须与其语义场景边界对齐，不创建独立的第二份旁白时间事实。

成本边界：本地渲染和现有 Edge TTS；不启用付费 API、云渲染或外部发布。执行前检查依赖与服务可达性，报告实际安装、生成次数和耗时；不预先承诺完成时长。可先抽帧/低成本预览迭代，完成检查和预览审批后再最终编码。重试需有上限和记录，不后台无限循环。

失败处理：缺字体/LFS 素材先定位补齐；TTS 失败、段长超限、检查失败、预览缺场景、体积超限或字幕不符均不可交付为通过。先在忽略的 renders/临时目录构建完整产物，检查后再替换 public；保留原产物的 Git/LFS 恢复能力。脚本失败可能已写部分字幕，故失败后必须核对所有最终文件，避免新字幕配旧视频。

- 若使用的 HyperFrames 技能要求最终预览审批，在可审阅的完整预览通过检查后，集中请求一次最终渲染批准；获批后连续完成两语言渲染、接入、测试和报告。若 Owner 明确指示不同的预览/渲染方式，以该指示为准。
- PR 按 Owner 要求创建；准备 PR 时依仓库规则搜索/关联已有 Linear 问题、中文记录，并运行所需门禁。发布、合并、线上替换不在本规格授权内。

## 8. 回滚与复杂度

最小回滚：回退本次视频工程、资产、对应测试和必要播放器文字的同一变更集；Git LFS 保留旧资产。不要通过改安装运行时或工作区治理数据回滚。生成前记录基线 HEAD，保留原有未提交文件，不用 reset/clean 清理他人工作。

Complexity Delta：新持久事实源 NO；新持久状态/数据库 schema NO；新子系统/服务/后台进程 NO；新公开产品接口 NO；新运行时开关 NO；新跨包依赖 NO；新宿主平台行为 NO；新外部网络能力 NO（沿用已有制作时 TTS/包下载，不增加网站播放时服务）。制作清单/brief 属于工程内容，不是产品治理事实源。

## 9. 验收报告最少字段

问题和最终行为；实际 HEAD/变更范围；复用清单；实际 CLI/依赖版本；双语文件路径/大小/哈希/媒体参数；命令与结果；场景与实际网站截图；完整视听结果；实际文案偏差；失败和修复；人测状态；未完成项；回滚方式；Complexity Delta。分别写清 `工程检查 / 浏览器视觉 / 音频听检 / 人测 / PR / 发布` 状态，不用一个 PASS 代替全部。
