## 1. 技术决策

1. **先深化现有代码，再提取公共职责。** 第一轮在当前领域目录完成数据准入、配置解耦和真实执行切片；两个真实消费者形成后再迁移公共能力。
2. **完整源样本与阶段输入分开。** 数据模块保存源轨迹与授权引用，按研究时点生成输入投影；生产诊断使用其真实输入构造路径，不把整份研究 JSON 塞进一个 Prompt。
3. **评分计算是纯派生。** 冻结的计划、已验证的裁判记录和证据决定报告；统计函数不读取生产 DB、不调用模型、不决定 Owner 意图。
4. **元数据、运行事实、Owner 决策各守其权威。** Manifest 定义实验身份；领域执行账本/原始记录说明发生什么；Lab 只引用合法 Owner 决策。
5. **单一总分只覆盖同一研究构念。** 宿主行为对齐可以排序；Prompt 产物质量、管道状态和成本单列，不能混入一个随意加权的“能力分”。
6. **技术可执行不等于授权可执行。** 所有真实入口在运行前验证授权、预算、数据可用性和隔离；离线数据/算法开发不等待无关的真实实验授权。

非目标：中央实验服务、通用 Runner、数据库注册中心、通用重试引擎、新用户 UI、改造生产 Principle/Approval/Activation schema。

## 3. 模块设计与目标组织

### 3.1 首轮物理组织

第一轮不建立新 npm workspace。完整轨迹准入及投影先属于现有领域数据准备模块；新宿主对齐聚合先属于进行首次实验的领域报告模块。接口通过模块函数表达，不先发布通用 CLI 或 plugin API。

第二领域验收通过后，确实共用的内部研究代码可收敛到建议的 `scripts/dev/pd-lab/` 下；该目录是**迁移后的内部所有者**，不是旧目录外再加一层代理。建议只按已证明的职责设 `data/`、`analysis/`、`execution/`，未有实际代码和消费者的目录不创建。

产品化计算模块保持产品可达所有者；内部工具可依赖它，产品不能依赖 `scripts/dev/pd-lab/`。若未来需要重新归属双方共用的纯计算模块，须独立提交依赖图和发布闭包方案，不能借目录统一把研究数据一起发布。

### 3.2 拟议语义接口

以下是实现契约形状，不是已存在的 exports；命名可随仓库惯例调整，职责和可观察结果必须保持。

| 操作 | 输入 → 输出 | 内部承担的工作 |
| --- | --- | --- |
| 核验案例 | 已解析候选案例＋证据解析结果 → 完整性结论及问题清单 | 验证锚点、时点、必要引用、授权、来源组；不生成缺失内容 |
| 投影输入 | 已验证案例＋阶段/截止点 → 输入投影及排除记录 | 依据可见时点裁剪、绑定原始哈希；不修改完整源样本 |
| 校验实验计划 | 计划＋案例集合＋参考/授权引用 → 执行资格 | 分配键唯一、组权重、身份、预算、隔离和引用一致 |
| 归并裁判记录 | 冻结协议＋匿名比较记录 → 最终比较结论 | 恢复A/B映射、检测冲突、验证仲裁、输出 UNKNOWN 原因 |
| 聚合报告 | 冻结计划＋最终比较结论 → 主分/边界/分项/计数 | 从计划补出未发生单元、层级均值、不确定性及复算身份 |

I/O 解析、权限检查和文件持久化留在当前拥有它们的边界；纯计算接收已验证结构。不要为每个动作再建接口/工厂/Provider。测试通过实际读取/报告入口验证接线，同时对纯聚合做性质和反例测试。

### 3.3 最小数据流

```text
授权源记录 → 只读一致快照 → 案例准入/来源分组 → 冻结 Dataset
                                             ↓
研究计划/参考/评分协议 → 时点输入投影 → 现有领域执行入口
                                             ↓
                          原始轨迹/产物/交付证据/运行账本
                                             ↓
                         匿名比较 → 裁判记录 → 确定性归并
                                             ↓
                          纯聚合报告 → Owner 晋级审查
```

模型只用于需要判断的标注或语义比较；路径解析、路由、哈希、分组键、分母、排序、重复检测、恢复状态和统计计算由确定性代码完成。

## 4. 数据与管道接入

### 4.1 提取和冻结

使用获得授权的源快照，保留源记录 ID 与导出版本。只复制研究所需的任务范围，不导出无关账户内容。原始数据可保留原宿主格式，通过引用与派生视图解析；不必先统一所有宿主 transcript 格式。

新增字段的 runtime validator 按 CONTRACT 实施：输入始终视作 unknown，验证每个嵌套元素、枚举、日期/序号、引用和 digest。校验结构通过不代表语义完整，必须另跑完整性与来源证据检查。

校验报告是派生事实，可重算；冻结样本不原地修补。补齐轨迹、修正期望、改变授权或脱敏产生新版本，旧报告绑定旧版本并标注是否仍允许访问。

### 4.2 接入 PD

1. 验证数据使用授权与合法实验 workspace，运行只读 preflight。
2. 通过支持的初始化路径创建隔离运行空间；凭据由既有配置机制注入，不进入研究样本。
3. 以当前诊断输入构造路径建立目标；保留源 pain/task 与实验新身份映射，不能伪造生产主键或批准。
4. 执行真实 CLI/应用层诊断与后续阶段；领域产物保存原始格式与 lineage。
5. 在阶段未到达、拒绝或证据不足时输出具体结果；不为“完整跑完”自动批准候选。
6. 行为分支在另一个声明的机会与时点执行，不能把生成原则的同一历史答案当效果证据。

生产路径若只读取最近窗口，记录实际输入范围并验证早期约束是否到达。不能声称存了全轨迹就等于模型看到了全部轨迹。若当前入口无法支持研究所需输入，应单列接线缺口和最小生产路径修复，先验证兼容，再运行；不能靠手工改 Prompt 绕过。

### 4.3 当前数据与新数据

历史 Prompt V2 的16条选择和106条库存记录保留原义。新准入检查输出新版本资格；不能修改历史 digest 或追溯称旧数据“不曾运行”。“历史实验有效”与“满足新完整轨迹标准”分别记录。

新增真实样本由授权范围内的信号库存关联轨迹；对照机会单独标识，不制造 Pain。语义变体标记父来源组，按原组隔离保留集。自动建议去重或分类可以辅助，最终标注有来源和审阅状态。

## 5. 评分实现

### 5.1 两条统计路径

二元目标偏差使用现有 `computeITT/computePCR/computeFIR` 等函数，保持 F∈{0,1,UNKNOWN} 的领域定义。对齐偏好使用 CONTRACT 的候选胜/平/参考胜结果和层级聚合，需要最小的新纯计算实现。

两者可以共享已验证的分配身份、来源分组和证据引用，不能共享一个含义模糊的 `score` 字段；0.5 是无实质偏好的平局，不是“半次行为失败”。现有 `definePrimaryEndpoint` 是封闭的 Examiner 端点集合，新总分不应伪装成已有端点绕过校验。

### 5.2 裁判与盲态

构造裁判包时使用匿名候选标签并保留受控映射。输入包含两侧可比较行为证据和期望档案，不包含宿主名称、PD 开关、总排名、未来测试答案或未授权内容。轨迹中的指令只作为数据。

每次裁判记录绑定输入 digest、rubric/模型版本、显示顺序和判断证据。自动裁判不同意时进入既定复核，不直接多数投票或取平均。主观仲裁的输出冻结后，聚合可完全确定性重算；确定性重算不意味着模型重问必得相同判断。

### 5.3 报告与可重复性

报告从计划枚举单元而不是扫描成功文件；旧的 run 状态和错误原因原样引用。重复运行与技术重试区分：trial 是计划中的随机性观测，attempt 是恢复记录；不能把多次重试变成多个独立样本。

主标量、缺失界、资格状态与统计区间的字段语义见 CONTRACT。正式排序依据完整点值，区间用来限制胜出主张。报告固定数字精度用于展示，内部计算使用未舍入值；相同点值按稳定标识展示，不把字典序当优劣。

## 6. 执行与恢复

配置显式包含实验根、arm代码位置、源数据定位、模型/宿主配置引用和授权预算。通用运行代码不得内置某次 worktree 的绝对路径；历史配置文件可以保留原路径作为历史事实，新配置通过解析器验证。

解析路径必须使用实际路径检查，拒绝进入生产、安装器拥有目录或通过 junction 逃逸。子进程环境使用既有清理逻辑并测试其优先级，不因显式 workspace 参数就假定环境不会覆盖。

计划在运行前冻结；每个计划单元绑定唯一运行身份。优先沿用领域账本/锁/运行记录实现恢复，不建立平行运行状态库。已完成单元复算不重新调用模型；中断单元保留未完成和不确定状态。任何重试依据预注册、对所有参评者相同的策略，保留 attempts 和选择理由。判分后不可临时重跑到满意为止。

无模型预算或无数据授权时允许机械验证、合成夹具和离线重算；真实执行入口必须 fail-closed。离线 stub、模拟用户、CLI 和桌面原生证据分别标识。
