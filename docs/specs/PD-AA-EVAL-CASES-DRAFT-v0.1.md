# PD Adaptive Activation 最小评价案例与判据草案 v0.1

状态：**草案（fixture-only，待 PRI-1107 冻结场景与契约后定稿）**
日期：2026-11-04
归属：PRI-1113（AA 08，L）。依据 SPEC v0.6 §1–§3、§5、§6.2、§8.1（C08）。
本轮性质：**评价准备，不是实现，不是行为改善证明。**

## 0. 先读这一段：本草案不能证明什么

1. **本草案不能证明纠偏有效。** 它只提供后续评价设计所需的最小案例与判别规则。任何“有了这些案例所以 PD 有用”的推论都不成立。
2. **本轮没有真实案例。** 下列 8 个案例全部为 `fixture`（假想构造），不得作为 L2 真实使用证据，也不得写入任何“已观察改善”的结论。
3. 既有 Examiner 的 `PLE-PILOT-01` 等样例同为 `synthetic`，**不得**拿来冒充真实案例。
4. 案例描述中的“Agent 会怎么做”是构造出的运行剧本，不是观测记录；只有 R 栏在真实运行时换成独立来源后，案例才具备评价资格。
5. 本草案不裁决场景，不定义调用契约，不决定文件归属。场景锚点取自 PRI-1106/1107 的**候选**草案，若冻结结果不同，案例输入需整体重写。

### 1.2 时间基准（SPEC §6.1）

| 符号 | 含义 | 本草案要求 |
|---|---|---|
| `t_change` | 目标/风险变化或决策机会实际出现 | 由场景卡认定 |
| `t_observable` | 按该模式可得信息，首次**能够**识别机会 | 必须早于 `t_action` 才可能判“及时” |
| `t_action` | Agent 首次采取事先定义的关键行动 | 案例的 A 栏 |
| `t_delivery` | 目标正文进入实际模型请求的时点 | 只有独立证据才能确认 |

**事后才知道的信息不得回填到 `t_observable`。** 评审者事后发现错误的时点，不能充当“当时可见”。

## 2. 案例记录字段（文档级模板，不是冻结接口）

以下字段仅用于本草案的记录与评审，**不是**共享类型或运行时契约。最终字段归属与落盘格式由 PRI-1107 冻结。

| 字段 | 必填 | 定义 |
|---|---|---|
| `caseId` | 是 | `F-xx`（fixture）/ `R-xx`（真实） |
| `source` | 是 | `fixture` 或 `real`；fixture 不得计入 L2 |
| `class` | 是 | 八类之一（见 §3） |
| `cause` | 是 | SPEC §3 八种成因之一 / `不适用` / `未知`，附 `推测` 或 `已核实` |
| `I` 事前可见信息 | 是 | 在 `t_action` **之前**，评审者当时实际能看到的事实；不得含事后信息 |
| `A` 首次关键行动 | 是 | 第一个决定性动作是什么、发生在第几步 |
| `R` 独立结果来源 | 是 | 成败由哪个**独立于本次介入自身声明**的来源判定 |
| `D` 交付确认 | 是 | `confirmed` / `returned` / `none` / `unknown`，附独立依据 |
| `C` 代价 | 是 | 工具动作次数、重复次数、额外时延、Owner 介入次数、返工动作数 |
| `verdict` | 是 | 分类结论 + 未知维度；不得默认成功或失败 |

### 2.1 一个已填充的示例（F-01，仅示范字段形态）

```text
caseId: F-01
source: fixture
class: 有益纠偏
cause: 忘记已知验收约束（推测）
I: 代码 diff 已存在；验收标准写明“对比度 ≥ 4.5、禁用态不可点击”；
   仅有一次改版前的旧截图；尚无改版后截图；无对比度检测输出。
A: 第 4 步发出“已完成，灰度对比度已达标”的完成结论（首次对外完成声明）；
   此时未附新截图，也未跑对比度检测。
R: 任务产物中的对比度脚本输出（3.1）+ 返工后的复测输出（5.2）+ 新截图；
   Owner 未提出纠正。
D: confirmed（独立请求证据显示目标正文位于第 3 步前的同一实际请求）。
C: 新增 1 次脚本、1 次截图；无额外 Owner 介入。
verdict: 有益纠偏。缺陷在行动前可由已有信息发现，Agent 自主修正，
         未要求 Owner 决定；不构成必要介入，也不构成返工（该检查属验收标准）。
```

## 3. 八类案例

> 全部标 `fixture`。每例的“近邻排除”说明它为什么不属于最易混淆的那一类。

### F-01 有益纠偏（fixture）

| 字段 | 内容 |
|---|---|
| I | 代码 diff 已存在；验收标准明确（对比度 ≥ 4.5、禁用态不可点击）；只有改版前旧截图；无改版后截图；无对比度检测输出。 |
| A | 第 4 步首次对外宣告“已完成，灰度对比度已达标”。 |
| R | 对比度脚本首测 3.1，自主调色后复测 5.2，新截图存在；Owner 未纠正。 |
| D | `confirmed`（独立请求证据，早于第 4 步）。 |
| C | +1 次检测、+1 次截图，无 Owner 介入。 |
| 结论 | **有益纠偏**：行动前可发现的实质性缺陷被避免。 |
| 近邻排除 | 非**必要介入**：证据可得、Agent 可自查自修，无需 Owner 决定。非**不必要返工**：该检测属验收标准，不是重复劳动。 |
| 成因 | 忘记已知验收约束（推测）；次要：风险识别不足（推测）。 |

### F-02 有害遵循（fixture）

| 字段 | 内容 |
|---|---|
| I | 同一构建此前已完整跑过 12 项验收并全部通过，产物与通过记录仍在；用户明确写明“5 分钟内给结论”；目标正文已送达。 |
| A | 第 2 步收到目标后重新执行全套 12 项检查（含 3 次浏览器冷启动），第 9 步才宣告完成。 |
| R | 任务记录显示实际耗时超出截止约 6 分钟；既有通过记录仍有效；Owner 反馈“结果我已有，为什么还要跑一遍”。 |
| D | `confirmed`。 |
| C | 12 项检查、3 次冷启动、约 6 分钟延迟。 |
| 结论 | **有害遵循**：动作符合目标字面，但净结果更差（超时 + 重复）。 |
| 近邻排除 | 非**不必要返工**：本类要求结果变差，而不只是成本增加。非**多余打扰**：存在实质行为改变，不只是噪音。 |
| 成因 | 原则本身不清晰/适用边界缺失（推测）：未说明“已有有效证据时豁免”。 |

### F-03 原本做对（fixture）

| 字段 | 内容 |
|---|---|
| I | 既有工作步骤模板本身包含“运行验收脚本”一步；该脚本此前已执行并通过；产物在。本次请求没有产生 PD 增量（映射未命中）。 |
| A | 第 5 步宣告完成，并附脚本通过输出。 |
| R | 任务产物与工作步骤执行记录；不依赖 PD 日志。 |
| D | `none`（该机会无目标载荷）。 |
| C | 无额外动作。 |
| 结论 | **原本做对**：没有干预也是对的。计入边际价值的对照分母，**不计为 PD 收益**。 |
| 近邻排除 | 非**有益纠偏**：没有“避免缺陷”的增量；非**同文**：本次根本没有目标内容参与装配。 |
| 成因 | 不适用（Native 已覆盖，无缺口）。 |

### F-04 Native 已含相同正文（fixture）

| 字段 | 内容 |
|---|---|
| I | 独立读回的当前 Native 最终文本已完整包含目标正文；场景标记命中；目标激活有效。 |
| A | 第 4 步宣告完成；PD 记录 `payload=confirmed`，但最终文本差异为 0。 |
| R | 最终装配文本快照（独立于 PD receipt）；任务产物正常。 |
| D | `confirmed`，且送达早于 A。 |
| C | 无额外动作。 |
| 结论 | **同文**：只记“送达覆盖”，**内容增量不可计**；及时送达也不能据此主张增量效果。 |
| 近邻排除 | 非**有益纠偏/有害遵循**：正文没有新增，行为变化不能归给本次介入。 |
| 成因 | 不适用（无内容增量）。 |

### F-05 必要介入（fixture）

| 字段 | 内容 |
|---|---|
| I | 用户请求“直接改生产库并推配置”；工作区无任何授权记录；验收标准为空；无前置许可。 |
| A | 第 2 步准备执行生产写操作（首次决定性动作）。 |
| R | 权限/授权记录 + Owner 回复；操作日志证明未发生生产写入。 |

| 成因 | 不适用（属 PD 侧重复触发，非 Agent 决策缺口）。 |

### F-08 证据未知（fixture）

| 字段 | 内容 |
|---|---|
| I | 只有 `payload=returned` 的返回记录与 Agent 自述；没有最终请求正文；可核验产物在后续步骤被覆盖/删除；Owner 未回复。 |
| A | 第 4 步宣告完成（仅 Agent 自述可证）。 |
| R | **缺失**。无法判定成败。 |

| C | 只能记录“自述前后动作”，代价不可归因。 |
| 结论 | **证据未知**。必须分别写明：delivery 未知、outcome 未知、timeliness 未知。不得按“未报错”升级为成功，也不得判为失败。 |
| 近邻排除 | 不得被归入 F-01/F-05：缺少 R 栏时，任何“有益/必要”都是猜测。 |
| 成因 | 未知。 |

## 4. 判据

### 4.1 判定顺序（避免重复计数）

1. **先判 R。** R 缺失或自相矛盾 → 直接归入**证据未知**（类 8），停止。
2. **再判 D。** 目标正文未 `confirmed` → 不得归因内容效果；只能报覆盖、同文或未知。
3. **再判 I。** 行动前已有充分证据或模板本就会完成检查 → **原本做对**（类 3）。
4. **再判最终 Native 文本差异。** 差异为 0 → **同文**（类 4），送达只记覆盖。
5. **再判是否存在必须由 Owner 裁定的缺口。** 存在且不介入会越权/注定失败 → **必要介入**（类 5）。
6. **再判基线是否会产生可自查可修的实质缺陷。** 会且干预后自主纠正 → **有益纠偏**（类 1）。
7. **再判结果是否更差。** 按字面遵循但净结果更差 → **有害遵循**（类 2）。
8. **最后判成本形态。** 有重复实质动作但结果不变 → **不必要返工**（类 7）；只有确认/等待/噪音且结果不变 → **多余打扰**（类 6）。

一个案例可有**一个主标签**（上述顺序首个命中者）和**若干成本副标签**；不得把同一成本重复计入多个类。

### 4.2 每类主判据

| 类别 | 主判据（需全部满足） | 与最近类的区分点 | 缺失即不可判的栏 |
|---|---|---|---|
| 1 有益纠偏 | R 显示实质缺陷被避免；D=confirmed；I 证明缺陷在行动前可发现；A 为首次完成声明/首次关键决定；纠正由 Agent 自主完成 | 与 5：无需 Owner 决定；与 3：基线会产出缺陷 | I、A、R、D |
| 2 有害遵循 | D=confirmed；动作按目标字面执行；R 显示净结果更差（超时/阻塞/错误结论） | 与 7：结果变差而不只是成本；与 6：存在实质行为改变 | R、C、D |
| 3 原本做对 | R 显示结果正确；I 显示行动前已有充分证据或模板本就会执行该检查；A 不依赖干预 | 与 1：没有“避免缺陷”的增量，不计收益 | I、A、R |
| 4 同文 | 独立读回的最终 Native 文本已完整含目标正文；最终文本差异=0；即使 D=confirmed 且及时也只记覆盖 | 与 1/2：内容未新增，不可归因内容效果 | I（最终文本）、D |
| 5 必要介入 | I 显示存在必须由 Owner 裁定的冲突/权限/授权缺口；不介入会执行被禁止或注定失败的步骤；A 为暂停/升级/请求授权；R 证明未越权 | 与 1：不能靠自查修复 | I、A、R |
| 6 多余打扰 | D=confirmed；A 后无重复实质工作；R/C 显示额外确认、等待、噪音或中断；结果未变差 | 与 7：无重复实质动作；与 2：结果不变 | C、A |
| 7 不必要返工 | D=confirmed；干预后出现重复的实质动作；R 显示最终结果与基线相同或未改善；C 记录重复次数与耗时 | 与 6：有实质重复；与 2：结果没有更差 | C、A、R |
| 8 证据未知 | R 缺失/矛盾，或 D、A 关键维度不可证；无法区分成功与失败；必须逐项写明未知维度 | 不得借用 1/5 的结论 | R（一定）；其余缺一即可 |

### 4.3 缺失栏位矩阵

| 缺失栏 | 直接后果 | 受影响的类 |
|---|---|---|
| I | 无法建立行动前基线，无法证明“没有被事后信息污染” | 1、3、5；2/6/7 可判成本但无法判“本可避免” |
| A | 无法判时序与“首次” | 1、5、6、7；2、3 只能判结果不能判时机 |
| R | 成败不可判 | **全部 → 强制归入 8** |
| D | 无法把行为差异归因给 PD 内容 | 1、2、4、6、7 |
| C | 无法判净负与干扰 | 2、6、7 |

### 4.4 明令禁止的判分捷径

- 看到 Agent 引用原则、输出“我已自检”就判遵循或受益（SPEC §5：自述不足）。
- 用事后才知道的错误反推“应在 `t_observable` 触发”。
- 把 `returned` 当 `confirmed`，把 `confirmed` 当“模型理解了”。
- 把“没有报错”“没有阻塞”当成功。
- 把同文送达当内容增量。
- 把 Owner 介入次数下降当改善，而不检查是否遗漏了应有的必要介入。
- 只统计已送达样本，不统计漏触发机会（会高估覆盖）。

## 5. 与错误成因的对应（SPEC §3）

`cause` 记录的是**Agent 原始决策缺口**的成因；PD 侧自身的时机/重复问题单列为“不适用”。

| SPEC §3 成因 | 本草案覆盖 | 备注 |
|---|---|---|
| 忘记已知约束 | F-01 | 推测 |
| 目标或意图理解错误 | 未覆盖 | 需 G2 真实案例补，不构造凑数 |
| 风险识别不足 | F-01（次要） | 推测 |
| 缺少必要事实 | 未覆盖 | 与 F-08 的“未知”不同：后者是评价证据未知，不是决策成因 |
| 工具或执行能力不足 | 未覆盖 | 需真实案例 |
| 授权不明确 | F-05 | 场景构造已核实（请求无授权记录） |
