## 两种模型到底是什么

这两个名称是 PD 中的职责，不是厂商产品名或两种必须不同的模型架构。

- Decision Model：对比有来源的前后任务上下文，判断 SAME_TASK、NEW_TASK、GOAL_SHIFT、PHASE_SHIFT、UNCERTAIN，返回短摘要与事前依据。目标是低成本、低延迟、可靠结构输出；不读全套原则、不选择原则、不决定 Owner 的真实意图。没有 previousTask 时不能假装知道任务未变。
- General Reasoning Selector：理解当前目标、工作阶段和抽象原则的关系，从当前授权候选中选择引用或弃选。较强的通用指令/推理模型承担此角色；它不是实际执行任务的 actor。试点暂限单条原则，不声称已解决多原则组合。
- 同一个模型可承担两个角色；只有提示与输出契约不同。先不训练专用模型。所谓“决策模型免费”，指承担第一项职责的模型有免费托管额度，或者权重可本地运行，不代表判断质量有保证。

原文依据：v0.5 §5.6–5.8、§6、§10.3，特别是“Decision Model does not need to understand abstract principles”。

## 自评发现与修正

1. 职责混淆：删除阶段一 selectionNeed 与原则候选输入；由阶段二负责适用性判断。
2. 缺状态的虚假节费：当前不建 Working Set，无已验证可复用选择，SAME_TASK 不能跳过第二阶段。首个 D 臂是任务理解中间步骤的消融，通常2次调用，对比 C 的1次；不声称已经验证完整门控机制。后续门控需有效选择复用与误跳过评估，另审方案。
3. 假设适配器天然单请求：现有 PiAiRuntimeAdapter 配置 maxRetries 默认2、maxRepairAttempts 默认3，且输出路径存在降级。设置 maxRepairAttempts=0 不足以证明单请求。实施需在网络传输边界计数，并约束重试、修复、输出路径切换和token缩减再试；复用既有 seam，若无法限额先提交最小缺口。
4. 结构正确不等于语义正确：strict JSON 仅减少格式错误，不能证明目标识别或原则选择正确。先以反例评价阶段变化、缺上下文、引用伪指令、同任务关键决策变化和原则过度干扰。
5. 经济价值不由免费API推出：云端免费也有配额、排队和可用性成本。首个 D 消融还增加请求。只有语义收益达到事前标准才继续；没有收益优先 C。等后续确有有效选择复用，才讨论门控节费的 break-even：C_decision < (1-p_refresh)*C_selector（另加重验、延迟与错误代价）。
