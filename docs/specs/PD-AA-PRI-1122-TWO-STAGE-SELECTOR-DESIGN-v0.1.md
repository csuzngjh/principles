## 1. 目标与问题定义

目前固定标记只能把指定原则可靠装配，不能自主识别原则需求。这里研究：在不同任务、当前目标与工作阶段下，模型是否能找到值得提醒的已有原则；在同样预算下，两阶段是否优于一次直接选择，并最终改善工作行为。

两阶段是待证假设，不是既定赢家。首先实现候选方案的小范围比较，不新建 Working Set、长期记忆、异步刷新服务或多原则冲突引擎。与 PRI-1110 配置身份及现有闭环并行，不等待 1–2 周真实观察结束，也不绕过其治理和送达验收。

最小版本每个机会最多优先一条原则，但候选可以来自不同领域，不固定某一条 ID；多原则组合仍是 PRI-1123 的独立方向。这一限制复用现有单目标装配接口，避免把选择器试验变成重做运行时。

规范关系：v0.6 §9 原先将本方向 Deferred；Owner 本轮同意的是提前并行研究，未改写 v0.6 首期价值判断。v0.5 §5.6–5.8 的任务/目标/阶段变化判断和 §6 的原则适用性提供研究起点，不自动恢复旧 Working Set/异步服务为现行授权。

## 3. 最小调用链与职责

```text
当前可信准入 + 事前可见任务上下文 + 明示目标/阶段（可未知）
 → Runtime V2 授权候选快照与候选预算
 → 阶段一 Decision Model：任务、目标或阶段是否变化？
 → 首个无复用状态试点继续阶段二 General Reasoning Selector
 → 在本次候选中返回一个引用或明确弃选
 → 确定性校验、截止校验、同源重验、现有 packer
 → 最终正文与调用证据；失败则 Native
```

确定性代码负责路由、预算、重试上限、解析、资格、ID匹配、去重和回退；模型只做语义判断。现有安全/治理约束始终独立执行，不由阶段一决定要不要执行。

### 输入边界

- opportunityRef：真实工作区、Session、当前准入引用。宿主缺可靠身份时只允许隔离离线样本，不能假装支持本地 embedded 实时接线。
- currentInput：当前消息与有限的事前工作上下文；引用、工具输出、历史消息与当前指令明确分层。
- 初始上下文上限提议沿用 v0.5 研究参数：最近最多6条有效消息、12000字符，超限保留最新完整消息边界；既有任务/阶段摘要仅在有来源时输入。候选文本另设总字符预算，不以随意截断正文代替语义保真；具体上限连同profile在实现前确认。
- intent：Owner 明示长期目标、任务目标与阶段及来源；缺失写 unknown，不让模型补造 Owner 意图。
- candidates：本次已授权且有效候选的 Artifact/Activation、完整内容摘要、必要的原则文本。只有阶段二读取原则候选；C 单模型与 D 阶段二使用同一有界候选视图。阶段一仅读取任务、目标、阶段及其事前来源，不判断抽象原则适用性。
- budget：统一绝对截止、候选内容上限、最大输出、剩余额度、必需保留约束；由执行器传入，模型不能修改。
- binding：输入快照摘要、候选集合摘要、配置身份、实验臂及协议版本。任何输入/候选修订变化使旧响应不能复用。

候选数量/序列化字符预算须在实现前按现有 Reader/packer 容量核实并冻结；大候选集的截断顺序和遗漏必须各臂一致并记录。第一版不增设模型召回器或检索索引，候选外原则漏选单独记为覆盖限制。

### 阶段一：Decision Model

输出结构包含 `changeType = SAME_TASK / NEW_TASK / GOAL_SHIFT / PHASE_SHIFT / UNCERTAIN`、当前任务/阶段的有据短摘要、允许的短原因码和输入片段引用。仅做任务、目标与阶段的语义判断，不增加 selectionNeed 字段，不判断原则是否有价值。它不改变原则授权，不生成原则，不输出最终目标 ID。缺少有据 previousTask 时不能伪造可靠的 SAME_TASK；应标 UNCERTAIN。

首个试点未实现持久有效选择的复用，因此所有 changeType 在预算允许时均进入阶段二；D 测试任务理解中间步骤是否改善选择，不能宣称通过跳过阶段二节费。若以后研究门控，必须先有经身份、有效期、授权和上下文重验的可复用选择，并单独评价误跳过。SAME_TASK 本身不足以省略阶段二，UNCERTAIN 也不等于无原则适用。模型自报 confidence 仅作诊断。

没有可靠当前输入、阶段一出错或预算耗尽时，记录 unavailable/degraded 并回 Native，不生成合法 none_applicable 来掩盖故障。后续引入门控时，阶段一误跳过必须独立抽查。

与旧 v0.5 的有意差异：本试点不新增持久 Working Set，因此不承诺跨轮保留上一选择，也不把 SAME_TASK 用作门控。所有状态在预算内进入第二阶段，缺失状态如实记录。此差异是明确的最小消融实验取舍；未来门控/跨轮节费另需方案，不能把本试点外推为已实现完整 v0.5 动态复用。

### 阶段二：通用推理原则选择器

输出 `selected / none_applicable / uncertain`；selected 必须返回本次候选中的唯一 Artifact/Activation 引用、候选内容摘要及简短事前依据。它从不同任务/原则中选择一条，不照抄模型编造的原则正文。

模型返回新ID、多个目标、不可解析结构或过期摘要均不自动修复为成功。none_applicable 是模型判断，仍需独立评价是否漏选；uncertain 采用 Native，不强行选一条。最终确定性校验的状态与模型声称的状态分开保存。

## 4. 成本、失败与回滚

- 两阶段每机会最多 2 次 selector 模型请求；一次直接选择臂最多 1 次。必须在真实适配器请求边界证明上限：底层 maxRetries 默认2、maxRepairAttempts 默认3，且存在输出路径降级，不能只在调用方写“0重试”便宣称没有额外请求。禁用所有附加调用或明确暴露单请求路径，fake transport 统计实际发出次数；失败保持样本分母。
- 合计用同一个绝对截止，不给两个阶段各一份完整超时。阶段一、阶段二、候选读取/装配耗时分别记录，取消传到底层适配器；只做 Promise race 不足以约束同步等待或外部调用。
- 配置缺失、请求拒绝、结构错误、预算不足、撤销/修订、过期响应均回 Native。阶段二失败不能借之前成功结果或其他 Session 的响应。
- Native 已有同文：addedTarget=false，不能计新增干预收益。预算不允许或必需约束会被挤掉：不注入额外目标，保留现有治理和回退语义。
- 候选文本与输入均可能含提示注入，不能指示模型扩大授权或改变 schema。日志只存白名单引用、摘要、阶段、时长与有限原因，不保存模型私有推理链、密钥或任意全文。
- 首个实现仅隔离研究入口。未来接宿主需明确缺消息身份、尾部延迟、配置身份和独立送达限制；不默认改生产默认值。
- 回滚：停用研究入口/回退本次实现提交；不触及治理记录、旧研究包或安装。没有新持久化迁移、worker、自动配置写入。

拟议隔离实验的单机会 selector 合计截止 10 秒、actor 截止 60 秒，均为待批准的初始上限，不是当前宿主性能结论。token/字符上限须随具体 profile 冻结；未知币价不得填0元。

## 5. 对照协议：选择质量与行为价值分开

四臂共享同一事前任务状态、候选快照、原始 Native、actor 模型版本和工具能力：

| 臂 | 选择机制 | 作用 |
|---|---|---|
| A | 原始 Native，无额外选择 | 判断干预本身是否有益 |
| B | 现有显式固定映射 | 检查简单方法已能解决多少问题；无标记时不偷偷提供触发信息 |
| C | 一次通用模型直接选择 | 判断两阶段是否真的值得额外复杂度 |
| D | Decision Model → General Reasoning Selector | 任务理解消融方案；当前无门控，不宣称节省调用 |

阶段二先与 C 使用同一模型/候选协议，阶段一模型独立标识；不得把强模型升级、更多候选或更大预算的优势归因到“两阶段”。同时报告相同硬预算下质量，以及实际调用、token和延迟成本；当前 D 通常两次、C 一次，D 必须证明额外质量收益，而非预设更省钱。不同模型的实验另列，不混算。

先做离线选择评价；再用固定 actor 在独立复制的任务/工具环境里行动。随机化各臂次序，每个 actor 运行新 Session、无跨臂产物/缓存/会话复用。只有确定性只读场景才可共享环境。

每条链单独记录：机会可观测性 → 模型选择 → 最终装配 → 独立请求正文确认 → 首次关键行动 → 任务结果。离线模型选择正确不等于真实宿主送达，actor stub 不等于真实行为改善。门控漏选、场景外干扰、无效/有害遵循、工具/模型失败、超时、同文零增量均保留。

### 最小样本准备（尚未执行）

先准备 12 个开发场景与另 12 个留出场景，不重写历史 EXM/Gold：

1. 明确交付验收、原则适用但 Native 未含目标。
2. 普通事实问答、没有额外原则价值。
3. 引用/历史中出现验收标记，当前任务不是验收。
4. 工作由实现转为验收，事前信息足够与不足两个变体。
5. Owner 明示长期目标与局部捷径冲突，以及目标缺失的未知变体。
6. 两条均可能相关但只有一条有可观察行为收益；允许多种合理答案而非唯一ID oracle。
7. 高风险行动的既有安全约束不得被门控略过。
8. 原则已在 Native，选择相同目标但不能计新增收益。
9. 候选撤销、正文修订或候选视图不完整。
10. 请求重放、过期响应、跨 Session 的相同文本。
11. 延迟/预算不足时保持任务可继续。
12. 原则表面相关但会造成过度检查、返工或目标偏离。

以上只是场景种子，不是已经形成的24条测试或已审定Gold。留出场景由未参与调参的人准备/封存，实施者冻结提示与版本后才读取；数据来源、授权和去重分组都写入清单。

事前评价约束先冻结：允许目标集合或弃选、可观察行为签名、任务成功条件、不可接受干扰和未知条件。评分者看行动/产物，先隐藏选择理由与实验臂；不把原则引用、长解释或自述算成功。分歧保留并列证据，不让选择模型兼任唯一裁判。

### 试点预算与判定

拟议首轮对 24 个场景各臂执行1次，不做自动重试。A/B 无 selector 调用；C 24次；D 最多48次；actor 最多96次，总计最多168次请求（包括失败尝试）。只做选择阶段时最多72次，不能默认顺带消耗actor额度。真实运行前需另批模型/provider、单次token上限、总费用、总时长、端点/数据范围、停止与清理卡；旧两次宿主实验额度不可复用。

24个场景只能做探索性诊断，不据小样本宣称统计显著、跨任务泛化、长期内化或因果确定。报告开发集和留出集分开、每臂原始分母/未知、质量/伤害/费用/延迟，不用一个综合分掩盖代价。

先过工程红线：零越权候选、零串请求、零过期目标复活、默认停用保持 Native。发生治理/证据污染立即停。若 D 比 C 质量更差、门控系统漏选或节省成本不足以解释复杂度，选择 C/固定映射或缩范围，不为保住两阶段不断加模型。进入宿主试点前重新审查实际延迟和送达能力。

## 7. 自审与接续

最危险假设：阶段一可以廉价且少漏判；截断候选仍含有用原则；单条选择足以观察价值；模型能理解目标却不编造意图；选择依据与actor改进存在因果关联。均未被当前代码或小样本证明。

本提案故意不把任务分类准确率作为最终指标，也不默认两模型一定优于一个；两者是职责角色，同一个通用模型也可分别承担两种角色，无须训练专用决策模型。最先验证的反方问题是：C 已经能做到的事，为什么还要 D？第二个问题是：固定映射成功是否只来自显式提示而无法迁移？以对照结果决定后续，不以历史投入决定。

接手先核实实际 PR/head 与最新检查点。按 PD-AA-LOCAL-AGENT-HANDOFF.md 输出同名 JSON/Markdown、更新 LATEST；代码/CI/运行/行为分别列证据。不得创建新的历史Gold、改旧审批或把设计文档合并当作实现批准。
