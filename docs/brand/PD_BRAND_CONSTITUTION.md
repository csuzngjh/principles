# 1. PD 的品牌核心

## 1.1 一句话定义

> PD 是一个由 Owner 治理的 Agent 行为原则内化系统。

更面向使用者的表达：

> PD 把反复纠正 Agent 的经验，沉淀成可审查、可回滚、可内化的行为原则。

更短的品牌主张：

> **让原则变成 Agent 的下一次行为。**

---

## 1.2 PD 不是什

PD 不是：

* 普通 Agent memory layer
* prompt 管理工具
* 任务执行引擎
* 自动修复工具错误的补丁系统
* 让 Agent 自我野蛮进化的系统
* 炫酷 AI 控制台
* 数据烟花式 dashboard
* 企业后台式复杂配置平台
* “一键优化 Agent”的营销型 AI 产品

PD 是：

> 一个帮助 Owner 治理 Agent 行为、沉淀高质量判断、减少重复纠正的行为内化系统。

---

## 1.3 核心用户感受

所有设计最终都应该让 Owner 产生这种感受：

> “我终于能把反复纠正 Agent 的经验沉淀下来了。”

而不是：

> “这个 AI 看起来很酷。”

也不是：

> “这个后台功能好多。”

也不是：

> “我又多了一个需要管理的复杂系统。”

> 关于情绪价值的完整框架——每个功能解决 Owner 什么负面情绪、提供什么正向感受——请参见 [docs/.private/product/emotional-value.md](../.private/product/emotional-value.md)。

---

## 1.4 品牌叙事

想象一个真实场景：

> 一位开发者每天和 AI coding agent 协作。他发现 Agent 总是在修改跨模块代码时忘记确认范围，导致他反复花时间回滚和纠正。
>
> 第三次纠正后，PD 提示："系统观察到 Agent 在跨模块修改场景中 3 次未确认范围。建议沉淀为原则。"
>
> 他审查了证据，修改了措辞，批准了这条原则。
>
> 下一次 Agent 遇到类似任务时，它主动给出了修改范围和验证计划。
>
> 如果这条原则后来产生了副作用，他可以随时回滚。

这就是 PD 想要创造的体验：

* 不是 AI 魔法，而是 Owner 的判断被系统尊重和执行。
* 不是一次性修复，而是长期行为变化。
* 不是黑箱自动化，而是透明可审查的治理。

PD 的人格应该是：

* 冷静的
* 克制的
* 可信的
* 精密的
* 有长期主义的
* 尊重 Owner 判断的
* 帮助人进入慢思考状态的

PD 像什么？

* 安静的治理舱
* 精密的行为审查台
* 高信任的系统控制室
* 一本结构清晰的研究笔记

# 3. 设计哲学

## 3.1 简洁不是少，而是只暴露最核心的信息

PD 的界面不应该把所有内容都展示出来。

真正的简洁是：

> 当前 Owner 需要做什么判断，就只暴露支持这个判断的信息。

示例：

审批一条原则时，优先展示：

* 这条原则来自什么行为证据；
* 它试图改变什么行为；
* 它适用于什么场景；
* 它可能有什么副作用；
* Owner 可以批准、修改、拒绝、暂存或回滚。

不应该同时展示：

* 大量无关日志；
* 技术细节；
* 复杂指标；
* 所有历史轨迹；
* 不必要的系统状态。

---

## 3.2 复杂性必须被智能封装，但不能被黑箱化

PD 要隐藏复杂，但不能变成黑箱。

设计原则：

```text
默认摘要
按需展开
证据可追溯
决策可解释
结果可观察
操作可回滚
```

界面应采用三层信息结构：

### 第一层：Owner 当前需要判断什么

用一句话说明当前决策。

### 第二层：为什么系统提出这个判断

展示证据、模式、来源、风险。

### 第三层：需要追责时可以看见完整轨迹

提供 trajectory、pain evidence、原则历史、部署通道、行为变化。

---

## 3.3 每个界面只服务一个高质量决策

不要把 PD 控制台做成“信息大屏”。

每个页面都必须回答一个明确问题，例如：

* 我现在应该审哪条原则？
* 哪个 Agent 行为正在反复偏离？
* 哪条原则可能变成债务？
* 哪些 pain 值得沉淀？
* 这条原则有没有改变后续行为？
* 这条原则是否应该回滚？

如果一个页面同时试图回答太多问题，应拆分。

---

## 3.4 信任来自可解释、可审查、可回滚、可观察

Owner 对 PD 的信任，不来自“AI 很强”。

信任来自：

* 我知道系统为什么提出这条原则；
* 我能看到它来自哪些证据；
* 我可以修改它；
* 我可以拒绝它；
* 我可以撤回它；
* 我能看到后续行为是否发生变化。

所有设计都应该反复强化：

> Owner 仍然掌握方向盘。

---

## 3.5 让 Owner 进入慢思考，而不是制造即时刺激

PD 的 Web 控制台应该让人进入安静、专注、审慎的状态。

不要使用：

* 大量红点；
* 高频动画；
* 夸张数字；
* 排行榜；
* 彩色指标墙；
* 强刺激渐变；
* 成就弹窗；
* 运营后台式实时跳动数据。

应该使用：

* 留白；
* 稳定布局；
* 明确层级；
* 低饱和色；
* 清晰证据链；
* 少量高价值提示；
* 面向长期行为变化的表达。

---

## 3.6 所有设计都要保护 Owner 注意力

Owner 的注意力是 PD 系统中最稀缺的资源。

设计目标不是让 Owner 看更多，而是让 Owner：

* 少看低价值信息；
* 更快理解关键判断；
* 更容易做出高质量决策；
* 更容易回滚错误原则；
* 更容易看到长期行为变化；
* 更少重复纠正 Agent。

一句话原则：

> 不要把系统复杂度转嫁给 Owner。

# 4. 核心设计原则

所有设计任务必须遵守以下 8 条原则。

---

## Principle 1：一个画面只讲一个核心信息

无论是网页、营销图、README 图、视频封面，还是产品截图，每个画面都只能有一个主要信息。

错误示例：

```text
同一张图里同时讲 PD 是什么、如何工作、有哪些功能、未来路线图、技术架构。
```

正确示例：

```text
一张图只讲：
“PD 把反复纠正 Agent 的经验沉淀成可治理原则。”
```

---

## Principle 2：优先展示行为回路，而不是功能列表

PD 的核心不是功能集合，而是行为内化回路。

核心母题：

```text
Evidence → Principle → Owner Gate → Behavior Change
```

中文表达：

```text
行为证据 → 原则提案 → Owner 审查 → 后续行为改变
```

所有关键视觉都应该围绕这个母题展开。

---

## Principle 3：Owner 永远处在治理中心

不要把 Agent 画成全能主体。

不要暗示：

```text
AI 自动决定什么是更好行为。
```

应该表达：

```text
AI 提出原则候选，Owner 审查并授权，原则才进入未来行为。
```

视觉上，Owner Gate 必须是核心节点之一。

---

## Principle 4：复杂被封装，证据可展开

默认画面要简洁，但不能失去追溯性。

适合的结构：

```text
结论卡片
↓
证据摘要
↓
展开查看完整 trajectory
```

不适合的结构：

```text
一上来展示所有日志、字段、指标、堆栈、历史记录。
```

---

## Principle 5：长期价值优先于短期刺激

不要使用夸张指标包装 PD，例如：

```text
效率提升 300%
一键让 Agent 进化
永不重复犯错
自动修复所有问题
```

应该使用长期价值表达：

```text
减少重复纠正
沉淀 Owner 判断
让原则进入后续行为
观察相似任务中的行为变化
```

---

## Principle 6：视觉应克制，结构应清晰

PD 的视觉风格要安静，不要花哨。

用结构建立高级感，而不是用特效建立高级感。

优先使用：

* 留白
* 网格
* 细线
* 低饱和色
* 清晰卡片
* 温和阴影
* 稳定排版
* 少量强调色

避免使用：

* 霓虹光效
* 大面积渐变
* 金属质感
* 3D 机器人
* 爆炸式背景
* 复杂粒子流
* 多色状态块
* 装饰性图形过载

---

## Principle 7：文案要审慎，不要神化 AI

PD 的文案不应该让人感觉“AI 替你决定”。

应该让人感觉：

> 系统发现了模式，但最终判断权在 Owner。

推荐表达：

```text
系统观察到一个可沉淀的行为模式。
建议转化为原则，等待 Owner 审查。
这条原则可能影响后续相似任务。
你可以批准、修改、拒绝或暂存。
```

避免表达：

```text
AI 已自动优化你的 Agent。
系统已经学会了最佳行为。
一键进化你的智能体。
彻底解决 Agent 错误。
```

---

## Principle 8：所有设计必须支持可回滚心智

PD 的信任来自可回滚。

无论是 UI、文案、图示还是营销材料，都要体现：

* 原则不是永久写死；
* Owner 可以拒绝；
* Owner 可以修改；
* Owner 可以撤回；
* 系统可以观察副作用；
* 原则可以归档或降权。

如果一个设计只强调“内化”，却没有体现“审查与回滚”，它是不完整的。

# 5. 视觉语言

## 5.1 总体视觉方向

PD 的视觉方向：

> 克制、安静、精密、可信、慢思考、长期主义、治理感。

视觉不应该首先让人觉得“酷”，而应该让人觉得：

> 这个系统值得信任，我可以在这里做高质量判断。

## 5.4 排版规则

### 标题

标题应该短、清晰、有判断力。

推荐：

```text
Principles become behavior.
把反复纠正，沉淀为原则。
Owner stays in control.
Evidence before internalization.
```

避免：

```text
下一代智能体自我进化革命平台
全自动 AI Agent 行为智能优化系统
震撼发布！让你的 Agent 永不犯错！
```

### 页面层级

推荐层级：

```text
H1：一句核心判断
Subheading：一句解释
Body：少量说明
Visual：一张核心关系图
CTA：一个主要动作
```

避免：

```text
多个同级大标题
多段长文
多个 CTA
同屏太多卡片
信息密度无控制
```

### 留白

PD 需要较大的留白。

留白不是浪费空间，而是帮助 Owner 慢思考。

规则：

* 不要填满每一屏。
* 不要让卡片贴得太近。
* 不要把所有信息都塞进首屏。
* 重要判断周围要有安静空间。
* 每屏只承载一个主概念。

## 5.6 Logo / 视觉标识

### 当前状态

MVP 阶段暂用项目名称文字标识 "PD" 或 "Principles Disciple"。

### Logo 设计方向

当正式设计 Logo 时，应遵循以下约束：

**母题方向（推荐）：**

* 回路 / 循环 — 体现行为内化回路
* 门控 / Gate — 体现 Owner 审查权
* 沉淀 / 层叠 — 体现经验沉淀为原则
* 几何抽象 — 体现精密、理性、结构
* 细线构成 — 体现克制、安静

**禁止方向：**

* 不使用具象 AI 图标（大脑、机器人、芯片、神经网络）
* 不使用霓虹色或高饱和渐变
* 不使用过度圆润的卡通风格
* 不使用过度锐利的科技感尖角
* 不使用装饰性过强的字体

### 色彩规范

* 浅色背景：使用 Governance Blue (#243B53)
* 深色背景：使用 Warm Paper (#F7F6F2) 或白色
* 不得对 Logo 添加阴影、渐变、发光、3D 效果
* 不得将 Logo 放在复杂或高饱和背景上

### 安全区域与最小尺寸

* Logo 周围保留至少 Logo 高度 50% 的安全区域
* 最小使用尺寸：16px（favicon）/ 24px（UI 内嵌）/ 32px（独立展示）

### Favicon / App Icon

* 应为 Logo 的极简变体（如单字母 "P" 或核心图形元素）

# 7. Web 控制台与 UI 组件原则

> 详细的控制台页面设计和 UI 组件规范，请参见 [PD_UX_PRINCIPLES.md](PD_UX_PRINCIPLES.md)。

本节仅列出与品牌直接相关的界面约束。

## 7.1 控制台品牌约束

PD 控制台的定位是 **Governance Workspace**（治理工作台），不是传统 SaaS dashboard。

品牌层面的约束：

* 核心不是"看数据"，而是"做判断"。
* 首页不应设计成指标大屏或实时运营后台。
* 首页优先展示 Owner 当前最需要处理的 1-3 个治理事项。
* 每个页面只回答一个明确的治理问题。
* 所有可操作按钮应体现 Owner 权限（批准、修改、拒绝、暂存、回滚、归档），不使用"自动优化""一键进化"等暗示 AI 自主决策的表达。
* 空状态应引导 Owner 理解下一步，而不是只显示"暂无数据"。
* 错误提示应冷静，不制造恐慌。

## 7.2 状态标签色彩约束

状态标签应低饱和，不要像警报系统。具体标签定义见 [PD_UX_PRINCIPLES.md](PD_UX_PRINCIPLES.md)。

# 15. 品牌判断门

当不确定某个设计是否符合 PD 时，使用以下判断门。

## Gate 1：是否服务 Owner Governance？

如果设计没有体现 Owner 的判断权、审查权、回滚权，则不合格。

---

## Gate 2：是否服务行为内化？

如果设计只表达“保存信息”，但没有表达“改变后续行为”，则不合格。

---

## Gate 3：是否保护注意力？

如果设计让 Owner 看更多噪音、做更多低价值决策，则不合格。

---

## Gate 4：是否建立信任？

如果设计只让人觉得酷，但没有体现证据、审查、回滚、可观察变化，则不合格。

---

## Gate 5：是否足够克制？

如果设计过度依赖特效、渐变、AI cliché、视觉刺激，则不合格。

---

## Gate 6：是否可复用？

如果设计只能用于一次，不能沉淀成模板或系统语言，则优先级降低。

# 17. 给 AI 助手的标准前置提示词

以后任何设计任务，都可以在任务前附加以下提示：

```text
你正在为 Principles Disciple / PD / 原则门徒 项目执行设计任务。

在开始前，你必须遵守 PD_BRAND_CONSTITUTION.md。

PD 的品牌核心是：
把反复纠正 Agent 的经验，沉淀为可治理、可回滚、可内化的行为原则。

设计必须体现：
- 简洁
- 聚焦
- 克制
- 慢思考
- Owner 治理
- 注意力保护
- 证据可追溯
- 原则可审查
- 部署可回滚
- 后续行为可观察

设计不得出现：
- 霓虹赛博朋克
- 发光 AI 大脑
- 机器人管家
- 魔法光效
- 高饱和蓝紫渐变
- 数据烟花式 dashboard
- “一键进化”“自动优化”“永不犯错”等夸张表达

所有设计都必须回答：
1. 这个设计服务 Owner 的哪个判断？
2. 它只暴露了什么核心信息？
3. 它如何保护 Owner 注意力？
4. 它如何体现证据、审查、回滚和行为变化？
5. 它如何避免廉价 AI 感？
```

---

# 18. 结语

PD 的品牌不是“AI 很强”。

PD 的品牌是：

> Owner 终于可以治理 Agent，而不是反复纠正 Agent。

PD 的设计不是为了制造兴奋感，而是为了创造一个安静、可信、可审查、可回滚的治理空间。

所有发行物、网页、控制台、图片、文案，都应该服务同一个目标：

> **让原则真正变成 Agent 的下一次行为。**

如果一个设计不能强化这个目标，它就不应该进入 PD 的品牌系统。
