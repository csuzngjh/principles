# SPEC-PD-UIUX-001：官网与 Web 控制台体验升级

版本：1.0 · 日期：2026-10-11 · 状态：待 zcode 实施与验证

## 1. 目标与完成标准

让新用户容易找到适合自己的安装方式，让 Owner 能看懂真实状态、快速找到当前需要做的判断，并在小窗口、键盘导航和浅深主题下正常使用。

本次升级保留现有暖纸色、治理蓝、细线和安静审查的视觉身份。重点是信息架构、状态文案、响应式、无障碍和关键路径体验；不是重新设计 PD 的治理架构。

成功必须由页面行为和证据确认：

1. 无上下文投递记录时，不声称原则已经进入 Agent 决策上下文。
2. Focus 首屏能说明当前是否具备决策条件，以及需要先做什么。
3. 一个具体决策对象只有一个主要操作入口，统计口径可解释。
4. 390px 窄屏和桌面缩放后，正文仍可完整阅读与操作。
5. 键盘跳过导航不会改变当前路由或清空正文。
6. 浅深主题的关键文字、按钮和边界说明满足对比要求。
7. 英文静态 UI、辅助技术名称和页面语言一致。
8. 官网先区分宿主再提供安装步骤；示意案例不冒充真实改善证据。

审计入口：`docs/audit/PD_UI_UX_AUDIT_2026-10-11.md`。审计基线为 `10d7e4bf`，不是实施时的当前实现证明。实施前重新确认源码、调用链、测试与页面。

## 2. 范围

### Included

- 官网 EN/ZH 首页、安装、下载与相关共享样式。
- Console 外壳、侧栏、Focus、原则详情的状态/证据展示、Welcome、语言/主题相关组件。
- 确认存在的错误语义色缺口，以及与修改直接有关的交互状态。
- 已有测试的必要更新、生产边界回归、真实页面截图与验收记录。

### Excluded

- Principle 生命周期、Owner 决策、RuleCode 激活、审批权限、安全门、身份认证协议的重设计。
- 新的状态数据库、决策来源、后台服务、治理接口、运行时开关。
- 新安装器能力、Companion 原生壳改造、自动登录、无认证审批。
- 新增批量批准/拒绝、搜索系统、快捷键体系、分析仪表盘。
- 重做品牌、视频、动效体系；全站内容重写；改变 ADR 或 AGENTS.md。
- 真实效果案例编造、客户转化率承诺、把自述/投递计数升级为行为改善证明。

## 3. 开始前的核验

zcode 开始实施前完成以下工作并记录简短结论：

1. 阅读仓库 `AGENTS.md`，查看工作树与最近提交；保留无关修改。在符合仓库规范的隔离工作区实施。
2. 阅读产品身份、适用 ADR 与既有 UI/Owner 行为契约；情绪价值文档按 AGENTS.md 的私有文档路径直接读取，不复制私有原文到公开交付。
3. 查看当前 UI、现有 export、直接调用者、数据验证器、服务端投影和消费者测试。
4. 运行一次 impeccable context，审阅 audit/critique/operate；UI 编辑前读取 craft-floor。以本 SPEC 的保留风格与范围为准。
5. 阅读 ERROR_PATTERN_INDEX，运行 error:context Pass 1，将相关模式的 Required Evidence 纳入验收；无命中仍作语义判断。
6. 列明 Focus 中每个读模型的 authoritative owner、身份字段、计数含义、权限来源与失败展示。回答“现有能力缺失，还是已有信息没有接到界面”。
7. 当前源码与审计不一致时：已经解决的问题直接记录证据；新的冲突先说明，不为凑齐审计条目恢复旧设计。

只运行仓库开发服务/测试环境。安装目录与现有用户工作区状态遵循 AGENTS.md 的 installer/runtime 边界。不要为了预览修补已安装运行时。

## 4. 页面需求与验收

### R1 — 原则状态必须与证据一致（P1）

**用户问题：** 0 次投递、0 条效果记录却显示“已进入上下文”，会让 Owner 判断错误。

以已验证的 receipts 数据和 coverage 为依据，不从“已批准”“已激活”推断投递。展示至少区分：

| 记录状态 | 页面表达 |
|---|---|
| 数据可用，Presence=0，Effect=0 | 当前保留范围内未观察到上下文投递或效果记录 |
| Presence>0，Effect=0 | 已记录上下文投递，尚无对应效果记录 |
| Effect>0 | 已记录对应效果；显示证据种类，不承诺持续改善 |
| Presence=0，Effect>0 | 展示已有的效果记录，并说明没有上下文投递记录；不伪造 Presence |
| 数据不可用/降级 | 状态暂不可确认，给结构化原因和下一步；不是0次 |

保留时间范围、记录保留与完整性边界。区分 runtime 事实、自动纠正、Agent 自述；自述按自述展示。旧 Receipt History 与新的干预证据链语义分别保留，不能相加或互相替代。

候选文件：`packages/pd-console/src/ui/pages/principles/PrincipleDetailPage.tsx`、`src/ui/i18n/en.json`、`zh-CN.json`、已有 receipts 展示组件。

**验收 AC-R1：** 上表五种状态都有意图明确的回归测试；至少零记录与有投递无效果两种使用真实渲染验证。中文与英文均不得出现与数字矛盾的肯定句。

### R2 — Focus 先给结论，再给决定与追溯（P1）

**用户问题：** 重复列表与提示增加阅读量，全局锁定原因出现过晚。

目标阅读顺序：

1. 当前结论：是否有事项需要 Owner，治理动作是否就绪；未就绪给一次明确原因与恢复入口。
2. 当前决策：现有后端允许的具体决定，显示建议、风险/影响、证据摘要、合法动作。
3. 被阻塞/需要恢复：显示各自数量、原因与入口；按已有 `inbox.attention` 等语义确定逐条展示或聚合。
4. 状态动态、证据与反思内容：次级阅读，按需展开。

实施约束：

- 继续使用既有服务端 decision state、available/allowed actions、治理就绪信息。UI 只作展示，不建立新的权限 resolver。
- 不因“被阻塞”而统一禁用全部动作；例如服务端仍允许拒绝时，保留该动作。
- 显示“待处理N项”与“现在可操作N项”时必须区分，认证关闭不能使待处理对象消失。
- 同一决策对象的两个投影只能有一个主要操作面；原则动态可保留为次级摘要。去重以已核实的关联字段为依据，不用标题匹配，也不把同一原则的两个不同决策自动合并。
- 缺少稳定关联时保留对象、明确口径，记录边界；不能为了视觉整齐隐藏未关联决策。
- 保留现有 `selectDecisionSurfaceItems` 的降级保障：分组读模型失败时不能丢失合法待办。
- 全局锁定提示可集中展示，卡片仍需提供可理解的禁用原因或指向全局原因的可访问关联。各对象自己的阻塞原因不能被全局提示替代。
- “需立即逐条关注”的条目继续显露；不得机械折叠所有阻塞对象。历史未知项仍为说明，不升级成待办。
- 今日思考降为次级内容，不新增持久偏好；无待办时可以正常保留反思区。

候选文件：`pages/focus/FocusPage.tsx`、`OwnerDecisionCard.tsx`、现有展示辅助函数与双语言文案。服务端保持不变；若现有数据确实不能满足要求，先报告最小合同缺口，不在此任务自行扩展架构。

**验收 AC-R2：** 覆盖就绪/未认证/身份未配置、多项同类阻塞、单项急需恢复、历史未知、混合决策、分组接口失败、inbox关闭与两种既有 summary 模式。每个对象有可追溯入口；计数与实际展示口径一致；第一屏在1440×900与1280×720可看到全局状态及下一步。

### R3 — 窄屏导航与正文可用（P1）

**用户问题：** 固定256px侧栏挤掉正文。

复用已有 sheet/dialog 能力，选择一个有证据的断点；在窄屏使用顶部导航按钮和可关闭侧栏抽屉，正文去掉固定左边距。桌面保留现有侧栏。

- 菜单按钮有名称、展开状态和关联区域。
- 打开后焦点进入导航；Esc/关闭按钮可关闭；关闭后焦点返回菜单按钮；不出现键盘陷阱。
- 选中导航后进入目标路由并关闭抽屉；当前页保持可识别。
- 长原则、路径与不可分割字符串正常换行。真正需要二维阅读的区域允许局部滚动，页面主体不能整体横向滚动或裁掉内容。
- 操作控件优先44px触达；不能通过缩小文字来补布局。

候选文件：`App.tsx`、`components/layout/app-sidebar.tsx`、`page-shell.tsx`、已有 `components/ui/sheet.tsx`。

**验收 AC-R3：** 320、390、768、1280、1440px；浅深主题与EN/ZH。Focus、详情、设置、Welcome、Activation检查正文与关键按钮。200%浏览器缩放，支持场景下400%缩放检查重排。Playwright视口验证不冒充真实触摸；至少合成触摸检查菜单开关与关闭，并明确真机覆盖情况。

### R4 — 键盘跳过导航与当前位置（P1/P2）

“跳到正文”保持当前 HashRouter 路由，显式把焦点移至 main 并滚动；main按需可编程聚焦。当前导航链接设置 `aria-current="page"`，保留文字名称与可见焦点。

候选文件：`App.tsx`、`components/layout/app-sidebar.tsx`。

**验收 AC-R4：** Focus、原则详情、Settings上以Tab→Enter执行；URL路由不变、正文不空、activeElement是main；后续Tab能继续进入正文控件。详情页的当前“原则审查”入口也能被辅助技术识别。

### R5 — 主题、对比与错误语义色（P1）

调整现有语义token：官网 muted 在边界说明/次级文字实际背景上可读；Console Welcome主按钮使用匹配主题的 foreground。

- 普通文字至少4.5:1；符合大字定义的文字至少3:1；必要控件边界与焦点信息按适用标准验证。
- 检查normal、hover、focus、disabled；正常操作控件的正文不能误用禁用对比豁免。
- 核验 `text-red`/`border-red` 等是否真实缺失，确认后复用已有 danger；已有效的Tailwind色阶不作机械替换。
- 保留warning/error/success语义，不靠颜色单独表达。

候选文件：官网 `custom.css`、Console `styles/globals.css`、Welcome以及已核实存在问题的ControlCenter/RuntimeProfileManager/Update错误样式。

**验收 AC-R5：** 给出实际计算样式的前景、背景、字号与对比度；EN/ZH浅深主题检查。至少模拟一个相关真实错误响应查看文字/颜色/下一步；纯源码token扫描不足以证明错误流已通过。

### R6 — 完整语言切换与渐进披露（P2）

主题按钮、退出、title/aria文本和原则详情干预证据链静态文案接入现有i18n。语言切换及初次加载同步 `document.documentElement.lang`，保存偏好与刷新行为沿用现有实现。

证据链普通Owner默认看到“现有记录和缺口”，Phase 1、revision、摘要、来源标识等工程信息置于明确技术详情；保留证据追溯与原有字段，不重解释数据。

候选文件：侧栏、`i18n/index.ts`、双语言JSON、`PrincipleDetailPage.tsx`、必要的已有证据组件。

**验收 AC-R6：** EN→ZH→EN与刷新后lang、静态正文、title、aria名称一致。用户原始原则/宿主返回内容不强制翻译；切回中文按钮的“中文”名称合理保留。技术信息展开后完整可读。

### R7 — 官网先选宿主，再给安装路径（P2）

首页保留问题导向的大标题；简化首屏说明，先说“纠正→可审查原则→你的批准→后续证据”，术语作次级解释。允许在既有组件内调整版面，不增加首页章节。

安装页顶部使用两个明确入口：OpenClaw / Codex。默认不猜访客宿主，首次展示选择与一句差异说明。选定后只展示当前路径的前置要求、步骤、复制命令与完成确认；切换不会执行安装。可在现有URL查询或锚点表示选择，不新增后台或持久配置。

- 命令和Node要求以当前安装器、插件文档、manifest为准；不把审计中的版本号当成永久事实。
- 首屏安装命令必须标明适用宿主；选Codex后不继续显示OpenClaw命令为主要入口。
- 保留原有安装路由和常用链接；首页“开始使用”进入选择路径。
- Companion下载CTA附近同时显示“需先安装 PD；Windows桌面增强入口”，提供前往安装入口；已有用户仍可直接下载。
- 复制成功/失败可见，名称能区分复制哪个命令。命令仅展示/复制，不自动运行。

候选文件：`HeroSection.vue`、`InstallSection.vue`、`InstallGuide.vue`、`DownloadPage.vue`、双语言安装Markdown、必要的既有导航配置。

**验收 AC-R7：** EN/ZH分别走OpenClaw和Codex路径，核对当前真实命令、前置条件和复制结果；安装页刷新与浏览器前进后退按采用的URL策略一致；下载首屏无需向下滚动即可知道依赖PD本体。没有执行真实安装时不能声称安装验收通过。

### R8 — 示例可信、结束文案与产品价值一致（P2）

默认把静态行为时间线标为“行为变化示意”，CTA改为“看一个行为变化示意”；英文本同步。没有可授权核查的真实案例时直接采用此默认，不等待案例材料，也不编造数据。

如果使用真实案例，必须附脱敏来源、场景/时间范围、前后行为和证据强度；不能只凭生成、批准、投递证明改善。未经授权不展示私人会话或治理材料。

首页末尾主要文案改为围绕“减少重复纠正、你保留最终决定、可观察与可撤回”的下一步邀请，替换作为主结尾的受苦宣言。保留既有理念内容的访问入口；无需新建品牌页面。现有homepage测试若固定受苦口号，明确列为此SPEC要求的内容契约变更，而非偷偷放宽测试。

**验收 AC-R8：** 视觉、CTA、aria label、SEO中相关案例称谓一致；没有无法验证的真实性/成功率承诺。两种语言末尾均有清晰开始入口和Owner控制说明。

### R9 — 媒体加载与最后一致性检查（P2）

首页首屏之外ThinkingLog封面延迟加载；生成符合当前展示尺寸的压缩资源，保留原图，按实际需要使用srcset/sizes。维持hero视频metadata预加载、poster、字幕和原生控件。

优化后进行一次桌面/移动、浅深主题的批量截图审阅；集中修复，再做一次确认。清理本次引入的间距、字体层级、按钮/状态样式不一致；不扩展到全站重新设计。

**验收 AC-R9：** 记录图片优化前后字节数与尺寸，确认未滚近该卡时不会主动下载其完整大图；首屏关键图不误设lazy。没有性能基准时只报告资源改进，不宣称LCP或转化率提升。

## 6. MVP与复杂度边界

- `mvp-q-1-what-if-skip`：保留误导状态、键盘失败、小屏不可用和安装辨认成本，直接影响Owner判断与新用户开始使用。
- `mvp-q-2-how-observed`：以AC-R1–AC-R9、截图、键盘/路由状态、实际样式对比和现有服务端权限回归观察。
