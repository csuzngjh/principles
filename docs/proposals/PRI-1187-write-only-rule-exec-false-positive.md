# 取舍记录：write-only 规则误拦 exec

- 状态：已裁决——不做运行时过滤（结论见文末"裁决结论（已定）"）
- 来源：PRI-1187 三轮复核（2026-11-12）
- 关联 PR：#2570（撤回运行时过滤，保留激活期护栏与契约）、#2578（只读埋点）

## 现状

`affectedTools: ["write"]`（或 `["edit"]`）的规则，在 OpenClaw 上仍会评估并可能拦截 `exec`（删除/重写文件都经 shell）。这是**误拦**：规则声明只治理写工具，却对 exec 生效。

PRI-1187 曾尝试在运行时按 `affectedTools` 跳过评估，三轮复核各自找到了把"该拦"放过去的路子：

1. `host-liveness:*` 前缀：合成探针被整体排除在可靠性校验之外，可被用来隐藏未声明的工具族。
2. 声明窄、代码宽：规则只声明 `['edit']`，实现按路径拦截一切；过滤后 exec 上的拦截被静默移除。
3. 护栏只看 trace：trace 未覆盖的真实调用面（如"禁止改测试文件"策略在 exec 删除文件）在声明与 trace 一致时仍会漏拦。

结论：在现有生成器与夹具下，"声明 = 执行上界"的假设不成立。**误拦是噪音，漏拦不可接受。**

## 三个候选方向

### A. 运行时按 affectedTools 跳过评估（已撤回）

- 做法：gate 装载候选时按声明族过滤。
- 风险：上述三条绕过路径无法在不引入 fail-open 的前提下同时堵死；任何"声明窄"的规则都会在真实调用面上静默降级。**不可接受。**

### B. 保持全量评估（当前决定）

- 做法：运行时评估所有生效规则；声明只用于审批展示、审计与激活期一致性校验（已实现）。
- 风险：误拦噪音（write-only 规则拦 exec），可能造成用户困惑与额外审批。
- 缓解：审批上下文显著提示"本规则会在 exec 等族上同样生效"；规则作者被引导同时声明 exec 族。

### C. 生成/激活期收紧 + 运行时全量（#2570 已落地的部分）

- 做法：`validateRuleReliability` 强制 trace 工具族 ⊆ affectedTools；prompt v17 要求文件变更类策略声明 exec 族；Artificer 拒绝保留前缀 `host-liveness:`。
- 风险：只能保证"声明与已验证行为一致"，不能保证声明覆盖未来真实调用面；存量已激活规则不回溯校验。
- 可选增强：对存量规则做一次激活重校验/审计，或在审批页展示"声明族 vs 代码可能触达族"的差异提示。

## 不在本工单范围

- 不改门禁默认严格度。
- 不引入任何 fail-open。
- 不做 RuleHost/Gate 四套实现的收敛（独立一步）。

## 裁决结论（已定）

1. **误拦噪音继续接受为默认状态**：已定。安全门宁多拦不少拦，运行时不做声明过滤；误拦量由 PR #2578 的只读埋点量化，不改变任何判定。
2. **存量已激活规则不做回溯重校验/审计**：已定（本轮不做）。激活期护栏只作用于新激活；若埋点显示问题集中在少数规则，再按数据单独立项，而不是靠猜测扩大改动面。
3. **审批上下文暂不强制提示"本规则也会在 exec 上生效"**：已定（本轮不做）。当前以 prompt v17 契约（文件变更类策略须声明 exec 族）与本文档替代；是否升级为审批页强制提示，由埋点数据决定是否再议。
