# Console Rebuild 用户故事

> 本文档为开发与验收参考，按功能模块组织。每条用户故事包含角色、意图、验收标准。
> 角色定义：**Owner** = PD 治理者；**新 Owner** = 首次使用 PD 的 Owner。

---

## 1. 治理焦点页（首页）

### US-1.1 查看判断队列

**作为** Owner，**我想**打开控制台首页就看到当前所有需要我判断的事项，**以便**快速知道现在该做什么。

**验收标准**：
- 首页展示三个分区：「待你审查」「值得关注的行为偏差」「系统信号」
- 每个分区只展示结论级摘要，不展示原始日志/指标
- 分区按优先级排列：待你审查 > 行为偏差 > 系统信号
- 无数据时分区显示诚实空状态文案

### US-1.2 查看"今天"摘要

**作为** Owner，**我想**在首页顶部看到一行散文式摘要（N 条待审 / N 条偏差 / N 条停滞），**以便**一眼掌握当前治理负担。

**验收标准**：
- 摘要使用等宽数字（tabular-nums）
- 摘要是一行文字，不是指标卡墙
- 数字为 0 时不隐藏，如实展示"0 条待审"

### US-1.3 从首页钻入原则审查

**作为** Owner，**我想**点击「待你审查」中的原则卡片直接进入原则审查详情页，**以便**快速完成审查决策。

**验收标准**：
- 卡片点击跳转到 `/principles/:id`
- 卡片展示：原则摘要、标签「待审查」、通道、可回滚标记、证据摘要（inset well）
- 卡片有"审查并决定"和"暂存"两个动作按钮

### US-1.4 查看停滞信号

**作为** Owner，**我想**看到"已批准但尚未激活"的原则的停滞信号，**以便**知道哪些原则可能没有生效。

**验收标准**：
- 停滞信号使用 amber 左边框 + 冷静散文，不用红色/告警红点
- 停滞信号可点击跳转到生效情况页对应原则
- 停滞信号包含精确的未激活时长（如"已批准 6 天"）
- 若后端无法提供同类原则的平均激活时间作为判断基准，诚实声明

### US-1.7 首页 footer 简洁

**作为** Owner，**我想**首页底部只有一句核心定位声明，**以便**不被冗长文案分散注意力。

**验收标准**：
- footer 文案缩短为"这一页只回答一个问题：现在该做什么判断。"
- 原后半句"系统状态、指标与历史轨迹默认隐藏，需要时可在各页内逐层展开"移入首次引导文案
- footer 最多一句话

### US-1.5 首次使用引导

**作为**新 Owner，**我想**在首次登录看到空首页时了解 PD 能做什么，**以便**知道接下来会发生什么。

**验收标准**：
- 所有分区为空时，首页展示 PD 工作流程说明（4 步：观察偏差→捕获证据→生成候选→审查批准→注入行为）
- 引导文案是空状态文案的增强版，不是独立 onboarding 页面或弹窗
- 有数据后引导文案自动消失，替换为正常判断队列

### US-1.6 摘要时间范围明确

**作为** Owner，**我想**知道首页"今天"摘要的时间范围，**以便**准确理解数字含义。

**验收标准**：
- 摘要使用"当前"而非"今天"（避免跨时区歧义）
- 或明确标注时间范围，如"最近 24 小时"
- 数字为 0 时不隐藏，如实展示

## 2. 行为证据页

### US-2.1 浏览行为证据列表

**作为** Owner，**我想**看到系统捕获的所有值得治理的行为证据，**以便**了解 Agent 在哪些场景下出现了行为偏差。

**验收标准**：
- 每条证据卡展示：简短描述、发生场景、相关 Agent 行为、来源、是否建议生成原则
- 证据按单条呈现，不做"反复出现/相似任务"聚合
- 界面出现诚实声明："PD 暂按单条呈现，自动同类识别为 post-MVP"

### US-2.2 查看证据详情

**作为** Owner，**我想**点击证据卡查看详情（三层结构），**以便**了解行为偏差的完整上下文。

**验收标准**：
- 第一层：摘要（发生了什么）
- 第二层：场景/行为（在什么场景下、Agent 做了什么）
- 第三层：完整 trajectory（默认折叠，展开显示完整执行轨迹）
- 无 Flame/burn 视觉元素

### US-2.3 区分行为证据与产品反馈

**作为** Owner，**我想**行为证据页只展示"系统捕获的行为证据"，产品反馈在另一个入口，**以便**不混淆两种不同语义。

**验收标准**：
- 行为证据页（`/pain`）只展示系统自动捕获的 pain
- 产品反馈页（`/report-problem`）是 Owner 主动提交的对 PD 产品的意见
- 两者不在同一页面混合

### US-2.4 沉淀操作反馈预期

**作为** Owner，**我想**点击"沉淀为原则候选"后知道接下来会发生什么，**以便**对系统行为有合理预期。

**验收标准**：
- "沉淀为原则候选"按钮旁有弱化提示文案："系统将生成原则候选，出现在首页待审查区"
- 提示文案用 `--ink-4` 色，字号 13px
- 点击后 Toast 反馈："已提交沉淀请求，原则候选生成后将出现在待审查区"

## 3. 原则审查页

### US-3.1 浏览原则列表

**作为** Owner，**我想**看到所有原则的列表，**以便**了解当前原则库的整体状态。

**验收标准**：
- 列表展示原则卡片：原则摘要、状态标签、通道、置信度 meta
- 状态标签按配色：待审查=gov、需注意=amber、稳定=green、风险=danger

### US-3.2 搜索原则

**作为** Owner，**我想**按原则文本搜索，**以便**在原则数量较多时快速找到目标原则。

**验收标准**：
- 搜索框支持按原则正文文本搜索
- 前端过滤实现（原则数量通常 < 100）
- 搜索无结果时显示诚实空状态

### US-3.3 筛选原则状态

**作为** Owner，**我想**按状态筛选原则（待审查/已批准/已拒绝/已暂存），**以便**聚焦于需要我处理的原则。

**验收标准**：
- 至少支持 4 种状态筛选：待审查、已批准、已拒绝、已暂存
- 可单选或多选状态
- 筛选结果实时更新

### US-3.4 排序原则

**作为** Owner，**我想**按更新时间或创建时间排序原则列表，**以便**看到最近变动的原则。

**验收标准**：
- 至少支持 2 种排序：按更新时间、按创建时间
- 默认按更新时间倒序

### US-3.5 查看原则详情（三层结构）

**作为** Owner，**我想**查看一条原则的完整信息（结论→为什么→轨迹），**以便**做出高质量的审查决策。

**验收标准**：
- 第一层（结论）：大字陈述原则 + "这是面向未来相似场景的行为政策"
- 第二层（为什么）：适用场景/预期行为/不适用场景/副作用 + 来源证据列表
- 第三层（完整轨迹）：默认折叠，展开显示 Evidence→诊断→提案→审查→部署→行为
- 信息渐进展开，不一进页面就铺所有字段

### US-3.6 批准原则

**作为** Owner，**我想**批准一条原则，**以便**让它生效并注入 Agent 行为。

**验收标准**：
- 点击"批准"调用 `/approve` 端点
- 批准后 Toast 反馈："已批准 / 将通过提示通道激活"
- Toast 引导去"生效情况"页查看
- 不承诺"行为已改变"
- 多通道审批记录收拢为单次决策，不需要逐通道分别批

### US-3.7 拒绝原则

**作为** Owner，**我想**拒绝一条原则并说明理由，**以便**记录我为什么不同意这条原则。

**验收标准**：
- 点击"拒绝"弹出理由输入框（复用 `rejection-reason-dialog`）
- 拒绝理由为必填
- 拒绝后 Toast 反馈："已拒绝"
- 拒绝失败时显示冷静错误文案

### US-3.8 暂存原则

**作为** Owner，**我想**暂存一条原则（不做决策），**以便**稍后再审查。

**验收标准**：
- 暂存后原则状态变为"已暂存"
- 暂存后 Toast 反馈："已暂存"
- 暂存的原则可通过状态筛选重新找到

### US-3.9 查看通道信息

**作为** Owner，**我想**看到原则将通过什么通道激活，**以便**理解它的生效方式。

**验收标准**：
- 显示"将通过提示通道激活 · 可回滚"
- 不放选通道/选强度控件（后端只有一档，假开关违反诚实约束）

### US-3.10 修改措辞（禁用占位）

**作为** Owner，**我想**看到"修改措辞"按钮但知道它暂不可用，**以便**理解这是后续功能而非当前能力。

**验收标准**：
- "修改措辞"按钮位于原则正文旁（不是底部决策栏），作为内联编辑入口
- 按钮为禁用状态
- hover 或旁注明确"原则修改将在后续版本开放"
- 不伪造 modify 功能
- 底部决策栏只保留决策动作：批准 / 暂存 / 拒绝

### US-3.11 完整轨迹折叠区措辞

**作为** Owner，**我想**看到第三层折叠区的标题是中性的追溯邀请，**以便**不被"追责"等归咎性措辞影响判断心态。

**验收标准**：
- 折叠区标题使用"需要追溯时，查看完整轨迹"（不是"需要追责时"）
- 或使用"了解完整来龙去脉"
- 措辞符合品牌"冷静治理顾问"人格，无归咎意味

## 4. 生效情况页

### US-4.1 查看激活事实

**作为** Owner，**我想**看到已批准原则的激活状态，**以便**知道哪些原则真的在生效。

**验收标准**：
- 列表展示：已激活/未激活、通道（prompt/defer_archive/code_tool_hook）、动作/目标、`activatedAt`
- 数据来自 CR8 的全通道激活 join

### US-4.2 理解能力边界

**作为** Owner，**我想**看到 PD 的能力边界声明，**以便**不误以为 PD 能做到它做不到的事。

**验收标准**：
- 固定可见声明："PD 暂无法统计原则在后续任务中被触发的次数，也无法自动判断行为是否改变（需要语义匹配/反馈闭环，post-MVP）。"
- 声明不被折叠或隐藏

### US-4.3 识别未激活原则

**作为** Owner，**我想**看到"已批准但从未激活"的原则被高亮，**以便**知道可能存在问题。

**验收标准**：
- 未激活原则有视觉区分（高亮/标记）
- 可跳转到原则债务页查看详情
- 同步供首页停滞信号使用

### US-4.4 查看 lifecycle 指标（可选）

**作为** Owner，**我想**在原则有 rule 时展开查看 lifecycle 指标，**以便**了解规则质量信号。

**验收标准**：
- 仅当原则有 rule 时显示可展开区域
- 展开后标注"规则质量信号，不等于行为变化"
- 无 rule 时显示 `insufficientData` 诚实文案
- lifecycle 指标绝不作为主指标展示

### US-4.5 不看到虚假行为变化

**作为** Owner，**我不想**看到任何触发/命中计数、行为变化曲线或合成分，**以便**不被误导。

**验收标准**：
- 页面无触发/命中计数字段
- 无行为变化曲线/图表
- 无合成分当主指标

## 5. 原则债务页

### US-5.1 查看债务原则

**作为** Owner，**我想**看到可能成为债务的原则列表，**以便**管理原则库的健康度。

**验收标准**：
- 列表展示：长期未激活原则、Owner 标记可疑原则、建议归档/降权原则
- 债务原因为自然语言，非指标墙
- 冲突检测等无数据维度诚实留白

### US-5.2 归档原则

**作为** Owner，**我想**归档不再需要的原则，**以便**保持原则库精简。

**验收标准**：
- 有后端端点时：归档按钮可点击，归档后 Toast 反馈
- 无后端端点时：归档按钮为禁用占位 + 诚实旁注"归档功能将在后续版本开放"

### US-5.3 不看到虚假检测

**作为** Owner，**我不想**看到自造的冲突检测或合成评分，**以便**不被误导。

**验收标准**：
- 后端无数据的维度（冲突检测等）诚实留白
- 不自造 MVP5 级检测逻辑
- 不引入合成评分作为主信息

## 6. 控制中心

### US-6.1 查看配置就绪状态

**作为** Owner，**我想**看到 PD 的配置是否完成，**以便**知道 PD 能不能正常工作。

**验收标准**：
- 状态卡文案为"配置是否完成/缺少哪些配置"（治理味）
- 不是"PD 状态/Can PD work right now"（运营味）
- 仅作本页局部反馈，不外溢为全局健康灯/红点

### US-6.2 管理功能开关

**作为** Owner，**我想**启用/禁用 PD 功能，**以便**控制 PD 的行为范围。

**验收标准**：
- 功能开关可切换
- 切换后 Toast 反馈

### US-6.3 绑定 Agent/LLM Runtime

**作为** Owner，**我想**绑定 agent 到 runtime profile，**以便**指定 PD 作用于哪个 agent。

**验收标准**：
- 可选择 agent 和 runtime profile 进行绑定
- 可设置默认 runtime
- 操作后 Toast 反馈

### US-6.4 查看高级诊断

**作为** Owner，**我想**折叠展开高级诊断信息，**以便**在需要时查看但不被噪音干扰。

**验收标准**：
- 高级诊断区默认折叠
- 展开后显示 feature/runtime/warnings/copy diagnostics
- 低饱和、不渲染成告警墙

- 可保存/更新 token

### US-7.2 管理 Workspace

**验收标准**：
- 可添加新 workspace
- 可删除已有 workspace
- 可同步 workspace
- 操作后 Toast 反馈

## 8. 产品反馈页

### US-8.1 提交产品反馈

**作为** Owner，**我想**提交对 PD 产品的反馈（bug/混淆/隐私/功能建议），**以便**帮助改进 PD。

**验收标准**：
- 支持 4 类反馈：bug、confusing、privacy、feature
- 反馈草稿本地存储在 `.pd/feedback/drafts/`，不自动上传
- 明确隐私边界说明

### US-8.2 复制反馈为 Markdown

**作为** Owner，**我想**将反馈草稿复制为 Markdown 或打开 GitHub issue 链接，**以便**手动提交到 GitHub。

**验收标准**：
- 可复制为 Markdown
- 可复制为纯文本
- 可打开 GitHub issue 预填链接

## 9. 更新页

### US-9.1 检查并执行更新

**作为** Owner，**我想**检查 PD 版本并执行更新，**以便**保持 PD 最新。

**验收标准**：
- 可检查当前版本和最新版本
- 可配置更新策略（文件处理方式）
- 可创建备份
- 执行更新时有进度对话框
- 更新后 Toast 反馈

### US-9.2 回滚更新

**作为** Owner，**我想**回滚到之前的版本，**以便**在更新出问题时恢复。

**验收标准**：
- 可查看更新历史
- 可执行回滚操作
- 回滚后 Toast 反馈

## 10. 全局交互

### US-10.1 操作即时反馈

**作为** Owner，**我想**在执行任何写操作（批准/拒绝/归档/保存设置等）后立即看到反馈，**以便**确认操作是否成功。

**验收标准**：
- 所有写操作后弹出 Toast 通知
- Toast 样式低饱和、冷静，对齐 CR1 token
- 成功/失败有不同样式
- Toast 自动消失，不需要手动关闭

### US-10.2 导航

**作为** Owner，**我想**通过侧边栏在 5 个治理页和 4 个工具页之间导航，**以便**快速切换功能。

**验收标准**：
- 侧边栏品牌区："门"形 mark + `PD / Governance Workspace`
- 主导航（5 项）：治理焦点 / 行为证据 / 原则审查 / 生效情况 / 原则债务
- 次级工具区（弱化）：控制中心 / 产品反馈 / 设置 / 更新
- 当前页高亮
- 无 DNA logo、无"Burn pain, drive evolution"标语

### US-10.3 中英文切换

**作为** Owner，**我想**在中英文之间切换控制台语言，**以便**用我熟悉的语言使用。

**验收标准**：
- 切换后所有文案即时更新
- 无 raw key 泄漏
- 中英文键一一对应

### US-10.4 登录

**作为** Owner，**我想**通过 Bearer Token 登录控制台，**以便**访问治理功能。

**验收标准**：
- 登录页输入 Bearer Token
- Token 验证通过后跳转首页
- 登录页标语为治理化文案，不是"燃烧痛苦，驱动进化"

### US-10.5 操作确认保护

**作为** Owner，**我想**在执行不可逆治理动作（批准/归档/回滚）前得到冷静确认，**以便**避免误操作，同时不被恐慌弹窗打断思考。

**验收标准**：
- 批准/归档/回滚点击后显示内联确认条（不是弹窗），如"批准后原则将通过提示通道激活。确认批准？"
- 确认条包含 [确认] 和 [取消] 两个按钮
- 暂存操作无需确认，直接执行 + Toast
- 拒绝操作已有理由输入框作为天然确认，无需额外确认

### US-10.6 操作撤销窗口

**作为** Owner，**我想**在执行写操作后 5 秒内可以撤销，**以便**在误操作时快速恢复，体现"可回滚"心智。

**验收标准**：
- 所有写操作的 Toast 中包含"撤销"链接
- 撤销窗口 5 秒，超时后链接消失
- 撤销操作本身也有 Toast 反馈（"已撤销"），但不嵌套撤销
- 撤销后数据恢复到操作前状态

### US-10.7 键盘快捷键

**作为** Owner，**我想**通过键盘快捷键快速切换页面和执行常见操作，**以便**高频使用时提高效率。

**验收标准**：
- `Alt + 1~0` 切换 10 个页面（1=启动页, 2=登录页, 3=治理焦点, 4=原则审查, 5=行为证据, 6=生效情况, 7=原则债务, 8=控制中心, 9=反馈, 0=更新）
- 侧边栏导航项右侧显示快捷键提示（`--ink-4` 色，字号 11px），格式为 `Alt+N`
- 原则审查页决策栏：焦点在决策栏内时 `Enter` 批准 / `D` 暂存 / `R` 拒绝
- 禁止使用 `Cmd/Ctrl + 数字`（浏览器保留快捷键，会冲突）
- 禁止使用 `⌘` 符号（Windows 用户会困惑）

### US-10.8 键盘导航与焦点管理

**作为** Owner，**我想**完全通过键盘操作控制台，**以便**在无法使用鼠标时仍能完成治理工作。

**验收标准**：
- 所有可交互元素有 `:focus-visible` 样式（`outline: 2px solid var(--gov)`）
- Tab 键可遍历所有可交互元素，顺序符合逻辑
- Modal/Dialog 打开时焦点陷阱，关闭后焦点回到触发元素
- 不使用 `outline: none` 移除焦点环

### US-10.9 屏幕阅读器可访问

**作为** Owner，**我想**通过屏幕阅读器理解控制台内容，**以便**在视力受限时仍能完成治理工作。

**验收标准**：
- 装饰性 SVG 图标加 `aria-hidden="true"`
- 功能性 SVG 图标加 `aria-label`
- 状态标签使用 `<span role="status">` 或等价语义
- 折叠区 summary 使用描述性文案，不用"点击展开"
- 卡片整体可点击时用 `<a>` 或 `<button>` 包裹
