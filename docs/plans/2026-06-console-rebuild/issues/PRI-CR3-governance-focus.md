# PRI-CR3：治理焦点页（首页判断队列）

**Type**: AFK
**Priority**: P1
**Blocked by**: PRI-CR1, PRI-CR2, PRI-CR8
**必读**: `../01-shared-constraints.md`（全节）、`packages/pd-console/design-prototype/index.html`（像素级视觉参考，查看 focus 屏幕段）

## 背景

首页是整个控制台心智的锚点。它的**唯一职责**是回答"现在该做什么判断"，是一个
判断队列，**不是**概览大屏。视觉与结构以 `design-prototype/index.html` 的 focus
屏幕段为准（已含原型 token、卡片、证据 inset well、停滞信号、章节节奏）。

## What to build

实现 `GovernanceFocusPage`（路由 `/` 或 `/focus`），结构对齐原型：

1. **页眉**：eyebrow「治理焦点」+ 标题「现在，值得你判断的事」+ 一句副标。
2. **当前状态单行摘要**：用等宽数字呈现"N 条待审 / N 条行为偏差 / N 条停滞信号"。
   **不是**指标卡墙，就是一行散文式摘要。避免"今天"（时区歧义）和"反复偏差"
   （暗示聚合，违反 F.2）。
3. **分区判断队列**（每项是一张结论卡，点击钻入对应详情页）：
   - **待你审查**：来自审批聚合（CR8），每卡 = 一条原则 + 标签「待审查」+ 通道/可
     回滚 meta + 证据摘要（inset well）+ 动作（审查并决定 / 暂存 / 查看完整链路→
     原则审查页）。
   - **值得关注的行为偏差**：来自 pain（按单条，**不聚合**，标注"同类识别 post-MVP"）。
   - **系统信号**：停滞信号（如"已批准原则尚未激活"），冷静散文 + amber 左边框，
     **非红色告警**。
4. 空状态、加载态、错误态按 E 节文案规则。

## Acceptance criteria

- [ ] 视觉与 `design-prototype/index.html` focus 屏幕段一致（布局、间距、字号、颜色、
      hover、证据 inset well、停滞信号样式），用 CR1 的 token，无硬编码色值。
- [ ] 首页**不出现**任何指标图表、趋势线、彩色指标块、排行榜、全局健康灯。
- [ ] "待审查"数据来自 CR8 的审批聚合（一条原则一个条目），点击进入原则审查页。
- [ ] "行为偏差"按单条呈现；界面出现"PD 暂按单条呈现，自动同类识别为 post-MVP"类
      诚实声明；**无**"第 N 次/相似任务"假聚合（F.2）。
- [ ] 停滞信号为散文 + amber，**非** `--danger`、**非**告警红点（F.3）。
- [ ] 后端数据解析遵循 H 节（`unknown` + 校验，不用 `as`）；空/错误态有诚实文案。
- [ ] 中英文 i18n 完整。
- [ ] `cd packages/pd-console && npm run build && npm run test` 通过；`npm run lint` 通过。

## 实施提示（防漂移/防错乱）

- 卡片、标签、按钮、inset well 全部复用 CR1 的组件与 token，不要现写样式。
- 若某分区暂无真实数据源（如停滞信号需要 CR8 的激活 join），先用 CR8 提供的接口；
  接口未就绪时显示诚实空状态，**不要**塞假数据撑场面。
- 首页是判断的入口而非逛页面的地方：除"查看完整链路"等钻入链接，不加横向跳转装饰。

## MVP 三问

- **不做会怎样**：没有判断入口，拥有者无法被引导进入慢思考决策。
- **怎么观察**：打开首页即见判断队列；点击卡片进入对应详情页。
- **怎么关闭**：页面级，路由摘除即回退。
