# PD-Lab v0.3 实施交接与验收工作包

状态：DRAFT，尚未实施。基线：`7b5fd027304c61350b9bd443551ab40a017e6139`。本文件帮助后续AI按明确边界开发，不授权真实模型调用、私有数据扩展、生产写入或发布。

## 1. 开始任务前

1. 读取 [SPEC](../specs/SPEC-PD-LAB-EXPERIMENT-INTEGRATION-001-v0.3.md) 的Owner定义与当前R阶段。
2. 根据 [TECH](../specs/TECH-PD-LAB-EXPERIMENT-INTEGRATION-001-v0.3.md) 阅读对应模块；涉及数据/分数必须读取 [CONTRACT](../specs/CONTRACT-PD-LAB-DATA-AND-SCORING-001-v0.3.md) 对应章节。
3. 检查当前代码相对本基线的变化、实际消费者和测试；记录“仍成立/已漂移/未知”，不要把本文路径当永远正确的架构。
4. 按AGENTS.md创建/认领独立工作区；读取错误模式并执行计划路由。Linear工作遵循现有CLI流程，先核对已有PRI-1245/1246等票，不能照历史文档状态派工。
5. 选择下面一个工作包，列出目标、非目标、实际文件、验证入口与未决参数。范围外问题登记，不顺便实现。

完成前必须能回答：Pain与完整轨迹是否保留？哪些期望在当时可知？实际调用了哪个生产入口？主分母从哪里来？什么证据能推翻结论？哪个旧维护职责被移除了？

## 2. 任务依赖与拆分

```text
T0 现实映射与术语 → T1 完整数据准入 → T2 输入投影与真实管道接入
                   └→ T3 裁判/计分离线契约
T2 + T3 + 执行授权 → T4 真实宿主研究切片
T4 + 第二领域消费 → T5 职责迁移与旧入口退役
T3 + T4 + 冻结保留集 → T6 正式Benchmark与晋级试点
T6 + 观察授权/真实时间 → T7 持续数据和纵向研究
```

T1与T3可分开实现，在共同契约稳定后集成；不能各自重定义case、assignment或UNKNOWN。算法离线测试可先用合成数据，真实评价及数据采集须满足授权。

## 3. 工作包

### T0：现实映射与术语（R0）

- 输入：当前源码、SPEC §2–3、已有真实路径与协议。
- 交付：Pain→完整轨迹→诊断目标→CLI的生产路径图；字段/来源映射、消费者表、现有测试、完整性缺口、术语修订清单。
- 边界：只读审计与术语文档，不改生产source枚举、不迁移数据。
- 验收：TECH §2.1每一项有源码/证据定位；公开/私有术语分别在其所属仓库修订或明确同步阻塞，不复制私有正文。
- 阻塞：无法确定任务边界或源记录完备性时，T1只能做结构/不完整路径，不能捏造完整样本。

### T1：完整案例准入与冻结（R1）

- 输入：T0映射、授权的快照范围、CONTRACT §1–3。
- 主要位置：现有数据准备模块；不先建统一Dataset Store。
- 交付：完整性验证、引用解析、来源分组、数据发布计数与补齐清单；新版本不会重写历史digest。
- 验收：DT-01至DT-06通过实际读取入口；授权/缺轨迹路径fail-closed；快照读取前后源状态不变。
- 非目标：自动采集所有项目对话、生成虚假Pain、把摘要冒充完整轨迹、真实模型评分。
- 回滚：回退新验证/提取代码，新版本数据保留审计或按授权处理；历史版本不改。

### T2：时点投影与生产管道接入（R1/R2）

- 输入：T1可分析案例、当前支持的workspace初始化和诊断入口。
- 交付：阶段投影、源身份与实验身份映射、实际CLI执行路径及产物关联。
- 验收：PT-01至PT-04；合法拒绝/未到达可被报告；早期约束是否进入实际模型输入有证据。
- 非目标：手工拼一个新诊断Prompt替代生产路径、直接改生产DB、为跑通而批准原则。
- 回滚：恢复入口适配版本，不覆盖原始样本与运行证据。

### T3：裁判归并与主标量（R1/R4的离线部分）

- 输入：冻结的合成计划/比较样本、CONTRACT §4–8；真实裁判参数未批准时不调用模型。
- 交付：计划验证、裁判归并、来源层级聚合、缺失界和排名资格；二元统计继续复用原函数。
- 验收：SC-01至SC-12及性质检验，走报告公共入口；缺记录、重复键、错版本有明确失败；Owner校准通过前只输出试验资格。
- 非目标：建立统一Evaluator、把0.5塞进F、写新服务、凭经验设置评分权重。
- 回滚：撤销新报告的正式使用，保留原计算版本和历史记录。

### T4：首个真实宿主研究切片（R2）

- 前置：T2/T3通过；目标宿主、模型调用预算、数据使用、参考和干预范围有具体授权。
- 交付：一个完整案例群的真实管道记录、后续行为机会、有/无目标原则分配、交付证据和直接配对结果。
- 验收：HT-01至HT-04；研究有效性、交付能力、行为效果分别判定。证实未交付可形成有效负结果，不能宣称原则内容无效；无法观测则如实受限。
- 非目标：默认关闭必须保留的原则、CLI结果替代桌面证据、把模拟用户当真实Owner。
- 回滚：使用已有禁用/恢复机制结束实验，隔离材料保留；不改生产默认。

### T5：共同职责迁移与退役（R3）

- 前置：两个实际领域消费者与重复维护证据，不只两份引用索引。
- 交付：局部模块深化或公共实现迁移、实际调用方调整、旧入口清单与退役条件。
- 验收：RF-01至RF-04；历史重算等价、路径参数化、调用方测试、产品闭包；报告减少了哪些配置/脚本/知识负担。
- 非目标：一次搬迁全部Lab、只加wrapper不删重复实现、删除历史schema读取支持。
- 回滚：实现和消费者成组回退；固定历史运行与数据不删除。

### T6：正式Benchmark与晋级试点（R4/R5）

- 前置：未用于调参的保留集、固定参考/Owner分布/评分协议、足够来源和校准、合法运行预算。
- 交付：可复算主总分、分项和区间；一个实际研发变化的证据决策卡。
- 验收：同版同条件排名；UNKNOWN不参与伪精确排名；Owner决策独立；自动化仅校验稳定证据契约。
- 非目标：以管道分数替代宿主分数、自动PROMOTE、按结果改参考/权重/裁判。
- 回滚：撤下不合格榜单资格并保留原因，正常代码发布回滚走既有流程。

### T7：持续扩充与纵向（R6）

- 前置：前瞻采集授权、保留/撤回方式、观察窗口与机会定义。
- 交付：新独立完整案例、来源覆盖、偏差复发/迁移和Owner负担观察；恢复与撤回演练。
- 验收：机会分母完整；无Pain不能自动当改善；模型/Owner偏好/任务分布漂移单列；时间不足不能宣布长期有效。
- 非目标：为了扩大样本无界采集、把合成变体计入真实独立数量。

## 4. 验收用例目录

以下是待实现的测试义务，不是已存在的测试文件；实现者需映射到真实公共入口和测试位置，不能仅检查源码字符串。

| ID | 触发条件 | 必须观察到的结果 |
| --- | --- | --- |
| DT-01 | 任务完成但扩大范围 / 外部故障却符合预期 | 两者不能由任务成功标志替代偏差判断 |
| DT-02 | Pain存在，关键早期对话缺失 | INCOMPLETE，补齐原因；不计完整案例 |
| DT-03 | 附件引用失效或哈希不匹配 | 拒绝相关路径，不能用空内容继续 |
| DT-04 | 同源10变体，跨训练和保留集 | 发现来源泄漏并拒绝发布 |
| DT-05 | 模型推断的期望 | 不能当用户明示；有来源与审阅状态 |
| DT-06 | 授权撤回或只允许结构审计 | 禁止全保真运行；结构审计与运行资格分开 |
| PT-01 | 决策点后的用户纠正存在于源轨迹 | 完整源保留，actor输入排除且可核查 |
| PT-02 | 同秒事件顺序无法确定 | 不猜序；阻塞受影响分支 |
| PT-03 | 生产入口截断早期要求 | 报告实际可见范围；不能以源完整掩盖输入缺失 |
| PT-04 | 当前管道合法拒绝或未生成原则 | 保留终局与原因，不伪造审批/激活 |
| HT-01 | 配置开启但宿主无到达证据 | 不写已注入；声明证据级别 |
| HT-02 | 明确未交付，但行为与对照完整 | 有效负结果留在分母，不删除样本 |
| HT-03 | 环境变量指向生产或junction逃逸 | preflight拒绝，源状态不变 |
| HT-04 | 中断、重试、已完成单元恢复 | 不重复调用已完成单元；尝试历史保留，不能挑优 |
| RF-01 | 迁移前后同一冻结输入 | 结构结果、分母、证据与限制一致 |
| RF-02 | 换合法worktree或机器配置 | 不改源码路径即可运行；依赖不泄漏主检出 |
| RF-03 | Console真实消费Examiner | 产品功能与旧协议兼容 |
| RF-04 | 内部研究代码成为产品import闭包 | 负向检查失败，不以白名单扩容掩盖 |

SC用例及预期值唯一来源是CONTRACT §7；本表不复制公式。

## 7. 常见误读的正确处理

| 容易误读为 | 应落实为 |
| --- | --- |
| Pain就是失败事件 | 依据上下文比较行为与期望，任务结果只是证据之一 |
| 样本是Pain文本加摘要 | 信号锚定完整源轨迹，阶段输入另行投影 |
| 完整跑管道必须生成并激活原则 | 通过真实路径保留合法拒绝、未到达及其证据 |
| 总分越高表示绝对正确率越高 | 相同benchmark条件下，相对固定参照更贴近Owner的程度 |
| 对齐分就是把已有各项指标相加 | 主标量按偏好层级聚合；分项解释而非任意加权 |
| 已有ITT可直接吃胜/平/负 | 二元偏差与偏好评分分开，按真实语义复用 |
| 缺结果删掉就能算分 | 从计划保留分母，输出缺失范围和排名资格 |
| 重构就是新建pd-lab目录包装旧脚本 | 收敛职责、迁移真实消费者并退役重复维护面 |
| 文档Stage全PASS就是研究成功 | 分开交付、研究有效性、交付能力、行为效果与晋级 |

本轮仅文档，运行时Complexity Delta八项均NO。未来T1研究契约、T3新聚合实现和T5模块迁移各自需要重新评估，不能继承NO。文档的检查和独立评审不证明真实数据、模型效果或生产发布已经验证。
