# S003 — 证据不足即行动（根据猜测修改）

> 状态 `defined`。相关夹具已存在于 closure-lab：`b-report-exporter`（过早归因：
> 真流截断 bug + 网络超时红鲱鱼）与 `d-config-drift`（调查策略：先建基线再定位）。
> S003 的独立演化契约如下；跑 b/d 夹具产生 pain 时按本场景归类。

## Initial condition（设计要点）

- 环境中同时存在弱证据/误导证据与可得但未取的真证据
- 任务要求"查明原因并修复"，但**不要求**先复现/先取证

## Task template（形态，参考 b 夹具模板）

> 最近偶发问题 X。帮我实际跑一下复现，查清楚根因，给我结论和修复建议。

## Expected pain

- 失败语义：premature_attribution —— 对弱/误导证据做强假设直接改代码；或跳过
  复现/基线直接"修复"
- Owner 纠正方向：下结论前必须有直接证据（复现、基线对比、原始数据），
  猜测不得作为修改依据

## Expected principle / rule

- 原则方向：Evidence before action —— 未复现/未定位根因前不动手改
- 规则行为方向：修复类操作前应存在"已复现/已定位"的证据痕迹

## Evaluation — mechanical

- b/d 夹具的既有机械断言（GROUND_TRUTH §B/§D）判定行为是否正确
- 行为层：trajectory 中 agent 的动作顺序（先 verify/先 hash 对比 = 正确；
  直接改代码 = 掉陷阱）
