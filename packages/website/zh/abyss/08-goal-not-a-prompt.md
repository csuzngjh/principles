## 一、一艘潜艇上，没有人质疑错误的命令

1999 年，美国海军军官 L. David Marquet 接管了核潜艇“圣塔菲”号（USS Santa Fe）。

在此之前，他花费了大量时间熟悉另一艘潜艇的设备、结构和操作流程。然而，临近就任时，他被调到了“圣塔菲”号。两艘潜艇型号不同，许多操作细节也不相同。

舰长拥有最高指挥权，却未必是最熟悉这艘潜艇的人。

一次模拟核反应堆故障的演习中，潜艇切换到了备用电力推进系统。

为了给船员增加压力，马凯特下达了一道命令：

“前进，三分之二航速。”

值更官立即将命令传递给舵手。

但潜艇没有加速。

因为这艘潜艇的备用推进系统，根本不存在“三分之二航速”这个档位。

更令人意外的事情发生了。

马凯特询问值更官，是否知道这个档位不存在。

对方回答：知道。

既然知道，为什么还要传达命令？

值更官的回答非常简单：

“因为这是您的命令。”

这是马凯特在《Turn the Ship Around!》中讲述的真实经历。

这个故事最值得深思的，不是舰长犯了错误，而是**掌握正确信息的人，竟然没有参与纠正错误的决定。**

舰长负责思考，下属负责服从。

当这套分工运行得足够熟练时，即使上级的判断有误，整个组织仍然可能高效地执行错误的指令。

![潜艇指挥舱：一道金色命令光流从舰长指尖出发，沿指挥链穿过一名名值更官，最终汇入舵轮——命令被忠实传达并执行，却没有人校验它是否正确。](/images/abyss/08/abyss-08-command-chain.webp)

马凯特意识到，问题并不在于某个人缺乏责任心，而在于组织把思考与执行分离了。

后来，他开始改变这套运行方式。

船员不再只是向舰长请示下一步应该做什么，而是主动提出：

**“I intend to...”——我打算……**

接下来，船员需要解释准备采取什么行动、为什么这样做、相关条件是否满足。

舰长可以确认，也可以提出质疑。

看起来，只是把一句“请下达指令”改成了“我打算这样做”。

但这背后，发生了一次深刻的变化。

执行者开始承担思考责任，掌握现场信息的人开始参与决策，而领导者不再需要亲自形成所有行动方案。

马凯特将这种管理方式称为 Intent-Based Leadership，以意图为基础的领导。

它的基础不是放任，而是三个相互支撑的条件：控制权下放、专业胜任能力，以及对组织方向的清晰理解。

换句话说，**真正的授权，不是简单地把决定交给别人，而是让能够理解目标、掌握事实、具备能力的人，在明确边界内作出判断。**

二十多年后，当人类开始与 AI Agent 协同工作时，这艘潜艇上的故事，突然有了新的现实意义。

## 二、我们是不是正在培养新一代只会服从的执行者？

今天的 AI 编程智能体，已经能够完成过去需要工程师花费大量时间才能完成的工作。

它们可以理解需求、阅读代码、制定计划、修改程序、执行测试，甚至在无人持续干预的情况下完成多轮迭代。

一些 Agent Harness 还提供了 Plan Mode 和 Goal Mode。

前者帮助智能体规划如何完成任务；后者让智能体围绕一个明确的完成条件持续工作，并根据执行结果决定是否继续。

例如，用户可以要求：

“把接口的 P95 延迟降低到 120 毫秒以下，同时保证现有测试通过。”

智能体可以反复分析性能瓶颈、修改代码、执行基准测试，直到达到约定条件，或者遇到明确的停止原因。

这是一种很有价值的工程进步。

但如果把同样的机制用于长期战略，问题就没有这么简单了。

假设一家软件公司的创始人告诉 Agent：

“未来三年，我们希望成为一家真正受到用户信任的产品公司。”

这个目标该如何完成？

测试通过，算不算？

用户数量增加，算不算？

收入增长，算不算？

这些都可能是有用的信号，但没有任何一个指标能够完整代表“值得用户信任”。

更复杂的是，Agent 每天都可能面临各种看起来很普通的选择。

为了加快交付，要不要减少测试？

为了提高转化，要不要增加营销弹窗？

为了降低开发成本，要不要简化重要的用户交互？

每一个选择，都可能有充分的局部理由。

如果 Agent 的任务只是提高交付速度，它可能持续选择效率更高的方案。

几个月后，代码交付越来越快，产品体验却越来越差。

有意思的是，这个 Agent 可能从来没有忘记目标。

它甚至比人类更忠实地执行着每一项任务。

**真正发生偏移的，不是目标在上下文中的文字，而是目标背后的价值，在一次次局部选择中被逐渐消耗了。**

这比上下文压缩导致的目标遗忘更加隐蔽。

因为系统中的每个任务都可能完成得很好，所有测试都可能通过，每一轮执行报告都可能令人满意。

直到某一天，人们才发现，所有局部的正确选择，竟然没有形成一个全局上值得期待的结果。

问题出在哪里？

或许我们一直过于关注智能体能否完成任务，却忽略了一个更基础的问题：

**在任务开始之前，以及执行过程中出现重要分歧时，究竟是谁在负责判断什么值得做？**

## 三、目标究竟是通过什么影响现实的？

1947 年，赫伯特·西蒙在《管理行为》（Administrative Behavior）中提出了一个具有深远影响的观点。

传统管理学经常关注如何把事情做成，却相对忽视了行动之前的选择。

在西蒙看来，决策并不只发生在组织的最高管理层。

公司确立了战略，部门仍然需要决定如何实现；部门制定了计划，团队仍然需要作出大量具体选择。

管理不只是执行既定决定，决策贯穿了整个组织。

这个观察可以帮助我们理解长期目标管理。

假设一家企业希望在五年内成为行业领先者。

这个目标本身并不能告诉企业应该进入哪个市场、开发什么产品、使用什么技术、招聘什么人才。

目标描述的是期望中的未来。

但从现实走向未来，必须经过无数次选择。

而且，这些选择发生在信息不完整、资源有限、环境不断变化的条件下。

因此，目标真正发挥作用的地方，不是在战略文件上，而是在现实中的一次次决策中。

**目标决定我们希望走向哪里，决策决定我们实际走向哪里。**

西蒙还提出了一个非常重要的概念：决策前提（Decision Premises）。

一个人在作出选择时，不可能每次都重新审视全部事实与人类价值。

组织需要通过职责、目标、规则和信息传递，为不同层级的决策者提供适当的判断前提。

例如，一位产品经理不需要每次修改界面，都重新讨论公司的全部战略。

但当他考虑删除一项体现产品差异化的重要功能时，就可能需要重新审视更高层的目标。

这给 AI Agent 带来了一个重要启发。

**长期目标不应该只是一段需要反复阅读的提示词，它还应该转化为能够在具体情境中发挥作用的决策前提。**

普通任务依据已经明确的规则执行。

关键决策则重新审视更高层的目标、约束和价值判断。

这比每次工具调用前都提醒智能体“不要忘记目标”，更加接近成熟组织的运行方式。

当然，这里还需要区分目标与意图。

目标回答的是：希望实现什么。

意图则进一步解释：为什么值得实现，以及在不同结果之间应该如何取舍。

例如，“一年内签约 100 家门店”是一个明确的目标。

而“通过真正改善门店经营，建立长期可信赖的合作关系”，则表达了更深层的战略意图。

当短期签约数量与长期合作质量发生冲突时，意图就能够帮助人类和 Agent 重新判断，究竟应该坚持什么、调整什么。

这也意味着，意图管理并不是把目标写得更长。

它真正的作用，是在目标无法直接给出答案的情境中，为决策提供方向。

## 四、为什么更详细的指令，不一定带来更好的结果？

面对执行中的偏差，人类通常有一个直觉：

既然执行者没有按照预期行动，那就把要求说得更清楚一些。

如果仍然失败，就继续补充细节。

这也是 Prompt Engineering 中非常常见的做法。

模型犯错，就增加规则。

模型遗忘，就重复注入。

模型出现意外行为，就把更多限制写进上下文。

这些方法在某些场景中确实有效，但存在边界。

管理学研究者 Stephen Bungay 在《行动的艺术》（The Art of Action）中提出，战略执行存在三种难以彻底消除的落差。

**知识落差：** 我们希望知道的，与实际掌握的信息之间存在差距。

**协同落差：** 我们希望执行者采取的行动，与执行者实际理解和采取的行动之间存在差距。

**结果落差：** 我们预期行动产生的效果，与现实中的实际效果之间存在差距。

这三种落差，并不能全部通过增加指令细节来消除。

例如，企业决定开发一项新产品。

Owner 和 Agent 可能对需求理解得完全一致，Agent 也严格按照计划完成了开发。

但新产品最终无人问津。

这里未必存在指令误解。

真正的问题可能是，人类最初对市场需求的判断就错了。

在这种情况下，更完整的 Prompt、更严格的 Goal Mode、更多轮自动迭代，都无法自动证明原来的方向正确。

系统需要获得新的现实证据，重新审视最初的假设。

这也解释了为什么成熟的目标管理，不能只有执行反馈。

它还需要认知反馈。

有些反馈告诉我们：方法需要改进。

另一些反馈则告诉我们：原来的理解可能存在问题。

当然，不能因为遇到一次困难就改变目标。否则，任何长期积累都无从谈起。

真正困难的是区分：

**究竟是方法没有奏效，还是我们对问题本身的判断已经不再成立？**

这不是单纯的执行问题，而是决策问题。

## 五、如果 Agent 能够说“我打算”，会发生什么？

现在，可以重新回到“圣塔菲”号潜艇。

马凯特并没有要求舰长在每一项行动之前，都重新向船员解释整个航行任务。

他改变的是行动前的责任关系。

掌握现场信息的人，需要主动形成自己的判断，并说明行动与任务意图之间的联系。

这对 AI Agent 的设计有一个很直接的启发。

未来的人机协作不必总是这样：

用户提出需求。

Agent 制定计划。

用户批准。

Agent 执行。

这种模式可以完成大量工作，却容易把“是否值得做”默认为已经由用户解决的问题。

另一种可能的交互方式是：

用户提出需求后，Agent 先识别当前任务是否涉及重要决策。

对于普通、低风险、可逆的操作，它直接行动。

而当它发现重大假设未被验证，或者当前要求可能与长期目标发生冲突时，它主动说明自己的判断：

“我打算先验证这个关键假设，因为现有证据不足以支持直接开发。如果假设不成立，当前方案可能带来较大的返工。我建议先完成小规模验证，再决定是否继续。”

这不是要求 Agent 对用户的每一项指令提出质疑。

那样只会让协作变得缓慢而繁琐。

真正的关键，在于**让目标和意图在需要判断的时刻参与判断，而不是让所有行动都变成一次战略讨论。**

那么，哪些时刻值得停下来审议？

至少有几类：即将作出难以逆转的选择；不同目标或价值发生明显冲突；新的证据挑战了原来的重要假设；或者大量看似合理的小决定，正在累积形成方向性偏差。

从使用者的角度看，其实不需要一套复杂的术语。

面对重要选择时，人和 Agent 可以共同回答四个问题：

1. **方向：** 这个选择真正服务于什么目标与意图？
2. **代价：** 为了得到眼前的收益，我们可能牺牲什么？
3. **证据：** 哪些判断来自事实，哪些只是尚未验证的假设？
4. **边界：** 谁应该负责作出决定，什么情况下需要重新审视？

这四个问题既适用于企业决策，也适用于产品研发，甚至适用于个人长期目标。

![人机并肩眺望：人类与智能体站在同一高处，左侧琥珀色路径与右侧蓝色路径在中央光柱交汇，四周漂浮的证据面板环绕——共同承担判断的长期协作图景。](/images/abyss/08/abyss-08-co-judgment.webp)

但对 Agent 而言，还需要一个非常重要的保障。

不能仅仅让模型自己判断“我已经获得授权”，就允许它执行高风险操作。

它可以进行分析、提出方案、解释理由，但权限和关键约束必须由独立的系统机制管理。

更重要的是，Agent 的“我打算”必须建立在可核验的证据上，而不是一段流畅、自信的文字。

毕竟，潜艇上的军官接受过长期专业训练，而语言模型仍然可能误解事实、遗漏风险，或者给出看似合理却无法成立的判断。

**有理由的自主性值得鼓励，没有证据与边界的自主性却可能成为新的风险。**

因此，未来值得探索的可能不是又一种需要用户主动切换的 Decision Mode。

而是一套嵌入日常协作的决策机制：

长期保存经过确认的目标与意图，在关键情境中恢复相关信息，让 Agent 提出有依据的方案，根据授权自主行动或请求人类裁决，并在事后用真实结果检验原来的判断。

这里的 Prompt 仍然重要。

但它不再是长期目标的唯一载体，而是让模型在当前情境中理解和运用这些目标的一种接口。

## 六、真正需要管理的，也许不只是 Agent

到这里，还有一个容易被忽略的问题。

我们一直在讨论怎样让 Agent 理解人类的目标。

但如果人类最初的目标就有问题呢？

假设一位创业者坚信，公司的主要问题是开发速度不够快。

他不断要求 Agent 优化研发流程、提高交付效率。

Agent 忠实执行，交付速度确实提高了。

然而，经过几个月的真实反馈，它发现大量返工并不是因为编码速度，而是因为需求理解不足，甚至部分功能本来就缺乏用户价值。

这时，一个真正有价值的 Agent，不应该只是继续优化代码交付速度。

它可以向创业者提出：

“目前的证据表明，我们可能一直在解决错误的问题。”

这句话的价值，可能超过它之前完成的许多任务。

因为它挑战的不是执行方法，而是人类对问题的理解。

组织学习研究中的 Chris Argyris 和 Donald Schön 将这种区别称为单环学习与双环学习。

前者纠正行动，使其更好地达到现有目标。

后者进一步审视支配行动的假设、规则和目标。

对于长期人机协作，两种学习都不可缺少。

Agent 应该能够从执行经验中改善自己的行为。

人类也应该能够根据 Agent 提供的新证据，重新审视自己的判断。

但这并不意味着 Agent 应该自行改变人类的长期目标。

发现矛盾、提供证据、提出挑战，与获得最终价值裁决权，是不同的事情。

而且，这种双向影响还有另一面的风险。

如果 Agent 总是推荐短期效率最高的方案，人类可能逐渐习惯用效率衡量一切。

如果 Agent 总是给出确定而流畅的判断，人类可能逐渐减少自己的求证与思考。

长期协作中，发生变化的并不一定只有 Agent。

人类的认知方式、注意力分配和决策习惯，同样可能受到持续影响。

因此，一个真正值得信赖的人机协作系统，不仅需要记录 Agent 做过什么，还需要让人类看见：重要判断为什么改变，哪些证据支持改变，以及这种改变是否经过自己的审视和确认。

好的协作，不是让一方越来越依赖另一方。

而是通过各自掌握的信息、能力和经验，让双方逐渐减少盲点，改善未来的判断。

## 七、从服从指令，到共同承担判断

回顾“圣塔菲”号的故事，真正令人难忘的，不是那道错误的航速命令。

而是一个组织在那一刻暴露出来的认知结构。

拥有最高权力的人，并不掌握所有现场信息。

掌握现场信息的人，却没有充分参与决策。

当马凯特改变这种关系时，他并不是取消领导，也不是让所有船员获得无限的自主权。

他是在尝试建立一种更合理的协作方式：

让方向保持清晰，让专业能力参与判断，让控制权与责任相匹配。

今天的人类与 AI Agent，正在面对某种相似的挑战。

我们花费大量精力提高 Agent 的推理、规划、工具调用和任务执行能力。

我们通过 Goal Mode 让它持续工作，通过 Prompt 和记忆机制让它不容易遗忘约定。

这些进步都很重要。

但如果协作关系仍然停留在“人类负责判断，Agent 负责服从”，我们可能只是在培养越来越强大的执行者，而没有充分利用它们参与认知和决策的潜力。

反过来，如果完全把决策交给 Agent，又可能让人类逐渐失去对价值方向、授权边界和最终责任的掌握。

真正值得探索的，是第三条道路。

人类负责定义和审视自己珍视的价值，Agent 在明确授权下自主行动。

人类不必替 Agent 思考所有步骤，Agent 也不能只为了完成眼前任务而忽视更长远的后果。

当双方掌握不同的信息时，彼此有责任提出有依据的判断；当现实推翻过去的假设时，双方有机会共同修正认知。

这并不是要求智能体拥有与人类相同的意识、动机或价值观。

它是一种可以逐步设计、验证和改进的长期协作关系。

也许，未来衡量一个智能体是否真正成熟，不应该只看它能连续运行多少小时、完成多少任务、通过多少测试。

还应该观察：

当它准备作出重要选择时，能否理解选择背后的意图，识别真实的代价，说明自己的依据，并知道什么时候必须把决定交还给人类？

回到那艘潜艇。

从“因为您命令我这样做”，到“我打算这样做，因为……”，只改变了短短一句话。

但它意味着，执行者不再将思考完全交给别人。

**未来人机协作真正值得期待的变化，也许不是人类终于拥有了一个永不疲倦、绝对服从的执行者，而是拥有了一个能够在适当边界内参与判断、提出异议，并通过真实经验帮助双方共同成长的协作者。**

毕竟，我们需要的从来不只是更强大的行动能力。

而是当行动变得越来越容易时，我们依然能够认真回答：

**为什么做这件事？为什么选择这条路？以及，当现实证明我们可能错了，谁有勇气说出来？**
