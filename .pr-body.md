## PRI-304: Core config contract: define .pd/config.yaml schema and effective config

### Relationship to PRI-301 / PRI-304

- **PRI-301** is the design doc that defined the PD configuration ownership map. This PR implements the core contract slice.
- **PRI-304** is the implementation issue for this PR.

### .pd/config.yaml is the only PD-owned user config

Per ADR-0016, PD owns exactly one user config file: `<workspace>/.pd/config.yaml`. This PR implements the pure core contract for that file.

### .pd/feature-flags.yaml / .state/workflows.yaml retirement semantics

- `.pd/feature-flags.yaml` is retired into `.pd/config.yaml.features`. Feature flags are now computed from the new config contract.
- `.state/workflows.yaml` is not a compatibility input. No reader for it exists in this contract.

### Secret boundary

- PD does not own provider secrets (ADR-0016 S2.2).
- OpenClaw profiles reference provider/model/id only — no secrets copied.
- PD-local profiles use `apiKeyEnv` (env var name) — never the key value itself.
- Forbidden secret fields (`apiKey`, `token`, `secret`, `password`, `auth`, etc.) are rejected at validation time.
- Redacted summary never includes token/API key values or raw provider objects.

- **ERR-001/ERR-005**: No `as` bypasses on untrusted input. All parsed YAML treated as `unknown`, validated with `typeof`/`Array.isArray`/type guards.
- **ERR-009/ERR-010**: Missing/malformed required fields fail loud with `reason` + `nextAction`.
- **ERR-013**: Uses `Object.hasOwn()` for untrusted object key checks.
- **ERR-002**: Graceful degradation includes structured reason.
- **ERR-014/ERR-016/ERR-017**: Preview/redaction paths use bounded safe serialization.
- **ERR-047**: Non-boolean enabled fields fail loud instead of silently treated as disabled.
- **ERR-045**: Sensitive key detection uses ANY-segment match logic.
- **ERR-046**: String values run through full redaction pipeline before truncation.

### Test scenarios (8 required + edge cases)

1. Missing config -> deterministic defaults
2. Valid MVP config -> effective config correct
3. Malformed root/object/array/value -> structured error
4. OpenClaw runtime reference -> summary shows safe label/id only
5. PD-local profile -> shows apiKeyEnv, not secret value
6. Per-agent override beats default runtime
7. Feature flags computed from new config contract
8. Redaction does not leak token-like/key-like/raw provider data

Plus 14 edge cases: empty features, negative/zero/NaN/Infinity timeoutMs, unknown profile type, unknown agent key, invalid diagnostics mode, missing ui, non-existent profile reference, readiness states, dangerous keys.

### Remaining risk

- No I/O layer yet (YAML loading in pd-cli/openclaw-plugin is a follow-up issue).
- No migration path from .pd/feature-flags.yaml yet (plugin layer responsibility).
- pi-ai profile readiness is `not_ready` because runtime availability cannot be verified in pure core.
- Console UI (PRI-303) depends on this contract but is not implemented yet.
